# Hub 第二阶段产品目标

> 当前状态：Codex PTY 已完成 macOS、Ubuntu 和手机端验收，当前主线转向交付高价值节点维护能力。

## 1. 阶段定位

第二阶段不做多节点中心化平台，先继续扩展单节点的真实可用能力，重点验证个人设备在日常查看、检查和维护上的价值。

## 2. 阶段目标

- 找到高频、低风险、可持续验证的节点场景。
- 新增节点能力按明确需求提供受控接口，不保留通用任务执行入口。
- 优先增加查询、诊断和可控的轻量操作。
- 保持手机端优先，结果和操作都要易读。
- 根据真实使用反馈删掉低价值能力。
- 探索手机端 Codex 会话管理入口，验证 PTY 是否足够承载远程开发。

## 3. 工作原则

- 真实需求优先，不为了“功能数”扩展。
- 小步交付，每次只加少量相关能力。
- 查询优先，状态变更单独评估。
- 复用第一阶段的认证、日志和页面结构。
- 每项能力都要有自动化测试和实机验收。

## 4. 阶段范围

包含：

- 节点场景收集和能力管理。
- 公共、macOS 和 Ubuntu 能力扩展。
- 新增能力对应的 API 和页面调整。
- 结果展示、分类和交互反馈优化。
- 自动化测试、实机验收和使用反馈记录。
- 配置驱动的固定网站下载自动化基础能力和首页手动运行入口。
- 可信 tailnet 内的手机端 Codex 会话探索。

不包含：

- 多节点中心、自动发现和任务转发。
- 任意 Shell 入口、通用网页终端和脱离 Codex 会话的命令执行。
- 系统定时调度、跨任务复杂工作流和无人确认的状态变更自动化。
- 多用户、复杂权限和公网直连。
- 复杂插件系统和未验证的扩展框架。

## 5. 安全与网络边界

- Chub 必须监听节点自己的 Tailscale IP。
- 保留 Bearer Token 认证。
- 不启用 Tailscale Funnel。
- 不把 Hub 直接暴露到公网或普通局域网。
- Codex PTY 只在可信 tailnet 内启用。
- Codex PTY 还要求稳定的双向实时网络链路；可信 tailnet 只解决访问边界，不保证跨网络中继的延迟、抖动和丢包质量。
- Codex 的审批交互仍由 CLI 原生界面管理；Chub 首页提供会话权限模式选择，并在运行中切换时先停止会话，避免权限变更只停留在待生效状态。

## 6. 高层验收方向

- 新增能力来自明确真实场景。
- 能力在适用平台稳定运行，失败语义明确。
- 手机端能理解并使用新增能力。
- 不突破固定操作、安全和网络边界。
- 形成经过实际使用筛选的能力集合和下一阶段建议。

## 7. 页面信息架构

管理页面保持主要功能区域，服务重启作为页面级操作放在顶部标题区域：

- 当前节点：展示节点身份和系统概况。
- Codex PTY：远程管理本机 Codex 会话。
- 页面顶部标题：点击标题区域打开服务重启确认弹窗。
- 诊断信息：集中承载日志查看和诊断信息。

顶层卡片统一使用“绿色分类说明 + 主标题”的标题结构，并按需提供简短辅助说明：

- `当前节点` + 节点名称。
- `远程开发` + `Codex PTY`。
- 页面标题区域 + `重启服务` 弹窗。
- `诊断信息` + `日志`。

新增能力应优先归入以上区域；只有形成独立、完整的操作流程时，才增加新的顶层卡片。

卡片交互保持相互独立：

- 每张动态卡片独立加载、刷新和展示错误，局部失败不影响其他卡片。
- 卡片刷新期间保留最近一次成功内容，成功后原位更新；跨页面返回时优先恢复卡片内容，只刷新实际可能变化的数据，避免列表和操作入口闪烁消失。
- 卡片上的“刷新”只更新本卡片；首次连接允许并行加载全部卡片。
- 卡片内操作默认只更新本卡片。服务重启等全局操作完成后，只定向刷新实际受影响的卡片。
- 动态卡片的右上角统一放本卡片“刷新”；“全部任务”“全部文档”等次级导航放在卡片底部右侧。
- 首页卡片入口、列表入口和列表内下钻统一使用当前标签，保留一致、清晰的浏览器返回层级。
- 下级页面统一依赖浏览器返回，不增加页面级返回按钮或专用定位参数；卡片默认不因返回刷新，只有显式配置的卡片在首页重新显示后定向刷新。
- 标题简介右侧最多放一个操作入口；桌面双列和手机单列都使用卡片自然内容高度。

### 7.1 弹窗与原生控件

- 需要确认、选择或编辑的业务流程使用统一的模态 `dialog`，复用统一的遮罩、边框、阴影和响应式布局；桌面端居中，手机端按内容选择居中或底部抽屉，但同类业务弹窗保持一致。
- 页面级或跨卡片操作可以放在页面标题区域，例如服务重启，不为了单个操作新增独立卡片。
- 原生表单控件（尤其是下拉选择器）继续使用浏览器/系统原生弹层，不强行改造成自定义弹窗；这样保留平台一致的选择交互和无障碍行为。
- 自定义业务弹窗必须使用 `showModal()`，提供明确的取消/关闭入口和半透明背景遮罩；危险操作在确认前说明影响。
- 页面通过全局 CSS 统一禁用浏览器默认的按压/tap-highlight 反馈，覆盖页面大标题、卡片标题横条、卡片容器、按钮、链接、表单控件和其他交互区域；组件若需要反馈，只保留明确设计的状态变化，不为单个区域重复实现同类禁用逻辑。

### 7.2 卡片折叠

- 首页功能卡片的标题横条是统一的折叠控制区：展开时点击标题横条折叠，折叠后点击卡片可展开。
- 刷新、链接、表单控件和卡片内容内的业务操作不因标题折叠交互而误触发；标题横条提供键盘 Enter/Space 操作和 `aria-expanded` 状态，横条内的独立操作按钮不触发折叠。
- 折叠只改变卡片展示，不改变卡片数据、后台轮询或业务操作状态；折叠偏好可跨页面刷新和服务重启保留。
- 折叠状态保存在当前浏览器的本地存储中，刷新或服务重启后保持；不跨设备同步，存储不可用时回退为当前页面状态。
- 卡片内容统一使用内容层承载，并由内容层统一管理同级元素间距；子元素不重复保留层级调整前的外边距，避免按钮、工具栏和输出区域出现异常贴近或间距过大。
- 卡片简介以“查看方案、实现范围和验收标准。”及“查看节点最近的操作和运行记录。”为长度参考，建议控制在约 15 个字符、通常不超过 18 个字符，优先保证信息准确和视觉平衡。
