# Chub 微信任务编排外置设计

> 状态：调研中
> 主要读者：需要实现或排障微信普通正文编排的 AI Agent；维护人员用于确认分流行为、阶段范围和微信验收。
> 本文负责：定义微信普通正文在内置流程与外置编排模块之间的分流、首个模块的处理范围、阶段目标和验收标准。
> 本文不负责：能力编排模块通用协议、模块安装生命周期、Session/Worker 状态机、微信固定指令语法或用户可见回复格式。
> 维护说明：当前微信任务润色仍由主项目内置流程处理；外置微信编排尚未实现。本设计是首个具体编排任务的实施依据。

## 当前基线

当前“微信任务润色”配置仅影响之后接收的微信普通正文：直接执行、自动润色后执行、自动润色后确认执行。固定指令、续提、Session、确认队列、翻译 FIFO、隐藏翻译任务、任务终态和通知仍按当前 Chub、Quick Worker 与 OpenClaw 契约执行。

微信固定指令、用户可见回复格式和额度展示以[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md#4-微信-clawbot-指令)为准；身份、路由、幂等和持久化边界以[OpenClaw 定制集成设计](OPENCLAW_CUSTOMIZATION_DESIGN.md)为准。

## 目标分流与责任

第一版只处理微信普通正文。Chub 在入口完成认证、固定指令识别、路由、幂等和正文限制后，按该范围的活动偏好分流：

```text
微信普通正文 → Chub 入口校验
  ├─ `internal`：内置流程直接调用 Chub 执行面处理任务
  └─ `weixin-orchestration-dev` 或 `implementation_ref`：委托活动微信编排模块
       → 模块决定复用候选 Session 或创建新 Session、处理顺序和下一步
       → 模块调用 Chub 进程内能力执行面
       → Chub 实际提交 Runtime/Worker 任务并维护终态、通知和回送
```

活动偏好由 Chub 编排协调层持久化为 `weixin-normal-text -> internal | development_ref | implementation_ref`；其中阶段二的 `development_ref` 固定为 `weixin-orchestration-dev` 加当前源码摘要。设置页只展示和切换这一偏好，变更只影响之后新接收的普通正文，不影响已受理请求。

活动模块不可用、所需能力不可用或模块回合失败时，该范围内的新普通正文明确失败，不静默切回 `internal` 或执行原文。已经受理的请求固定原处理路径、带源码摘要的 `weixin-orchestration-dev` 或 ZIP 实现引用，不因后续启用、停用、替换或设置变化改投。固定指令、续提、Web 快速交互、自动化和周报始终绕过本分流。

模块拥有普通正文的流程语义：它可从 Chub 签发的候选 Session 投影中复用目标，或以受控创建上下文创建新 Session，再调用能力执行面处理任务。Chub 不再在该范围内硬编码具体业务步骤，但仍校验每次选择，并拥有 Runtime 调用、Worker 任务、确认、通知和最终状态。

## 首个模块范围

首个模块只覆盖三种既有处理模式：

- **直接执行**：提交规范化正文。
- **自动润色后执行**：先生成润色结果，再提交批准的正文。
- **自动润色后确认执行**：先生成润色结果，等待确认后再提交批准的正文。

模块可组织“润色 → 确认 → 主任务”等步骤，但不能改变固定指令语义、确认语义、回送格式或失败关闭规则。目标忙、润色失败、确认超时、能力结果未知或目标不可用时，按当前产品契约收敛，不执行原文作为隐式降级。

## 实施阶段与验收

### 阶段一：微信编排基础

建立微信普通正文的编排请求、候选 Session 投影、受控创建上下文、能力发现、检查点、等待与恢复。此阶段保留 `internal` 路径，不展示模块安装或切换入口。

验收：重复消息不会重复创建 Session、任务或通知；模块只能使用当次签发的引用；成功、等待、拒绝、不可用和未知结果均可收敛；Web 或 Worker 重启后不重复提交；当前内置微信流程和其他入口不变。

### 阶段二：首个模块与启用分流

实现首个微信模块，并将其作为 Chub 从固定仓库开发目录加载的 `weixin-orchestration-dev` 开发实现；提供该范围最小的活动实现选择，使新普通正文可在 `internal` 与 `weixin-orchestration-dev` 间明确切换。该开发实现不接受动态代码路径或安装来源；每次加载记录源码摘要，存在非终态请求时拒绝重载。完整 ZIP 导入、替换、移除和维护页面仍留在下一阶段。

验收：未启用时走 `internal` 内置执行；启用 `weixin-orchestration-dev` 后走活动模块；模块不可用时明确失败；源码变化不会用于恢复已受理请求；三种处理模式的最终任务、确认与通知符合现有契约；模块选择/创建 Session、提交和等待的可信记录完整。自动化验证通过后，维护者在真实微信客户端验证文字发送、确认、结果回送和失败反馈。

### 阶段三：模块生命周期与交付

将已验证的微信模块从 `weixin-orchestration-dev` 扩展为通用架构定义的 ZIP 导入、激活、停用、替换、移除、恢复和模块维护页面。

验收：同版本新包不影响已受理请求；被非终态请求引用的产物不能覆盖或移除；所有维护操作以注册表、活动偏好和请求终态确认；至少完成一个真实平台的安装、启用、执行、停用、移除和恢复验收。
