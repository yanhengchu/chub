# Chub 集成能力清单

> 状态：持续维护。本文是 Chub 当前外部集成能力、固定 API 和微信指令的简明查询入口。

项目整体功能与使用入口见 [README](../README.md)；架构、安全和并发边界见 [Chub–OpenClaw 接入设计](CHUB_OPENCLAW_INTEGRATION_DESIGN.md)。

### 1.1 插件列表

| 插件 | 状态 | 功能 |
| --- | --- | --- |
| Chub OpenClaw 插件 | 已实现 | 提供受限 Chub Tool、微信消息转发和飞书通知原文保护 |
| 腾讯微信插件 | 已接入 | 提供 ClawBot 账号绑定、微信消息收发和语音转写 |

### 1.2 Chub OpenClaw 插件能力

| 能力 | 类型 | 状态 | 功能 |
| --- | --- | --- | --- |
| `chub_get_status` | Agent Tool | 已实现 | 查询 OpenClaw Gateway 所在节点的 Chub 基础状态 |

### 1.3 固定 API

Chub OpenClaw 插件只调用以下固定 API：

| 请求 | 用途 |
| --- | --- |
| `GET /api/status` | 查询节点健康和基础状态 |
| `POST /api/notifications/send` | 发送飞书通知 |
| `POST /api/openclaw/wechat-chub-mode/dispatch` | 调度微信 Chub 消息 |

## 2. 当前微信指令

以下能力均由 Chub 直接处理，不经过 OpenClaw Agent 或 LLM。未匹配固定指令的非空正文作为普通任务提交给 Codex CLI。

| 英文指令 | 中文别名 | 状态 | 功能 |
| --- | --- | --- | --- |
| `chub` | `查询状态`、`状态查询`、`检查状态`、`状态检查` | 已实现 | 返回缓存的 Chub 状态总览 |
| `chub refresh`、`chub -f` | `刷新状态` | 已实现 | 刷新状态数据并更新缓存 |
| `chub sync` | `补充槽位` | 已实现 | 清理失效槽位并补充等待候选 |
| `codex help` | 无 | 已实现 | 返回当前 Codex 指令帮助 |
| `codex new` | 无 | 已实现 | 新建、占用槽位并切换 Session |
| `codex switch`、`codex switch N` | `切换N` | 已实现 | 循环切换或切换到指定槽位 |
| `codex archive N` | `归档N` | 已实现 | 归档指定槽位并在成功后释放槽位 |
| `codex retry` | 无 | 已实现 | 在当前 Session 续提最近一次忙碌拒绝任务 |
| `codex new retry` | `继续执行` | 已实现 | 新建 Session 后续提最近一次忙碌拒绝任务 |

当前指令规则：

- 固定指令要求整条消息匹配；比较前去除首尾空白和标点、合并连续空白，英文指令不区分大小写。
- `N` 仅使用 Chub 分配的 `1`–`9` 槽位；中文切换和归档支持一至九。消息不能提供内部 Session ID、路径、权限、模型或任意命令。
- `Available` 可立即接收任务；`Busy` 可切换但不能接收新任务；`Unavailable` 保留已占编号但禁止切换。
- 新建、切换和归档在执行前复检目标状态；重复微信消息复用首次结果，不重复执行操作。
- 普通任务在当前绑定不存在时按固定配置创建 Session；Session 忙时不自动新建，只保存最近一条待续提任务 10 分钟。
- 普通任务成功后由 Chub 按任务保存的微信路由原路通知。文本优化与翻译镜像默认关闭；显式启用后使用独立只读 Session，不占用槽位，也不改变业务任务结果。
- 裸 `codex` 不是固定指令，与其他未匹配正文一样进入普通任务流程。
- `chub` 只展示状态，不附带指令列表，也不触发通知补发；`chub sync` 是唯一会补充等待候选的状态维护入口。

真实微信文字及语音链路的具体验收状态见 [Chub OpenClaw 插件说明](../integrations/openclaw/chub/README.md)。

## 3. Chub 状态总览规则

### 3.1 状态总览

`chub` 默认展示最近一次成功快照，内容包括：

- Chub 服务和微信 Chub 模式是否就绪。
- 执行中、待通知和通知失败的任务数量。
- Codex 周期额度、每日 Token 用量、槽位占用、当前绑定及各 Session 的 `Available`、`Busy` 或 `Unavailable` 状态。
- 状态更新时间；部分数据超过有效期时明确标记为较旧。
- 内存或磁盘仅在达到后端固定告警阈值时展示；CPU 瞬时值首版不展示告警。消息不能修改阈值。

系统、任务、Session 和用量分别维护快照与更新时间；单项失败保留其最后成功值，不清空或阻塞其他状态。Chub 启动后异步执行一次有界初始化采集，不阻塞服务就绪；初始化尚未完成时返回已有分区，没有成功值的分区显示“暂不可用”。

首版默认值为：系统状态有效 60 秒，Codex 用量有效 5 分钟，强制刷新冷却 30 秒；任务和 Session 由本地事件实时更新，不设置独立轮询周期。系统状态和 Codex 用量只在启动初始化或强制刷新时采集，过期后不会后台自动刷新；用户需要发送 `chub refresh` 获取新值。内存或磁盘使用率达到 85% 时展示警告；CPU 瞬时值不作为首版告警，避免短时波动造成噪声。这些值由后端固定配置维护，不能通过微信消息传入。

正常示例：

```text
Chub：正常 · 微信模式已就绪
任务：2 个执行中
系统：正常

Codex：Weekly 35% left · Daily tokens 81.8M · 更新于 14:20
槽位：2/9
1. 项目维护 [Current] · Busy
2. 日志检查 · Available
```

降级时保留可用内容，并标明受影响分区：

```text
Chub：正常 · 微信模式已就绪
任务：无执行中任务
系统：内存 87%（警告）

Codex：Weekly 35% left · Daily tokens 81.8M · 数据较旧（更新于 13:40）
Session：暂不可用
```

### 3.2 刷新与槽位同步

- 普通 `chub` 只读缓存，不启动 Codex App Server、不扫描或调整槽位，也不触发通知补发。
- `chub refresh` 和 `chub -f` 强制刷新状态数据，但不补发通知、不改变当前绑定或槽位。已有刷新正在执行时共享该次结果；最近一次刷新仍在冷却期时直接返回其结果和刷新时间，不再次访问数据源。
- 强制刷新更新系统状态、任务快照、当前已分配 Session 状态和 Codex 用量；它不扫描等待候选，等待候选只由 `chub sync` 处理。
- 刷新超过微信同步请求预算时返回已有快照并标明刷新未完成，不让整条状态查询失败。
- `chub sync` 是显式写操作：保留有效槽位编号、清理已不存在或配置失配的槽位，并按既定稳定顺序补充等待候选。
- `chub sync` 不创建、归档或切换 Session；当前绑定失效时只清除绑定，不自动选择新目标。
- `chub sync` 成功后回复清理、补充和当前槽位数量，并附带操作后的已分配 Session 列表；没有变化时明确回复“槽位无需调整”。扫描或写入无法完整确认时不提交部分结果，也不附带可能失真的列表。重复消息重放首次完整结果，不再次同步。
- `chub sync` 已确认完成但附带状态格式化失败时仍报告同步结果，并提示重新发送 `chub` 查看总览；附带总览失败不能把已完成操作记为失败。
- 每次状态查询从本地持久任务状态汇总执行与通知计数；Session 创建、切换、归档和槽位同步更新 Session 快照，展示时以当前快速交互运行态覆盖 `Busy`。只能重新访问外部数据源确认的系统状态与 Codex 用量可标记失效。
- 普通 `chub` 遇到失效分区仍展示最后成功值和“数据较旧”，不隐式刷新；没有成功值时显示“暂不可用”。
- 状态查询不承担通知补发。失败通知保留失败状态，当前不提供微信补发指令或后台自动重试。

缓存、并发、幂等、锁和通知复用的实现边界统一维护在 [Chub–OpenClaw 接入设计](CHUB_OPENCLAW_INTEGRATION_DESIGN.md#52-状态快照与维护操作)。

### 3.3 验收

- 连续发送普通 `chub` 只读取快照，不启动 Codex App Server，也不改变槽位或通知状态。
- 多个 Session 并发工作时，状态查询不长期占用调度锁，不阻塞普通任务提交和固定维护操作。
- 并发强制刷新只产生一次数据源刷新；冷却期内不重复刷新，超时和单分区失败均保留可用快照。
- `chub sync` 使用稳定顺序原子更新槽位，失败不提交部分结果，重复消息不再次执行。
- 裸 `codex` 进入普通任务；表格登记的英文指令和中文别名仍按完整匹配进入固定路由。
- 状态查询不重新登记失败通知；完成和重启通知仍使用独立精简状态，不受总览失败影响。
