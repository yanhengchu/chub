# 配置驱动的飞书文档下载自动化方案

> 状态：已实现并验收。当前支持受管 Debug Chrome、飞书登录检查、配置驱动下载，以及 V 国内业务周报输入集的完整发布。

## 1. 当前能力

首页提供相互独立的“自动化任务”和“自动化环境”卡片：

- 自动化任务展示启用任务、当前周期材料、最近结果和手动运行入口；
- 自动化环境管理受管 Debug Chrome、浏览器用户和飞书登录状态；
- “全部任务”页面展示完整任务列表和执行结果；
- 各卡片独立请求、缓存、刷新和报错，任务运行只定向更新受影响卡片。

当前任务由维护者从首页、全部任务页或命令行手动触发，尚未接入系统定时调度。页面在浏览器未启动时可显示“启动并运行”，使用已初始化的受管默认 Profile 以无界面模式启动并确认就绪后再提交任务；不会自动初始化 Profile、切换账号或改用有界面模式。

## 2. 受管浏览器环境

自动化只连接由 `chrome-cdp` 管理的独立 Debug Chrome，不接管用户日常 Chrome。浏览器用户来自本机稳定版 Chrome 的普通持久化 Profile；Guest 模式不纳入列表，客户端不能传入用户目录或任意文件路径。

Profile 初始化是一次性受控复制：

- 默认 Chrome 仍在运行时拒绝初始化，避免复制不一致的数据；
- 复制到独立自动化目录后再由 Debug Chrome 使用；
- 初始化、选择、启动和停止都等待最终状态并写入操作日志；
- 任务执行或登录检查期间通过跨进程文件锁阻止冲突操作；
- 有界面与无界面是进程启动属性，切换前必须先停止当前实例。

自动化任务只关闭自己创建的页面和弹窗，不关闭共享 Debug Chrome，也不操作用户已有页面。即使有界面窗口被手动关闭，受管基础页仍用于保持 CDP 会话可连接。

## 3. 飞书登录检查

自动化环境可以检查固定租户云文档的登录状态。检查只判断当前受管 Profile 是否已登录，不代表具体文档一定存在或具备访问权限。

- 进入固定租户业务域名时显示“登录有效”；
- 进入飞书账号域名时显示“需要登录”；
- 进入其他域名、超时或页面异常时显示“检查失败”；
- 浏览器停止、重启或切换 Profile 后清除旧检查结果。

需要登录时，页面只截取飞书登录二维码 Canvas 并在自动化环境卡片内展示。二维码作为短期凭证保存在私有临时目录，图片接口要求可信访问并返回 `no-store`；登录完成、图片更新、浏览器停止或页面离开时清理临时文件和对象地址。二维码、Cookie、Token、手机号和完整登录页均不写入日志或长期状态。

## 4. Runner 流程

所有入口调用同一 Automation Runner：

```text
校验任务配置
  -> 获取共享浏览器锁
  -> 连接 Debug Chrome 并创建任务页面
  -> 检查登录与导航域名
  -> 执行白名单页面步骤并捕获下载
  -> 校验内容并安全落盘或发布
  -> 写入最终状态和操作日志
  -> 清理本次页面、临时文件和连接
```

Web 提交只代表任务已受理。页面通过持久化状态轮询排队、运行、成功或失败；Runner 必须主动写入最终结果，不能把子进程创建成功当作任务成功。

步骤类型和参数由严格模型及版本化模板限定，不允许执行任意 JavaScript、Shell 或 Python。主页面和弹窗导航必须位于任务生成的域名白名单内；登录域名只用于识别登录失效，不成为可继续执行的业务域名。

下载步骤必须明确声明预期下载事件。导航、等待等无副作用步骤可有限重试，点击、事件派发和下载触发不做整任务自动重试，避免重复产生外部副作用。

## 5. 配置边界

任务清单来自：

- `config/automations.yaml`：跨节点公共任务，纳入版本管理；
- `config/automations.local.yaml`：本机任务，不提交；
- `config/automations.example.yaml`：本机配置示例。

公共任务和本机任务按固定顺序合并；任务 ID 和展开后内容完全一致时去重并保留公共任务，ID 相同但内容不同时明确报错，不允许本机配置静默覆盖公共任务。任务文件只描述受控任务身份和文档入口；登录检查、选择器、步骤、超时、输出及扩展规则由仓库内版本化模板维护。

配置模型拒绝未知字段、未知动作和不适用参数。登录密码、Token、Cookie 和任意本机路径不得写入配置。旧配置仅在代码明确保留的兼容范围内加载，新能力以当前示例和模板为准。

## 6. 下载与落盘

普通任务的文件处理流程为：

```text
下载到目标目录内的临时文件
  -> 校验非空、大小、扩展名和已支持的内容类型
  -> 应用冲突策略
  -> 原子替换为最终文件
  -> 标记任务成功
```

下载目录必须解析在自动化数据根目录内；浏览器文件名和配置文件名都要经过路径清理。临时文件和最终文件限制为当前用户访问，失败时清理本次临时结果。PDF、ZIP 和 Markdown 使用对应的基础校验，不支持的类型明确拒绝。

## 7. V 国内业务周报输入发布

`V 国内业务周报` 是当前已接入的专属扩展任务。它下载主周报，并从“各端周报”章节提取同租户、受控路径且数量受限的关联文档。

当前周期固定为周一至周日；每周三到下周二属于同一个处理周期，下周二为报送日。主文档、五类本期来源和上周参考资料先进入本次运行暂存区，只有全部下载并通过结构、角色和周期校验后，才整体发布为：

```text
data/artifacts/weekly-reports/<周期>/inputs/
  <主周报>.md
  linked/
    <关联文档>.md
    .sources.json
```

资料未更新或角色不齐时显示“等待各端更新”；下载、读取或结构异常时显示失败。两种情况都保留上一份有效输入和更新标记。发布采用同一受控操作更新输入目录与标记，失败时回滚，避免周报技能读取半套材料。

新周期开始时页面切换为待下载，但不会删除上期工作区、材料或历史操作记录。任务标题、当前周期和各材料结果分别展示，整体状态只代表本周期输入集是否可用。

## 8. 状态、日志与安全

- 同一时间只允许一个浏览器任务或登录检查操作；文件锁由操作系统在进程退出时释放。
- 状态文件用于展示和异常恢复，不代替互斥锁。
- 每次任务记录任务 ID、时间、最终状态、当前步骤和非敏感失败原因。
- 操作日志覆盖 `requested`、`started`、`succeeded` 和 `failed`，最终成功只在文件或输入集完成发布后记录。
- 日志不记录 Cookie、Authorization、二维码、页面敏感字段或完整浏览器上下文。
- 任务超时、登录失效、越界导航、非法路径、内容校验失败和锁冲突都返回可区分结果。

当前不支持验证码或多因素认证自动处理、任意脚本、多下载并行、跨设备任务编排或集中式任务队列。系统定时调度也未启用；未来接入前必须先明确 Debug Chrome 的常驻与失败策略。

## 9. 维护规则

新增或调整自动化任务时，应同步维护任务示例、固定模板、严格模型、相关测试和真实页面验收。涉及周报输入角色、周期或发布结构的变化，还必须同步周报技能设计及其契约文件。

当前自动化已经覆盖从受管浏览器、登录检查、任务执行到安全落盘和周报输入发布的完整手动链路。后续维护重点是适配真实页面变化和增强校验，不应把网站操作逻辑移入系统调度器或客户端参数。
