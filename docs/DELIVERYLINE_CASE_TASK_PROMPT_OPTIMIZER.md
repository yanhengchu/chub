## 当前场景

本案例来自已有的[Chub 任务提示词优化插件设计](CHUB_TASK_PROMPT_OPTIMIZER_PLUGIN_DESIGN.md)。该设计描述了一个独立任务编排插件：普通任务经过统一分发器后，可以按受理时配置进入提示词优化阶段，再继续提交唯一的物理主任务。

已有设计文档已经明确的内容：

- 插件只消费统一分发器提供的规范化任务正文和受控上下文。
- `direct` 模式直接返回原正文，不调用 AI。
- `auto` 模式通过 Chub 的受控能力完成一次提示词优化，并按检查点恢复。
- 插件阶段完成不等于物理主任务完成，也不单独发送用户通知。
- 优化失败、结果未知或结果不合法时，不回退执行未经处理的原文。
- 第一阶段三个独立交付项均已由维护者验收通过，验收范围限于仓库开发模块来源：插件发现、协议预检、导入与移除；启停、Web 装配状态与启用后移除反馈；独立设置入口、模式配置和状态呈现。ZIP 制品路径按维护者决定作为低优先级独立小功能暂缓，通用宿主支持 ZIP 不等于本插件 ZIP 路径已验收。第一阶段已确认的交付意图还包括任务受理时的模式快照，但该能力未实现，也未包含在三个已验收独立交付项中；其归属是下一阶段接续还是另拆交付项，尚待维护者确认。任务阶段注册、`direct` / `auto` 实际执行、非空阶段链和 Web/微信任务接入尚未交付。真实微信结果仍需维护者在微信客户端验收。

以上是来源设计文档已明确的插件运行规则；本案例的阶段实现和验收状态以下文时间线及验收范围为准。

**所属阶段与整体目标：**属于第一阶段“独立插件可管理、可配置”的首项，为后续启用、设置和运行提供可靠的插件制品入口。本项建立插件从通用来源发现、协议校验、导入登记到安全移除的基础生命周期闭环；不代表插件已经进入任务阶段链。

**交付意图：**让 Chub 使用通用插件机制发现并校验任务编排插件，完成导入登记；维护者也能从插件管理入口撤销登记，形成可恢复的“发现—导入—移除”基础闭环。

**交付内容：**发现仓库索引声明的开发模块和通用机制支持的 ZIP 制品；校验模块身份、Manifest、任务编排协议与 Chub 兼容信息；将合规制品登记到通用插件宿主并展示导入状态。移除开发实现只撤销登记，保留仓库源码和索引；移除 ZIP 实现清理任务编排插件专属安装副本，保留 ZIP 来源文件。导入和移除均以宿主权威状态确认结果。

**范围边界：**不另建插件专用扫描、导入或移除机制；不扫描与项目目录平级的 `chub-local-modules/` 本机模块源。移除仅适用于未启用、未加载且无阶段链引用的制品。当前编排请求的 `stage_chain` 固定为空，因此没有活动阶段引用；开放启用、加载或非空阶段链前，必须由分发状态权威所有者增加活动请求引用检查。导入不等于启用或加载；本项不包括启停、加载、替换、专属设置页、`direct` / `auto` 配置、阶段链接入、Web/微信任务处理、内部 Session/AI 调用或提示词优化，这些由后续独立交付项承接。

#### Agent 执行视图

**执行目标**

复用 Chub 通用插件宿主，实现任务编排插件候选发现、类型专属校验、导入登记和受限移除。区分“已发现、校验通过、已导入、已移除”；只有宿主权威状态确认后才报告导入或移除成功。不得将导入状态表述为启用、加载或已进入活动阶段链。

**权威依据与现状**

- [总体架构](CHUB_ARCHITECTURE_DESIGN.md)规定内置开发模块按 `modules/chub-modules.json` 发现；导入记录决定插件管理可见性，但不会自动启用。
- [任务编排插件模块架构设计](CHUB_TASK_ORCHESTRATION_PLUGIN_DESIGN.md)定义任务编排模块的 Manifest、协议、兼容性、开发实现引用和 ZIP 实现引用规则。
- [任务提示词优化插件设计](CHUB_TASK_PROMPT_OPTIMIZER_PLUGIN_DESIGN.md)规定本插件独立登记并遵循任务编排通用模块机制。
- `app/core/module_sources.py` 已支持 `orchestration` 模块类型和索引路径校验；提示词优化模块已登记在仓库索引。插件管理已接入 Manifest 静态预检、开发实现登记、ZIP 安装登记和未启用实现移除；开发源码与候选 ZIP 保留，启用和加载尚未开放。

**范围内要求**

- 复用通用模块来源索引及插件导入流程，支持仓库索引声明的开发模块和通用插件 ZIP；不新增专用来源目录、索引格式或 ZIP 处理器。
- 按任务编排 Manifest 进行类型专属校验，至少检查稳定模块身份、模块类型、协议版本、Chub 兼容声明、阶段 `scope` 和必要入口声明；不另建平行协议。
- 分别生成并校验开发实现 `development_ref`（固定标识与源码摘要）和 ZIP 实现 `implementation_ref`（版本与内容摘要）；同版本不同内容的 ZIP 是不同制品。
- 合规候选通过宿主登记并进入通用可见范围；单个候选失败不得阻断其他候选或 Chub 无关能力。
- 移除开发实现只清除导入和元数据登记，不删除索引或源码；移除 ZIP 实现清除导入/安装记录及该制品专属安装副本，不删除候选 ZIP 或其他模块数据。
- 已启用制品拒绝移除并说明原因。当前不开放启用/加载且 `stage_chain` 固定为空；未来阶段链能够引用制品前，必须增加实际请求引用检查。

**明确不做**

不实现启停、加载、替换、非空阶段链或被现有任务引用时的完整移除规则；不实现插件专属设置页和 `direct` / `auto` 配置；不接入 Web/微信任务，不创建内部 Session/AI 任务，也不执行提示词优化。不得绕开通用宿主执行任意路径、命令或外部提供的代码。

**失败与最终状态**

- 校验失败不得产生成功导入状态；失败候选局部隔离。
- 导入和移除后均需确认宿主权威状态；状态未知时先查询、对账，不伪造成功或盲目重复副作用操作。
- ZIP 安装副本清理失败时保留导入登记并允许重试；若副本已清理但状态保存失败，保留的不可用登记可重试移除。
- 开发源码、索引和 ZIP 来源文件始终保留；删除 ZIP 安装副本只能依据宿主保存的固定插件目录，不能越界清理其他插件或运行态。
- 导入不会启用或加载插件，也不改写已有任务快照或阶段链。

**最低验收标准与证据**

1. 通用扫描发现仓库索引声明的任务编排开发模块及通用机制提供的有效 ZIP 候选。
2. 有效开发模块和 ZIP 分别通过 Manifest、协议及兼容性校验，并进入宿主确认的已导入状态。
3. 无效协议、入口或兼容信息不能导入成功；单个候选失败不影响其他候选。
4. 导入后状态可见，但插件未启用、未加载且活动阶段链不变。
5. 移除开发实现后登记消失且源码、索引仍在；移除 ZIP 后安装副本清理、来源 ZIP 保留。
6. 已启用制品不能移除；当前 `stage_chain` 固定为空。ZIP 清理失败或最终状态无法确认时，结果保持可重试或明确失败，不报告成功。
7. 验收证据覆盖候选发现、有效/无效预检、导入和移除前后的宿主状态及失败隔离；证据不替代维护者验收。
