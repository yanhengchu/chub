# Chub 微信任务编排插件模块设计

> 状态：已验收
> 主要读者：AI Agent；维护者通过与 AI Agent 协作，理解并确认本文规则。
> 本文负责：定义微信普通任务正文在“直接执行”、共享源码的开发实现和 ZIP 任务编排插件模块之间的当前分流行为、恢复边界与验收范围。
> 本文不负责：任务编排插件模块的通用协议和安装机制、Session/Worker 状态机、微信固定指令语法或用户可见回复格式。
> 维护说明：首个微信润色任务编排插件模块已在 macOS 真实微信文字路径验收。ZIP 仅表示正式交付与安装形态。后续改变阶段链、实现引用、恢复顺序、模块协议或外部路由时，须按本文“验收范围与复检”重新验收。

## AI 可执行契约

1. 只有已通过微信入口认证、幂等、固定指令识别、路由和正文限制的**普通任务正文**才进入编排。固定指令解释、身份与路由不委托给编排实现。
2. 每个请求由 Chub 持久化保存入口幂等关联、原始/当前任务文本、阶段链快照、cursor、已授权能力、阶段子任务、最终主任务、检查点和终态。重复入口、重复回调或重启对账只能读取并推进原请求，不能重新创建副作用。
3. 最终主任务只能由统一分发点在阶段链完成后投递；只有该物理主任务的可信终态才能完成编排请求并触发最终通知与微信回送。翻译等阶段子任务终态不得视为用户任务完成。
4. 已受理的润色请求固定创建时的 `weixin-orchestration-dev` 源码摘要或 ZIP `implementation_ref`；直接执行请求没有阶段链。后续启用、停用、替换、移除或配置变化只影响新请求；不得将旧请求改投其他实现或执行原文。
5. 模块只可使用 Chub 为当前请求签发的受限能力投影；不得直接操作 Worker、Runtime、微信、文件、网络或系统命令，也不得自行投递物理主任务、读写编排状态或改变固定目标。
6. 结果未知、实现不可用、源码/产物摘要不匹配或阶段失败时必须失败关闭；不得静默跳过润色、改投其他实现或执行原文。
7. 本次收敛前已持久化为 `kind=internal` 的旧润色阶段不再执行；恢复或回调时明确失败，维护者应重新提交任务。当前活动偏好在启动时迁移为开发实现，不改写已受理请求的阶段快照。

## 当前行为与边界

“微信任务润色”仅影响之后接收的微信任务正文，支持既有三种处理模式：

- **直接执行**：使用空阶段链，规范化正文只投递一次物理主任务，不启动润色任务。
- **自动润色后执行**：执行 `weixin_refinement`，翻译子任务完成后将润色后的正文交回分发点，再投递主任务。
- **自动润色后确认执行**：执行 `weixin_refinement` 并等待确认；确认后使用已保存的润色结果继续，取消则按既有契约收敛且不遗留等待中的编排请求。

下表区分当前实现中名称相近但绑定范围不同的对象；维护或恢复时不得混用：

| 名称 | 类型与作用 | 对已受理请求的影响 |
| --- | --- | --- |
| `weixin-orchestration-dev` | 仓库固定开发实现名 | 固定实现名和源码 SHA-256 摘要；摘要变化不能继续旧请求。 |
| `weixin-refinement` | 首个 ZIP 的 `module_id` | 仅用于识别模块产物；同版本不同内容仍是不同产物。 |
| `implementation_ref` | ZIP 的模块标识、版本和内容摘要组成的不可变引用 | 请求恢复时必须使用同一 ZIP 产物，不得改投当前活动模块。 |

设置页首项“插件是否启用”决定后续新微信正文是否进入润色流程；关闭后无论润色模式为何值，都直接投递。该开关与“编排实现”和“润色模式”独立：选择开发实现或 ZIP 只切换新请求的版本，不会自动启用插件；润色模式只决定已启用插件的处理方式，并会在插件停用、实现取消或当前 ZIP 移除后保留。选择直接执行即直接投递，不创建润色阶段。插件已启用时，选择两种润色模式必须存在固定开发实现 `weixin-orchestration-dev` 或已导入的 `weixin-refinement` ZIP；没有可用实现时不能启用插件，但可保留或调整之后恢复时使用的润色模式。设置页在“微信任务润色 → 编排实现”中统一显示“`微信任务润色 · 开发实现`”或“`微信任务润色 · 正式版 v<版本号>`”，不显示 `weixin-orchestration-dev`、源码摘要或 `implementation_ref`。这些内部引用仍是请求快照和恢复绑定的权威值，不能由可见名称推断或替代。开发实现与 ZIP 打包共用仓库 `orchestration-modules/weixin-refinement/` 源码，前者绑定源码 SHA-256 摘要，后者绑定包含内容摘要的不可变 `implementation_ref`。模块不接受页面、微信或配置传入的代码路径。

插件 ZIP 仅接受 `capability-orchestration`、`weixin-normal-text` 和协议版本 `1` 的产物。“插件模块 → 插件管理”的“任务编排插件导入”负责预检、导入、列表与移除；“微信任务润色”只负责选择实现、设置插件是否启用和润色模式。导入或切换实现不会自动启用。同版本但内容不同的 ZIP 是独立产物，不能覆盖仍被非终态请求引用的旧产物。被非终态请求引用的插件仍不能移除；没有未结束引用时，可以直接移除当前活动 ZIP，Chub 会同步清空当前实现并停用插件。

携带正文的 `S# [task]` 仍由 Chub 先完成槽位选择和持久化，再向编排实现签发固定目标的受限上下文；模块不能改选目标。没有任务正文的固定指令、Web 快速交互、自动化和周报不进入本分流。续提、确认和取消只恢复或推进已有请求的检查点，不创建新编排请求。

目标正在写入时，直接执行明确拒绝且不进入润色链路；最近一条被拒正文最多保留为短期 `retry` 候选，不自动排队或自动重投。润色后的固定目标暂忙时，请求保持等待，只向原目标重试。

## 恢复与最终状态

Web 或 Quick Worker 重启后，Chub 先对账已提交子任务与主任务的可信状态：已完成的阶段按原检查点和原实现引用继续，未完成的任务继续等待，无法安全确认且继续会重复副作用时明确失败。恢复不得切换到当前活动模块、另一 Runtime、另一 Session 或另一目标。

Quick Worker 的可信终态事件会定向推进已绑定请求；启动对账只读取已有关联，不重新提交翻译子任务或主任务。Web 重启时，先恢复 Quick Worker 可用状态，再恢复等待中的投递，不能仅因 Worker 尚未就绪判定润色失败。通知终态独立记录；任务已受理、HTTP 成功或进程启动均不代表用户任务成功。

通用模块协议、生命周期和能力执行面规则以[Chub 任务编排插件模块架构设计](CHUB_TASK_ORCHESTRATION_PLUGIN_DESIGN.md)为准；微信身份、路由、幂等与持久化边界以[OpenClaw 定制集成设计](OPENCLAW_CUSTOMIZATION_DESIGN.md)为准；固定指令和用户可见回复格式以[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md#4-微信-clawbot-指令)为准。

## 维护者操作

构建首个模块使用：

```bash
python scripts/build_weixin_orchestration_plugin_zip.py --version 1.0.0
```

默认产物命名为 `weixin-refinement-release-<版本>-<UTC时间>.zip`。随后在“插件模块 → 插件管理 → 任务编排插件导入”导入插件 ZIP，再在“微信任务润色 → 编排实现”中显式选择它，并按需要单独打开“插件是否启用”。不要手动修改插件安装目录；内容摘要变化会使已绑定请求失败关闭。确认没有非终态引用后，可以在插件管理直接移除对应产物；若移除的是当前活动 ZIP，Chub 会同步清空选择并停用插件。

## 验收范围与复检

截至 2026 年 9 月 9 日，已在 macOS 本机通过真实微信文字交互完成以下验收：

- 开发实现与首个 `weixin-refinement` ZIP 的分流和执行。
- 直接执行不进入润色链路；自动润色完成“翻译子任务 → 固定目标主任务 → 通知”；确认模式的确认与取消均按既有契约收敛。
- 开发实现的新任务选择、源码 SHA-256 快照、旧请求快照保持与摘要变化失败关闭。
- ZIP 的导入、启用、停用文本优化、切换实现、移除、引用保护和内容摘要隔离。
- ZIP 任务处理中发生 Web 重启及 Quick Worker 重启后的真实恢复：原请求保持原实现引用，翻译子任务、主任务和通知均只收敛一次。

本验收不承诺 Ubuntu 和可信语音的真实平台路径；它们在需要交付对应平台或语音能力时单独复检。以下变化也必须重新验收：阶段链/cursor 或最终投递的状态所有权、模块协议或实现引用规则、润色目标等待或恢复顺序、微信固定指令与 `retry` 语义、Quick Worker 恢复契约、OpenClaw 路由或通知终态。
