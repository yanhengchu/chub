# 本期工作周报自动化与生成设计

> 状态：已实现并验收，持续维护。当前采用人工触发、分阶段执行和重点确认门禁；受管 Chrome 的跨平台实机范围以 `.agents/skills/chrome-cdp/SKILL.md` 的当前状态为准。

## 1. 当前定位

本期工作周报是一条由 Chub 自动化和 `generate-weekly-report` 技能共同完成的端到端流程：第一阶段从飞书准备并发布完整输入，第二阶段整理本期重点、等待维护者确认，再生成和复核正式周报。

```text
受管 Debug Chrome 下载飞书资料
  -> 校验周期、结构和来源角色
  -> 原子发布本期 inputs
  -> 适配 mapping / manifest
  -> 生成本期重点确认清单
  -> 维护者确认或调整
  -> 生成正式周报
  -> 格式校验 + 事实与文案 Review
```

两个阶段属于同一产品链路，但保持独立状态和验收边界：资料未完整发布时不能开始生成；输入变化后，旧的确认和正式稿自动失效。当前不提供定时下载、无确认生成或全自动一键串联。

## 2. 页面与操作方式

首页提供相互独立的“自动化任务”和“自动化环境”卡片：

- 自动化任务展示启用任务、本期材料、最近结果和手动运行入口；
- 自动化环境管理受管 Debug Chrome、浏览器用户和飞书登录状态；
- “全部任务”页面展示完整任务列表和执行结果；
- 首页“本期周报”展示当前周期的重点清单和正式稿，尚未产出时显示“待生成”。

维护者可从首页、全部任务页或命令行手动触发下载。浏览器未启动时，页面可使用已经初始化的默认受管 Profile 以无界面模式“启动并运行”；不会自动初始化 Profile、切换账号或改用有界面模式。周报生成继续由维护者在材料齐备后手动发起。

## 3. 周期和工作区

正式周报周期固定为周一至周日。每周三开始新一期处理窗口，从周三至下周二的下载和汇总始终归属同一周期，下周二为报送日。

```text
data/artifacts/weekly-reports/<周期>/
  inputs/
    <主周报>.md
    linked/
      <关联文档>.md
      .sources.json
  mapping.json
  manifest.json
  output/
    本期工作重点确认清单-<周期>.md
    weekly-report-confirmation.json
    本期业务周报-<周期>.md
    周报生成核对记录-<周期>.md
```

新周期开始时页面切换为待下载或待生成，但不删除上期工作区、材料和操作记录。下载阶段只发布唯一有效的 `inputs/`；生成阶段只读输入文件，所有新内容写入本期工作区。

## 4. 阶段一：资料准备与发布

### 4.1 受管浏览器

自动化只连接由 `chrome-cdp` 管理的独立 Debug Chrome，不接管用户日常 Chrome。浏览器 Profile 由默认 Chrome 的普通持久化 Profile 一次性受控复制；复制前必须确认默认 Chrome 已退出，复制后的网站登录状态与默认 Chrome 不自动双向同步。

Profile 初始化、选择、启动和停止都等待最终状态并写入操作日志。任务执行和登录检查使用跨进程锁避免冲突；任务只关闭自己创建的页面和弹窗，不关闭共享 Debug Chrome 或用户已有页面。

自动化环境可检查固定租户云文档的登录状态。需要登录时只展示飞书登录二维码 Canvas；二维码作为短期凭证保存在私有临时目录，接口返回 `no-store`，登录完成或环境变化后立即清理。二维码、Cookie、Token、手机号和完整登录页不进入日志或长期状态。

### 4.2 配置和 Runner

任务清单来自跨节点公共配置 `config/automations.yaml` 和不提交的本机配置 `config/automations.local.yaml`，示例维护在 `config/automations.example.yaml`。任务只声明受控身份和文档入口；选择器、步骤、超时、输出及扩展规则由仓库内版本化模板维护。

所有入口使用同一 Automation Runner：

```text
校验任务配置
  -> 获取共享浏览器锁
  -> 创建任务页面并检查登录和导航域名
  -> 执行白名单页面步骤并捕获下载
  -> 校验内容、周期和来源角色
  -> 原子发布输入或安全落盘
  -> 写入最终状态并清理本次资源
```

Web 提交只表示任务已受理；成功必须以文件或完整输入集最终发布为准。步骤模型不接受任意 JavaScript、Shell、Python、本机路径或未知动作。主页面和弹窗必须停留在任务生成的域名白名单内；有外部副作用的点击和下载触发不自动重试。

### 4.3 周报输入契约

`V 国内业务周报` 下载主周报，并从“各端周报”章节提取数量受限、同租户且路径类型受控的关联文档。当前资料范围为：

- 上周周报 `previous-report`，只用于结构、背景和延续事项参考；
- 产品商业化、产品/OS、运营、客户端、服务端五类本期事实来源；
- 可选的周会记录、人工确认和补充材料。

五类本期资料都允许每周更换飞书文档地址。下载阶段不再用链接标题或文档 ID 判断业务端身份，而以受信主周报中的五份关联资料为准；链接仍必须属于同一飞书租户并使用 `/wiki/` 或 `/docx/` 文档类型。每份资料下载后必须从正文开头的标题或周期声明中检测到结束日期落在本期，否则保持等待且不发布整套输入。

主文档、五份本期来源和上周参考先进入运行暂存区。只有全部下载并通过结构、数量和周期校验，才整体发布到本期 `inputs/`。资料未更新或数量不足时显示“等待各端更新”；下载、读取或结构异常时显示失败。两种情况都保留上一份有效输入及其正式稿失效标记，避免生成阶段读取半套材料。

本期资料的使用范围结束日期必须落在正式周期内，开始日期可以早于周一；上周参考不参与本期日期校验。图片或 Canvas 中无法可靠读取的内容不能作为确定事实。

## 5. 阶段二：重点确认与正式生成

`generate-weekly-report` 技能位于 `.agents/skills/generate-weekly-report/`。它不打开飞书、不下载文档，也不修改自动化任务状态。

### 5.1 输入适配

`mapping.json` 声明来源角色、使用范围和报告校验规则，适配器据此生成 `manifest.json`。Manifest 为每份材料记录受控相对路径、业务角色、来源标题和链接、内容状态、实际使用周期、标题范围、文件哈希、运行标识及下载时间。

技能不能根据文件顺序或自然语言文件名猜测角色。只有 `ready` 或经维护者明确记录为 `manually-approved` 的材料才能进入正式汇总；绝对路径、目录穿越、远程 URL、非 Markdown 文件和不唯一的标题范围均明确拒绝。

### 5.2 重点确认门禁

阶段 A 先生成本期重点确认清单，记录每项 OKR 和其他重点工作的去向、来源覆盖、冲突、缺失项，以及建议纳入、合并、弱化、排除或待确认的内容。

维护者确认同时写入清单和 `weekly-report-confirmation.json`，绑定确认时间、最终取舍、带缺口批准范围、Manifest fingerprint、清单路径和清单哈希。输入、使用范围或清单发生任何变化，旧确认立即失效，必须重新校验和确认。

### 5.3 正式周报和复核

阶段 B 以已确认重点为主线，再回到原始材料核对数字、日期、版本、状态和责任边界。上周事项必须明确为继续、更新、关闭或不纳入；不同来源统计窗口不改写成完整周报周期，也不直接作不等口径比较。

正式稿默认直接进入业务关键指标或第一项 OKR，不展示输入资料清单和内部编制说明。来源链接统一放在文末；业务摘要只在维护者明确要求时生成。

技能内的 `.agents/skills/generate-weekly-report/scripts/validate_weekly_report.py` 执行 Manifest、周期、角色、路径、使用范围、哈希绑定、业务章节、Markdown 表格、来源链接和占位标记等确定性检查。正式稿还必须完成完整性、事实准确性和文案一致性 Review，结果写入本期核对记录。校验失败时可保留草稿，但不能标记完成。

## 6. 状态失效和失败处理

- 同一时间只允许一个浏览器任务或登录检查操作；状态文件用于展示和恢复，不替代互斥锁。
- 输入目录只有在完整校验通过后才原子更新；失败不会覆盖上一份有效材料。
- 新输入发布后，已有 Manifest、确认、正式稿和核对结果均视为失效。
- 输入缺失、仍在编辑或范围不明确时默认停止；只有维护者明确批准带缺口继续，才记录批准范围并进入正式生成。
- 每次下载和生成都保存非敏感状态与失败摘要；最终成功不以子进程启动或模型回复为依据。

## 7. 安全和维护边界

- 原始材料只读；生成内容只写入当前周期受控目录。
- 配置、Manifest、日志和展示文档不得包含 Token、Cookie、账号、二维码或终端票据。
- 日志只记录任务、角色、相对路径、状态和错误摘要，不记录文档全文。
- 项目资料页面只展示适合可信网络只读访问的内容，敏感业务材料不得直接纳入公开展示。
- 当前不支持验证码或多因素认证自动处理、任意脚本、多下载并行、跨设备编排、集中式任务队列或系统定时调度。
- macOS 已完成受管 Chrome 无界面生命周期和 Playwright 会话的实机验证；Ubuntu 已完成 Profile 与有界面生命周期实机验证，无界面生命周期和 Playwright 会话仍只有自动化覆盖，相关真实环境使用前需补验。Windows 不属于 Chub 当前支持平台，其验证状态仅由 `chrome-cdp` 技能维护。

飞书页面结构、来源角色、周期、报告结构或稳定业务口径变化时，应同步维护自动化模板、技能 reference、样例和测试。仅本周事实变化时不修改通用规则。现阶段继续保留人工触发和重点确认，是保障输入完整性与最终事实准确性的产品边界。
