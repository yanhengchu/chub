# 微信 ClawBot 语音转写来源标记补丁规范

> 状态：已应用于当前 Ubuntu 运行环境；微信插件升级或重装后需要复检并恢复等价能力。

## 1. 目的与行为

腾讯微信插件会把带 `voice_item.text` 的语音消息直接转换成普通正文，OpenClaw 的 `before_dispatch` Hook 因而无法区分语音转写与用户键入文字。微信 Chub 模式需要保留这个来源，才能在任务提交成功回执中显示本次语音识别内容。

当前契约如下：

1. 只有上游消息项类型为 `VOICE` 且包含非空转写时才设置来源标记。
2. `BodyForAgent` 始终保留干净的转写正文，固定标记只进入命令正文通道。
3. Chub Hook 只有同时看到固定标记和不同的干净正文时才按语音处理；用户键入同样的标记不会被识别为语音。
4. 提交给 Chub 的任务正文和幂等摘要使用干净转写，不包含标记。
5. 语音识别内容只在首次提交成功回执中显示；重复消息、提交失败和普通文字回执不增加该项。
6. 回显最多 3000 个字符，超出时明确标注截断，避免提交回执超过微信单条发送能力。

## 2. 恢复方式

先使用 `openclaw plugins inspect openclaw-weixin --json` 确认实际加载目录和版本。若上游已经向 `before_dispatch` 提供可信语音来源和干净转写，应适配上游字段，不重复应用本补丁。

当前结构的参考补丁位于：

`integrations/openclaw/patches/weixin-clawbot-voice-transcript-origin.patch`

应用前必须 dry-run，并同时维护 TypeScript 源码与实际加载的 `dist` 产物。不得只修改运行目录而不保留仓库内参考补丁，也不得把标记写入任务正文、日志或对外接口。完成后重启 OpenClaw Gateway，确认微信通道和 Chub 插件均正常加载。

## 3. 验收

1. 发送普通文字：提交回执仍只有固定确认文案。
2. 发送短语音：提交回执新增“语音识别内容”，正文与微信转写一致，任务正常执行。
3. 将固定标记作为普通文字发送：不得出现语音识别项。
4. 重复投递同一语音：不得重复执行，重复回执不再次展示语音内容。
5. 模式关闭时：语音转写仍作为干净正文进入原 OpenClaw Agent 流程。

真实微信语音验收依赖外部消息，仅由维护者发送测试语音确认；自动测试覆盖 Hook 识别、干净正文提交和普通文字防误判。
