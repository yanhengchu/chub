# Chub 能力编排外置架构设计

> 状态：持续维护
> 主要读者：需要设计、实现或排障能力编排模块的 AI Agent；维护人员用于确认通用架构、状态归属和模块维护边界。
> 本文负责：定义能力编排模块的通用职责、Chub 进程内能力执行面、请求与检查点模型、模块协议、生命周期和平台验收原则。
> 本文不负责：任何具体入口或业务任务的编排逻辑、用户可见交互和分流开关；微信任务正文由[Chub 微信任务编排外置设计](WEIXIN_TASK_ORCHESTRATION_EXTERNALIZATION_DESIGN.md)维护。
> 维护说明：首个微信润色编排模块已验收直接执行、固定开发实现与 ZIP 产物的分流、快照、生命周期和恢复；macOS 真实微信文字路径已完成任务处理期间 Web 与 Quick Worker 重启恢复验证。本文仍为“持续维护”，因为它定义可扩展到后续任务范围的通用协议，而非只描述首个微信模块。

## AI 可执行契约

1. 能力编排外置的是**已准备执行用户需求的逻辑处理权**。Chub 先完成入口认证、幂等、固定指令识别、路由和输入限制；只有得到规范化任务信息后，才创建或恢复编排请求并进入统一任务分发点。固定指令的解释不委托给编排实现。分发点按创建时快照串行调用零个或多个编排阶段；阶段完成后必须回到同一分发点，由 Chub 决定下一阶段或最终主任务投递。Chub 继续拥有权限、实际执行、任务终态、通知、日志和模块维护。
2. 模块与 Chub 同机，由 Chub 从固定目录加载。Chub 的**进程内能力执行面**不是远程服务或通用 HTTP API；它复用 Chub 现有的 Session、任务、Worker、Runtime 和通知能力，保证其状态所有权不被模块绕过。
3. 模块只能查询并调用本次编排请求获得授权的能力投影。能力目录以[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md#11-核心能力)为准；能力 ID 不是模块可直接导入的函数。模块不得操作 Worker、Runtime、微信、文件、网络或系统命令，也不得提供 Runtime、原生 Session、路径、命令、URL、环境变量、收件人或身份材料。
4. Chub 为每次编排保存 `orchestration_id`、入口幂等关联、原始用户需求、当前任务文本、阶段链快照与当前位置、固定的实现引用、已授权能力、能力调用记录、检查点和最终状态。入口幂等关联是重复入口的权威关联；编排记录只能与其一对一绑定，重启对账不能以新请求替代原记录。模块只定义检查点与下一任务文本，不能直接读写 Chub 持久化状态。
5. 能力执行面只返回 `succeeded`、`waiting`、`rejected`、`unavailable` 或 `unknown`。模块只能依据可信成功或对应等待关联的终态推进；不得以 HTTP 成功、进程启动、日志文本或模型正文推断成功。
6. 模块在一个事件回合中至多请求一次能力，随后返回检查点、等待声明或下一任务文本。它不能以未受控线程、计时器、连接或内存会话推进流程。阶段完成不等于用户主任务完成：阶段返回下一任务文本后，Chub 分发点才继续后续阶段或最终投递；只有物理主任务终态才决定用户完成通知。

## 当前实现范围

| 范围 | 当前状态 | 可选实现 | 不属于当前实现 |
| --- | --- | --- | --- |
| 微信普通任务正文 `weixin-normal-text` | 已验收 | 直接执行、固定开发实现 `weixin-orchestration-dev`、已导入 ZIP | 由[Chub 微信任务编排外置设计](WEIXIN_TASK_ORCHESTRATION_EXTERNALIZATION_DESIGN.md)定义具体分流与验收。 |
| 其他入口或业务范围 | 未接入 | 无 | Web 快速交互、自动化、周报、没有任务正文的固定指令及其他业务范围不得因本文被视为可编排。 |
| 任意排序、多阶段循环/DAG、远程模块或通用 HTTP 执行面 | 未接入 | 无 | 不得在页面、API 或模块中宣称可用。 |

编排 ZIP 的 `implementation_ref` 是“模块标识 + 版本 + 内容摘要”的不可变产物引用；它在请求创建时固定。它不是 Runtime 的 `implementation_id` 槽位，不能用于选择 Runtime、Session 或 Runner，也不能复用 Runtime 模块的目录、注册表或维护操作。

## 通用架构与状态

```text
受保护入口完成认证、幂等、固定指令识别和输入校验
        |
        v
Chub 形成规范化任务信息后：创建或恢复请求，进入统一任务分发点
  ├─ 没有下一阶段 → Chub 最终主任务投递 → Runtime / Quick Worker
  └─ 当前阶段（开发实现 / 已激活模块）
       → 阶段内部按需调用受限能力
       → 返回当前任务文本的新版本或等待/终止结果
       → 回到同一分发点，从下一阶段继续
```

编排协调层与统一任务分发点拥有编排请求、阶段链快照、当前位置、能力调用记录、检查点、活动偏好和最终状态。关闭能力时，空阶段链由分发点直接投递主任务；开启能力时只加载开发实现或 ZIP。Worker 不加载或重新解释编排模块；它只执行分发点在没有后续阶段时提交的受控物理主任务。模块在 Web 控制面收到调用或可信能力完成事件后进入下一回合。

入口中的可信语音只在通道层用于确认来源并取得干净转写；进入 Chub 后，转写与文字都作为同一类规范化任务正文。携带任务正文的固定指令可先由 Chub 完成固定目标选择，再将正文和该目标的受限授权上下文交给编排；没有任务正文的固定指令不创建编排请求。续提、确认、取消等操作只恢复或推进已有请求的检查点，不创建新的编排请求。

编排逻辑状态固定为 `accepted`、`running`、`waiting_capability`、`resuming`、`completed`、`discarded` 或 `failed`。`completed` 只表示最终物理主任务已经确认完成，不能用于表示润色等逻辑阶段完成。Worker 任务状态、Session 生命周期、Native 映射和通知终态继续分别以其专项设计为准。重复入口消息只读取首次请求的当前决定或终态，不重新创建副作用。

重启后，Chub 先对账已提交能力的真实结果：可确认则按原检查点和原模块产物恢复；未完成则继续等待；结果未知且继续会重复副作用时明确失败。不得切换到当前活动模块、内置流程、另一 Runtime 或另一 Session 来“恢复”已受理请求。

### 统一分发点的最小恢复契约

分发点接收用户需求时保存阶段链快照和 `cursor`；每次阶段完成或可信子任务终态到达时，先持久化该阶段结果及下一 cursor，再安排下一次分发。重复回调只能读取已经持久化的阶段结果，不能再次推进 cursor 或重新投递子任务。空阶段链和 cursor 已越过链尾时，分发点才可创建一次最终物理主任务；该任务的终态再收敛整个编排请求。阶段可使用受限能力完成内部工作，但其子任务终态不得被误作最终主任务终态或用户完成通知。

## 模块协议与生命周期

正式或已导入的模块包固定为 ZIP，包根目录有唯一的 `chub-capability-orchestration.json`，且 `module_type` 固定为 `capability-orchestration`。当前微信范围只接受 `scope=weixin-normal-text`、编排与能力协议版本均为 `1` 的产物。它使用独立安装目录、暂存目录和注册表，不能复用 Runtime 模块的目录、槽位、加载器或状态清理记录。

具体编排任务可使用 Chub 固定加载的**开发实现**，例如微信任务正文的 `weixin-orchestration-dev`。它在活动偏好中以 `development_ref` 表示，只从仓库内的固定开发目录加载，不接受页面、微信、模块或配置传入的代码路径。开发实现与已导入 ZIP 并列为受控实现类型，且直接加载其 ZIP 打包的同一仓库源码目录；它不提供任意模块发现或安装。设置页仅以能力名称展示实现：开发实现为“`<能力名称> · 开发实现`”，ZIP 为“`<能力名称> · 正式版 v<版本号>`”；`development_ref` 与 `implementation_ref` 保持内部绑定，不得显示、接受或由名称反推。

每次加载开发实现都计算源码摘要，并将“开发实现名 + 源码摘要”保存到已受理请求的阶段链快照。存在引用该摘要的非终态请求时不得重载其开发目录；Web 重启后发现已保存摘要与当前源码不一致时，相关请求明确失败，不得以新源码继续旧检查点。导入 ZIP 时 Chub 对解压产物计算内容摘要，并保存 `module_id@version+内容摘要` 作为独立、不可变的 `implementation_ref`；每次调用前重新校验安装目录内容摘要，摘要不一致的已受理请求明确失败。

清单至少声明 `protocol_version`、`module_id`、`version`、`scope`、`orchestration_protocol_version`、`capability_protocol_version`、`display_name`、`description`、`chub_version` 和 `entry`。未知协议、无效入口、超出声明范围、输入/检查点模型不兼容或能力执行面协议不支持时，候选必须保持未激活。

Chub 为每个导入包计算不可变 `implementation_ref`（`module_id@version` 加内容摘要）。活动偏好以 `scope -> 有序阶段引用列表` 保存：空列表表示直接投递。阶段引用是结构化数据，至少包含阶段类别和稳定标识；开发和 ZIP 阶段分别保存其 `development_ref` 或 `implementation_ref`。已受理请求固定其完整阶段链及各阶段摘要。相同版本的新包也是新产物，不能覆盖或删除仍被非终态请求引用的旧产物。阶段链变更、停用或替换只影响后续新请求；已受理请求继续原阶段链，不能自动改投或回退。

| 阶段引用 | 含义 | 已受理请求绑定 |
| --- | --- | --- |
| `development_ref` | 具体任务的固定开发实现名加源码摘要 | 相同开发实现与摘要；源码变化不得继续旧检查点 |
| `implementation_ref` | 已导入 ZIP 的模块标识、版本和内容摘要 | 相同 ZIP 产物 |

导入、激活、停用、替换、移除和恢复均记录 `requested`、`started`、`succeeded` 或 `failed`。目录写入、入口加载或 HTTP 成功不代表操作成功；必须确认注册表、活动偏好和受影响请求的最终状态。当前“替换”通过导入新不可变产物并切换活动引用完成，不覆盖同版本旧产物；移除当前活动产物必须先切换到开发实现或另一 ZIP；被非终态请求引用时拒绝移除。模块专属缓存可按固定白名单清理，Chub 通用设置、编排记录、Session、Worker 任务、通知和第三方数据不得清理。

## 通用接入与验收

新增具体编排任务前，必须先定义其入口上下文、允许能力、模块范围、关闭/开发实现/ZIP 实现的启用分流规则、开发实现名与源码摘要规则、检查点语义、用户可见终态和失败边界。具体设计不得扩大为全局任务执行器，也不得把能力执行面暴露为任意 HTTP 调用入口。

所有模块至少验证：能力越权与伪造引用被拒绝；重复入口不重复执行；能力结果未知不产生替代副作用；重启、模块回合中断、停用、替换和移除不改写已受理请求；模块安装与激活的最终状态可确认。真实外部通道的收发仍由维护者在对应客户端完成验收。
