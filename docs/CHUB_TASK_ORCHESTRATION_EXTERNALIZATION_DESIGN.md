# Chub 任务编排外置设计

> 状态：调研中
> 主要读者：需要设计、实现或评审任务编排模块的 AI Agent；维护人员用于确认外置范围、切换边界和后续验收条件。
> 本文负责：定义任务编排外置的目标架构、受控任务计划、模块边界、版本快照、切换约束和接入验收要求。
> 本文不负责：当前微信固定指令和用户可见回复格式、Runtime Adapter/Runner 实现、Runtime ZIP 生命周期、Session/Worker 状态机或当前文本处理的实现步骤。
> 维护说明：当前微信任务处理仍由主项目提供，尚未存在任务编排模块、模块安装入口或外置运行态。本设计用于约束后续接入，不将目标架构表述为当前能力。

## AI 可执行契约

1. 任务编排外置的是**受控任务策略**，不是可取得 Chub 控制权的通用插件。模块只能依据已校验的标准化请求生成受限任务计划，不能直接执行命令、读写任意路径、调用外部通道或自行提交 AI 任务。
2. Chub 核心始终拥有入口身份、固定路由、请求幂等、Session 选择、权限、Runtime 选择、任务受理、通知路由和操作日志。Quick Worker 始终拥有任务、租约、取消、恢复和最终状态。编排模块不得替代任何一项所有权。
3. 编排模块输出只允许固定计划模型中的枚举动作、已登记的 Runtime 能力需求、已校验的配置引用、确认要求和受限输入变换说明。核心层必须在执行前重新校验计划；模块输出不能携带命令、路径、原始 Runtime ID、收件人、网络目标或任意环境变量。
4. 已受理请求必须保存编排模块标识、版本和经核心校验的计划快照。模块安装、替换、停用或移除只影响之后的新请求，不改写、取消、重放或改变已受理任务。
5. 当前 `chub-module.json` 协议版本 `1` 只支持 Runtime ZIP。任务编排模块接入前必须单独定义兼容的模块类型和加载协议；不得把任务编排逻辑伪装成 Runtime 模块，也不得修改现有 Runtime 模块的加载或清理语义。
6. 编排失败、计划校验失败或计划所需能力不可用时，相关请求必须失败关闭或保持明确等待状态；不得回退执行原文、改投 Session、切换 Runtime、放宽权限或重复提交。

## 当前基线

当前设置页的“微信任务润色”仍由主项目实现。它只影响之后新接收的微信普通正文任务，可选择直接执行、自动润色后执行或自动润色后确认执行，并保存后续翻译任务使用的模型与推理等级。固定指令、Session、目标路由、确认队列、翻译 FIFO、隐藏翻译任务、任务终态和用户可见通知均继续由当前 Chub、Quick Worker 与 OpenClaw 集成契约维护。

这项现有能力不是外置模块：没有模块目录、导入入口、模块版本、模块设置或编排模块状态。当前用户可见行为以[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md#4-微信-clawbot-指令)为准，身份、幂等、持久化和路由边界以[OpenClaw 定制集成设计](OPENCLAW_CUSTOMIZATION_DESIGN.md)为准，任务恢复与终态以[Chub Quick Worker 独立服务设计](CHUB_QUICK_WORKER_DESIGN.md)为准。

## 目标架构

### 编排位置

编排发生在 Chub 已完成入口认证、固定指令解析、目标 Session 选择和基本输入限制之后、创建 Worker 任务之前。模块接收的是已脱敏、限长且带固定上下文的请求，不接触外部通道对象、原始身份材料、任意配置文件或 Worker 私有状态。

```text
可信入口与固定指令
        |
        v
Chub 核心：认证、路由、Session 与输入校验
        |
        v
任务编排模块：生成受控任务计划
        |
        v
Chub 核心：校验计划、持久化计划快照、创建固定任务
        |
        v
Quick Worker：执行固定步骤、维护任务与通知终态
        |
        v
AI Runtime：执行已批准的 Runtime 能力
```

模块不能在 Worker 内临时解释新策略，也不能在任务执行中重新读取“当前模块”。Worker 只读取已经持久化且由核心校验过的计划快照，并按固定执行器完成对应步骤。这样模块替换不会让队列中任务出现版本漂移，也不要求因普通策略替换排空无关任务。

### 受控任务计划

计划模型在核心层定义并版本化，编排模块只能填写下列受限语义：

| 计划内容 | 允许的含义 | 不允许的含义 |
| --- | --- | --- |
| 处理模式 | `direct`、`optimize_auto`、`optimize_confirm` 等后端固定枚举 | 任意脚本、任意步骤名称或跳转 URL |
| Runtime 能力需求 | 例如需要后台 Turn、模型目录或只读文本处理 | 原始命令、二进制路径、未注册 Runtime 选择 |
| 配置引用 | 已登记的模型、推理等级、权限配置或节点级默认值 | 模块自定义的秘密、任意环境变量或工作目录 |
| 确认与重试 | 是否进入固定确认队列，以及既有的有限重试类别 | 改写确认语法、无限重试、变更保存的目标 Session |
| 输入变换 | 使用固定 Runtime 任务生成润色文本、限制长度和输出格式 | 直接伪造执行结果、绕过原文/结果限制或保留敏感输入 |

Chub 核心在持久化前验证计划字段、能力依赖、目标 Session 状态和配置兼容性。验证通过后，计划与模块 ID、版本、计划协议版本一同成为任务快照。计划协议不兼容时，新请求拒绝；旧快照只由其创建时已知的固定执行器处理，不增加跨版本兼容分支。

### 状态与配置边界

| 对象 | 权威所有者 | 编排模块的权限 |
| --- | --- | --- |
| 微信身份、固定路由、消息幂等与回送目标 | Chub/OpenClaw 集成 | 不读取、不修改 |
| Session、权限、Runtime 注册与任务受理 | Chub AI Runtime 公开用例 | 只消费核心给出的受限事实，不能选择或改写 |
| Worker 任务、租约、翻译 FIFO、确认队列与通知终态 | Quick Worker 和现有文本处理状态 | 只能通过计划请求既有固定流程 |
| 模块自身显示信息与非敏感策略配置 | 任务编排模块登记记录 | 仅供后续新请求读取，受固定大小和格式限制 |
| 计划版本与任务快照 | Chub 持久化任务状态 | 模块替换后不可回写 |

模块的专属设置只用于生成之后的新计划，不能保存账号、Token、Cookie、路径、收件人、Session 原生 ID 或未受限的请求正文。改变设置时不重算已持久化计划，也不影响正在执行、等待确认或等待目标可写的任务。

## 模块生命周期与切换

任务编排模块的包形态、协议版本、固定安装目录和预检规则需要在实际实现时单独补充；第一版不得直接复用 Runtime ZIP 的 `module_type: "runtime"`。无论最终是否复用模块管理基础设施，以下产品边界固定：

1. 安装候选模块前，核心层完成格式、版本、入口、计划模型和安全边界预检；无效候选不改变当前编排模块或现有任务。
2. 激活新模块后，只让它参与新的标准化请求。核心层记录激活结果与模块版本，但不把目录写入或进程启动当作完成。
3. 替换、停用或移除不要求取消已受理任务；这些任务继续按保存的计划快照完成、失败或明确等待。若固定执行器已无法识别旧快照，任务进入明确失败，不得用当前模块重新规划或重放。
4. 模块专属设置和模块自有缓存可以在替换或移除时按固定白名单清理；Chub 通用设置、Session、Worker 任务、通知记录、第三方数据和其他模块设置不在清理范围。
5. 设置页在实现前不展示导入、替换、移除或“已外置”状态。实现后只展示核心确认过的模块状态和最终操作结果，不在前端推断计划兼容性、任务快照或恢复完成条件。

## 接入与验收条件

任务编排外置只有在以下条件全部满足后，才可从“调研中”进入实现：

1. 明确第一版只覆盖的入口和策略范围，并同步当前能力清单；未覆盖的任务继续走当前固定实现，不做隐式迁移。
2. 定义模块清单、计划协议、兼容性规则、安装恢复和设置边界，且不改变已验收 Runtime ZIP 协议。
3. 实现核心对模块输入和计划输出的双向校验，覆盖非法动作、能力缺失、配置不兼容、超长输入、敏感字段和未知模块状态。
4. 证明模块替换不会改写已受理任务：至少覆盖直接执行、自动润色、确认队列、目标忙等待、Web 重启、Worker 重启、失败恢复和模块移除。
5. 验证微信固定指令、固定路由、确认语义、通知格式和失败关闭没有退化；真实微信收发仍由维护者在客户端完成验收。
6. 在至少一个真实平台完成模块安装、替换、停用、移除和恢复的最终状态验收；未验证的平台不得继承通过结论。

## 维护者操作

当前没有任务编排模块操作，也不需要在设置页导入任何文件。维护者继续使用现有“微信任务润色”配置管理当前行为；它的操作方式和用户可见效果以能力清单为准。

重新评审本设计时，先确认是否仍只覆盖微信普通正文任务。若要扩展到 Web 快速交互、自动化或其他入口，必须分别定义它们的请求规范化、权限、任务计划、失败边界和验收，不能把微信策略直接推广为全局编排。
