# Chub 外置模块功能设计

> 状态：待实现
> 主要读者：需要新增或维护 AI Runtime、任务编排能力的 AI Agent；维护人员用于确认统一接入范围和验收目标。
> 本文负责：定义 Chub 外置模块的整体目标、模块形态、动态加载边界、设置页展示目标和接入验收要求。
> 本文不负责：当前微信固定指令和用户可见回复格式（见[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md)第 4 节）、AI Session/Worker 的状态机与恢复细节，或多用户插件市场与零信任执行环境。
> 维护说明：本文是待实现目标。当前代码尚未采用外置模块机制；当前 Runtime 和微信任务润色的实际行为仍以《Chub AI Runtime 架构设计》和《Chub 集成能力清单》为准。

## AI 可执行契约

1. Chub 将 AI Runtime 与任务编排作为两类外置模块统一接入。模块是维护者可信的本机扩展，可被压缩、传输、存储和按需加载，但不是多用户插件市场、Codex Skill 或提示词文件。
2. **AI Runtime 模块**提供模型、Session 与任务执行能力；**任务编排模块**提供面向具体业务的配置、受理和结果规则，并声明可使用的 Runtime 能力。两类模块共用注册、版本、可用性和设置页展示规则，但不得混淆执行职责或状态所有权。
3. 模块只声明自身的稳定 ID、类型、版本、名称、入口、设置项和直接依赖。模块不拥有逻辑 AI Session、后台任务、Runtime 原生状态或通知终态；这些状态继续由既有的 Session Manager、Quick Worker、Runtime Adapter 和通知/业务入口分别拥有。
4. 模块压缩包可以从维护者选择的任意本机位置导入，但安装后的展开目录固定在项目内指定位置。Chub 只从该安装位置发现和加载模块；安装时只做基础清单、唯一 ID、兼容性和加载结果检查。单个模块损坏、缺失或不兼容时，只标记该模块不可用，不阻塞 Chub 本体或无关模块。
5. 个人工作站不默认要求签名、发布者认证、沙箱、逐项审批或复杂依赖解析。维护者直接安装的模块按当前设备用户权限运行；微信、OpenClaw 和其他外部入口不得借模块机制上传、安装、替换或执行模块，也不得因此扩大命令、路径、设备控制或敏感数据权限。

## 当前行为与目标边界

### 当前事实

当前生产只注册 Codex Runtime。设置页的 AI Runtime 分组动态列出已注册 Runtime；微信任务润色仍是固定设置入口，尚不是可枚举的任务编排模块。微信任务润色的处理模式、固定指令、通知和确认流程继续以《Chub 集成能力清单》第 4 节为唯一产品契约。

本设计不改变上述当前事实，也不授权在实现前把任何新 Runtime、任务能力或插件宣称为可用。

### 整体目标

将现有和后续的 AI Runtime、任务编排能力从 Chub 主体代码中抽离为可独立传输的外置模块，使维护者能够按需要从本机任意位置导入、安装、替换、停用和复用能力，而不必为每一项能力改动核心接入结构。

形成一套统一但轻量的模块注册和展示机制：Chub 识别模块类型、依赖和可用性，设置页在 AI Runtime 下动态展示实际已加载的 Runtime 与任务编排入口；快速交互和任务编排均通过受控的 Runtime 标识选择实际执行面，Worker 据此调用对应 Runtime，而不是固定绑定 Codex。

该机制服务于维护者授信的个人工作站。优先保证模块可携带、可加载、局部失败可恢复和最终状态可确认；不为假设性的多用户分发、供应链审计或极端并发引入影响日常可用性的重型门禁。

## 模块规范设计

外置模块不采用一份混合的业务清单。它由一个只承担发现与加载职责的通用模块外壳，以及 AI Runtime、任务编排两套独立规范组成。通用外壳不得承载模型、任务输入输出或业务配置等类型专有内容。

### 通用模块外壳

所有模块共用以下最小声明，用于安装、发现、加载和设置页枚举：稳定模块 ID、模块类别、显示名称、简要描述、模块版本、兼容的 Chub 版本范围和模块入口。模块 ID 全局唯一且一经发布不得复用；首期外置模块只允许 `runtime` 与 `orchestration` 两类，未知类别不得安装或注册。

首期模块包固定为 ZIP，包根目录使用唯一的 `chub-module.json` 清单，并通过清单声明固定的 Python 模块入口。运行代码只能经该入口加载，不根据压缩包名称、目录名称或页面名称猜测处理器。模块可在清单中声明依赖清单；安装时 Chub 自动使用项目 Python 环境执行 `pip install`，将依赖安装到该模块专属依赖目录后再加载。依赖安装、清单校验或模块加载任一失败时，此次安装失败且候选包不激活；候选包验证阶段可保留当前模块继续运行，但新版本激活后立即删除旧版本代码、依赖和关联 Chub 自有数据，不保留旧版本回退或兼容。模块外壳还允许声明可选的静态资源、提示词或模板位置，但不保存凭证、用户本机配置、任务快照或运行状态。加载后的可用性、加载错误和安装来源属于 Chub 注册表的运行时结果，不由模块自行宣称。

### 最小模块协议

`chub-module.json` 至少包含清单协议版本、稳定模块 ID、模块类别、显示名称、简要描述、模块版本、兼容的 Chub 版本范围和 Python 入口；可选包含依赖清单相对路径、静态资源位置和声明式设置项。清单协议版本用于拒绝无法识别的格式，不提供旧格式兼容读取。

Python 入口只导出模块注册对象：Runtime 模块导出符合当前 Adapter/Runner 与能力矩阵契约的 Runtime 注册对象；任务编排模块导出符合当前任务入口、Worker、通知和状态恢复契约的任务注册对象。入口不得直接创建 Web 路由、页面导航、外部命令或后台服务；Chub 根据注册对象完成固定入口绑定和设置页展示。

Runtime 注册对象除通用信息外声明 Runtime 标识、能力和可选的默认 Runtime 标记。首期只有一个 Runtime 时，该标记仅用于保留默认字段，不显示 Runtime 选择器；任务注册对象声明任务标识、固定支持入口、所需 Runtime 能力、设置项和业务处理器。当前首个任务入口为微信文本优化，后续入口必须先由 Chub 核心定义并登记，模块不得自行扩展入口类型。

### 首期实施契约与当前实现映射

首期不新建与现有 Runtime、Quick Worker 或微信处理链并列的执行协议。模块入口必须返回能够被当前共享契约、固定入口和状态 owner 直接消费的注册对象；现有 Codex Runtime 与微信任务润色先以适配方式接入，功能行为不因登记方式改变。

**Runtime 模块**必须直接构造当前 `app.ai_runtime` 的 Adapter 与 Worker Runner，复用 `RuntimeDescriptor`、`RuntimeRegistry`、`WorkerRuntimeRegistry` 和 `validate_runtime_wiring()`。Adapter 与 Runner 使用同一个 `runtime_id` 和能力声明；只要声明后台执行，必须满足当前 Worker 的最低后台能力和完整 Runner 契约。模块安装不能让客户端传入 Runtime 实现、命令、路径或环境，Worker 只接收已经由 Chub 解析的 Runtime 标识。

当前 Runtime 设置契约已支持文本、数值和带选项值、标题及简要描述的下拉字段，足以覆盖首期微信任务润色的处理方式、模型和推理等级。首期直接复用该声明式模型，不继续复制微信任务润色现有的专用前端选择器，也不让模块注入页面脚本；只有出现现有字段无法表达的真实设置时，才扩展共享契约。

**任务编排模块**首期以现有微信任务润色为基线注册固定的微信文本优化入口。现有 `WeixinTranslationManager` 继续负责润色、确认和等待目标可写等模块业务状态；OpenClaw 微信路由继续负责身份、固定指令和调用分流；Quick Worker 继续拥有实际 AI 任务、租约、取消、超时、恢复和最终状态。任务模块可以拥有这类受控的业务编排状态，但不得接管 Quick Worker 的通用任务队列、租约或终态。

微信任务润色模块的首期声明式设置映射为任务处理方式、文本优化模型和文本优化推理等级。模块读取和保存这些设置时继续使用当前模型目录校验与任务提交快照；迁移后设置页只通过任务模块注册对象读取这些字段，不再根据“微信任务润色”名称保留页面、路由或前端分支。

设置页改造以当前 Runtime 导航为基础：已注册 Runtime 已可由运行管理投影生成，而任务编排入口仍是固定页面。首期应将两类导航统一改为读取模块注册表，并由同一注册信息生成桌面和移动侧边栏、页面标题、说明、不可用原因和设置内容。模块安装后 Web 与 Worker 分别重建同一份注册表；Worker 保持独立健康，只在受理具体任务时按当前注册结果判断 Runtime 是否可执行。

### AI Runtime 规范

AI Runtime 规范描述“如何执行”。每个 Runtime 模块除通用外壳外，必须声明 Runtime 标识、可提供的执行能力、模型目录提供方式、配置项和 Runtime 适配入口；可选声明健康检查、实时终端、后台任务、只读执行、Session 映射和权限映射等能力。

Runtime 设置项必须说明名称、描述、取值类型、默认值或默认规则，以及修改后的生效范围。首期设置页由 Chub 依据声明式字段通用渲染；选项型字段同时声明选项值、标题和简要描述，并复用统一的模型、推理等级和权限选择样式。模块不提供独立前端页面、模板或 JavaScript。Runtime 模块必须复用当前 AI Runtime 的 Adapter/Runner、能力矩阵、统一 API、安全和状态所有权契约；其能力模型可按实际产品需求裁剪，但已声明能力必须完整满足当前项目对应的实现规范。该 Runtime 保存的模块专属设置属于模块升级还原范围。Runtime 模块不拥有逻辑 AI Session、Quick Worker 任务、租约或通知终态；这些状态继续由现有权威组件管理。

Runtime 对外提供的是能力声明，不是任意命令或路径的透传接口。上层任务只能依赖已声明能力，不能通过 Runtime 模块请求未声明的 Runner、工作目录或设备能力。

### 任务编排规范

任务编排规范描述“完成什么业务”。每个任务模块除通用外壳外，必须声明任务标识、任务说明、支持入口、输入约束、用户可见结果、设置项、业务处理入口和所需 Runtime 能力。

任务模块的 Runtime 依赖以能力表达，而不是直接依赖某个 Runtime 名称；注册表在实际可用的 Runtime 中解析候选项。任务模块设置在候选项中选择一个实际执行 Runtime，并在受理前校验其满足所需能力；Worker 只使用已经确认的 Runtime 标识调用对应执行面，不自行选择或切换 Runtime。

任务设置项必须携带名称、简要描述、取值类型、默认规则和生效范围，供设置页完整展示。首期只使用 Chub 通用的声明式控件，模块不提供独立前端页面、模板或 JavaScript。该任务模块保存的模块专属设置属于模块升级还原范围。任务模块负责自身业务输入的校验、派生任务的构造和结果解释；必须遵循当前 Quick Worker、通知、外部入口和状态恢复契约。模块可以保存受控的业务编排状态，例如微信文本优化的确认队列；不得接管外部入口身份校验、Quick Worker 的通用任务队列、租约、任务终态、通知投递或已受理任务的恢复规则。

### 首轮接入边界

首轮先将现有 Codex Runtime 和微信任务润色映射为上述两套内部注册对象，用它们验证字段、依赖解析、设置页展示和不可用结果是否足够。首轮不提供多 Runtime 的 Session 选择或跨 Runtime Session 迁移：Codex 是当前唯一默认 Runtime，停用后快速交互不能提交任务；默认字段只为后续扩展保留。压缩包导入在注册模型稳定后接入，不引入新的 Worker 服务。

### 模块形态与加载

外部模块只以 ZIP 形式安装。维护者可从任意本机位置选择 ZIP 并调用 Chub 安装流程；Chub 将其解压、安装到项目内固定模块目录，再从该目录扫描和加载。模块目录至少包含可读取的清单，并可包含执行代码、静态资源、提示词、模板和模块配置定义；凭证、用户本机配置、任务快照和运行状态不随模块包保存。任意本机目录不是直接加载来源，只是 ZIP 的存放位置。

压缩包安装完成后，Chub 立即扫描固定安装位置并刷新 Web 与 Worker 使用的模块注册表；Chub 或 Worker 进程重启时也立即执行同一扫描。清单无效、模块 ID 重复、类别未知、版本不兼容或加载失败时，注册表保留可诊断的不可用结果；其他已加载模块继续工作。

模块安装、替换、移除或不兼容升级属于外置模块的升级还原边界，不承诺已受理任务或旧运行态兼容。新版本激活或模块移除后，Chub 清理目标模块的自有 Session 映射、任务、队列、租约、缓存、运行状态和模块专属设置，再由新模块重新初始化；不保留双读、双写、旧模块回退或跨版本恢复逻辑。首次安装没有目标模块数据时不执行清理。Chub 通用设置、其他模块设置、第三方原生数据和明确要求保留的数据不在此清理范围。

### Runtime 与任务编排绑定

Runtime 模块声明可供上层使用的能力，例如模型目录、后台任务、只读执行、权限映射、Session 映射或实时终端。首期快速交互不展示 Runtime 选择器，创建和提交均使用当前唯一默认 Runtime；该 Runtime 不可用或停用时，快速交互不能提交任务。Runtime 注册对象保留默认标记字段，为后续多个 Runtime 的受控 Session 选择设计准备，但不在本期启用。任务编排模块声明支持入口、设置项、业务处理器和所需 Runtime 能力，并由模块设置指定实际 Runtime。后端注册表负责确认该 Runtime 满足全部直接依赖。

任务模块只能绑定 Chub 已定义的入口类型，例如微信文本优化；模块安装后不得自行新增任意 Web API、导航、外部指令或路由。移除 Runtime 不级联清理、停用或重新配置依赖它的任务模块，也不主动向这些模块发起额外请求；任务仍可按原入口受理至 Worker，Worker 在提交时发现实际 Runtime 不可用或依赖不满足后返回失败。普通产品入口不能由请求正文临时指定 Runner、命令、工作目录或未安装模块。不得自动切换 Runtime，也不得将局部故障扩散为 Chub 全局不可用。

首个迁移目标是将现有 Codex Runtime 与微信任务润色分别适配为 Runtime 模块和任务编排模块。迁移不改变既有 API、微信用户可见行为、安全权限、队列和通知边界，也不引入跨 Runtime Session 迁移或新的后台服务；模块升级时的关联运行态按本设计的升级还原规则重新初始化。

### 设置页目标

设置页在 AI Runtime 下按注册表动态展示模块管理入口、已注册的 AI Runtime 列表和已注册的任务编排列表。模块管理入口提供本机 ZIP 的导入、替换、移除和安装状态查看；替换或移除前必须说明将清理的模块专属设置和关联 Chub 运行态，并使用确认弹窗。Codex Runtime、微信任务润色等条目均由实际注册信息生成，不保留按名称硬编码的页面分支。

每个 Runtime 或任务模块在对应列表中拥有设置入口。页面使用模块声明的名称、描述和设置项渲染实际配置内容；模块自行确认需要配置的字段、选项和默认规则，Chub 负责统一控件、保存校验和不可用状态展示。Runtime 缺失或依赖不满足时，任务模块继续保留在列表中并展示明确的不可用原因，不触发额外的任务模块清理或配置请求。微信任务润色完成迁移后成为第一个任务编排模块。

## 状态、恢复与外部边界

- 单次任务在受理时保存已经解析的 Runtime 和模块配置，用于该次执行的幂等查询与结果归属；模块安装、替换、移除或不兼容升级触发升级还原时，关联 Chub 自有任务和运行态可被统一清理，不承诺继续执行、恢复或重放。
- Runtime 停用、健康异常或模块依赖不足时，只拒绝直接受影响的新提交；无关 Runtime、只读能力、维护入口和独立服务继续可用。Worker 的健康状态与某个 Runtime 是否可用相互独立。
- 外置模块不放宽真实 loopback/Tailnet 来源校验、固定 OpenClaw 路由、输入限长、敏感信息保护和失败关闭要求。模块接入不改变微信等外部通道的既有安全边界。
- 模块协议、ID、依赖或持久化格式出现不兼容变化时，按模块升级还原边界清理关联 Chub 自有运行态和模块专属设置并初始化新格式；Chub 通用设置、其他模块设置、第三方原生数据和明确要求保留的数据不在此范围。

## 分步实施计划

以下步骤按顺序执行。每一步只在前一步验收通过后开始；首期只覆盖 AI Runtime 外置化，任务编排模块在 Runtime 完整验收后另行启动。

### 第一步：Runtime 模块注册基线

**目标**：在不引入 ZIP 安装的前提下，建立只支持 `runtime` 类型的模块注册对象和注册表，并将当前 Codex Runtime 作为内置注册模块接入。Web、AI Session Manager 与 Quick Worker 从同一 Runtime 注册来源取得 Codex Adapter、Runner、名称、能力和默认标记，快速交互仍固定使用唯一默认 Runtime。

**验收标准**：

- Codex Runtime 的 Adapter、Runner、能力矩阵和 `runtime_id` 继续通过当前共享契约校验。
- 首页、设置页、快速交互、Worker 和微信现有入口的用户可见行为不变，未出现 Runtime 选择器。
- Web 与 Worker 都只识别当前 Codex Runtime；未知 Runtime 或缺失能力在提交前按现有规则失败，不影响 Worker 健康。
- 回归覆盖重复注册、描述漂移、Adapter/Runner 不一致、能力虚假声明和 Codex 既有任务执行。

### 第二步：Runtime 设置与导航注册化

**目标**：将设置页 AI Runtime 下的 Runtime 导航、标题、说明、设置入口和不可用状态统一改为 Runtime 注册信息驱动。继续复用当前声明式设置字段和通用控件；Codex 无专属设置时按其声明展示，不人为增加配置页内容。

**验收标准**：

- 桌面和移动设置侧边栏均从 Runtime 注册表生成当前 Codex 条目，不再依赖 Codex 名称判断。
- Runtime 设置读取、保存、启停和不可用反馈继续遵循当前 API、操作日志和权限校验。
- 下拉选项完整展示标题和简要描述，模型、推理等级和权限使用统一样式。
- 设置页完成桌面和手机浏览器回归，现有 Codex 设置与通用设置无回归。

### 第三步：ZIP 安装与 Runtime 激活

**目标**：实现 Runtime 模块 ZIP 的导入、解压到项目内固定目录、依赖自动安装、清单/入口校验、模块操作记录以及 Web 与 Worker 注册表刷新。首期安装流程只接受 `runtime` 类型，不处理任务编排 ZIP。

**验收标准**：

- 有效 ZIP 在依赖安装、模块加载和 Web/Worker 注册确认全部成功后才激活；安装结果具有 `requested`、`started`、`succeeded` 或 `failed` 最终记录。
- 清单损坏、未知类别、重复 ID、依赖安装失败、入口加载失败或兼容性不足时，候选包不激活，失败原因可在模块管理入口查看。
- 运行中替换成功后只保留新版本；关联 Chub 自有运行态和模块专属设置按升级还原边界清理。首次安装不清理既有无关数据。
- Web 与 Worker 都确认读取新注册表；Worker 保持健康，Runtime 不可执行时只在对应任务提交时失败。

### 第四步：Codex Runtime 外置迁移

**目标**：将当前 Codex Runtime 打包为首个 Runtime ZIP 模块，并由第三步的安装与加载流程提供其 Adapter、Runner、能力和运行设置。移除主项目中仅为固定注册 Codex 而存在的装配分支，但不改变 Codex 私有执行逻辑和既有产品入口。

**验收标准**：

- 安装后的 Codex Runtime 成为唯一默认 Runtime，快速交互、实时终端、后台任务、模型目录、权限映射和用量读取继续按现有能力工作。
- Worker 能按已确认的 `runtime_id=codex` 找到外置 Runner，并完成正常结果、上游错误、取消、超时和最终状态处理。
- 设置页显示外置 Codex Runtime 的真实名称、健康状态、启停状态和声明式设置；停用后只拒绝后续新任务。
- 现有 API、微信固定指令、通知、Session 单 writer、Worker 恢复和 macOS/Ubuntu 服务边界无回归。

### 第五步：Runtime 外置化验收与任务编排准备

**目标**：完成 Runtime 外置化的端到端验收，并冻结 Runtime 模块协议。通过后才开始将微信任务润色迁移为首个任务编排模块；任务模块复用已验收的 ZIP、注册表、设置页和 Runtime 绑定能力，不重新设计安装机制。

**验收标准**：

- 模块导入、替换、移除、依赖失败、Runtime 不可用、Web/Worker 刷新和升级还原均有明确最终结果。
- Codex 外置 Runtime 在实际页面完成快速交互、设置页和服务恢复验收；微信相关行为由维护者在真实微信客户端确认。
- 设计文档、能力清单、安装说明和自动化测试与最终 Runtime 契约一致；未实现的任务编排外置化仍标记为后续范围。

## 接入与验收目标

新增或迁移模块前，实施者必须确认模块类别、稳定 ID、支持入口、直接依赖、状态所有权、不支持范围和用户可见结果。

- Runtime 与任务编排模块能够被注册表唯一识别，并能从固定位置独立加载；单个模块的清单或加载失败不会影响 Chub 或其他模块。
- 声明依赖的模块在安装时自动完成依赖安装；只有依赖安装、模块加载和注册确认都成功后才激活新模块。替换失败时，既有可用模块继续可用。
- 设置页 AI Runtime 分组能完成模块 ZIP 的导入、替换、移除和状态查看；Runtime 与任务编排条目及其设置入口完全依据注册信息生成。
- 设置页只展示已注册模块，并能正确反映 Runtime 启停、健康状态和任务依赖结果；模块声明的描述和设置项完整展示。
- Runtime 不可用或任务模块依赖不满足时，Worker 只拒绝对应提交，仍保持自身就绪；无关 Runtime 和功能继续可用。
- 模块安装、替换、移除或不兼容升级会清理关联 Chub 自有运行态和模块专属设置，并以重新初始化后的新模块为准；不承诺旧任务、旧队列、旧设置或旧模块版本恢复。
- Codex Runtime 与微信任务润色迁移后，现有 API、页面、微信固定指令、队列、通知和权限行为无回归；多 Runtime 支持时，快速交互和任务提交均使用已确认的 Runtime 标识执行。
- 外置模块不得绕过当前项目的 Runtime、Worker、Session、安全、通知和外部入口契约，也不得安装新的任意 API、导航或外部指令。
- 自动化测试覆盖注册、依赖、配置、不可用和既有业务回归；设置页完成桌面与手机浏览器回归。涉及微信用户行为、路由或通知变化时，由维护者在真实微信客户端完成验收。

## 维护者操作

当前无需操作，外置模块尚未实现。实施时先确认目标模块是否已有权威产品文档：微信任务润色的用户可见行为继续维护在《Chub 集成能力清单》，Worker 执行与恢复继续维护在《Chub Quick Worker 独立服务设计》，Runtime 适配细节继续维护在《Chub AI Runtime 架构设计》。
