# Chub 正式部署包与安装设计

> 状态：已验收
> 主要读者：需要构建、部署或验收 Chub 新设备实例的 AI Agent；维护人员用于决定部署范围和完成最终验收。
> 本文负责：Chub 正式部署包的构建内容、内含正式插件包、目标设备安装流程、可选 OpenClaw 接入、状态隔离和验收边界。
> 本文不负责：已部署实例的升级与恢复、Runtime 或任务编排插件的 ZIP 协议、OpenClaw/微信业务路由或账号配置；这些内容由对应专项设计维护。

## AI 可执行契约

1. 正式部署包是从**当前工作区的最新受控源码**构建的 Chub 发布物，不是当前设备目录、磁盘镜像或运行态备份。构建只能使用固定包含与排除清单，页面和外部入口不得提供任意源路径、输出路径或 ZIP 内容。
2. 构建先使用维护页保存的发布配置生成当前 Codex Runtime 和微信任务编排的正式 ZIP，分别验证后再写入 Chub 主 ZIP。任一扩展产物无法构建或摘要无法确认时，主包不得生成成功结果。
3. 主包只随包交付插件 ZIP；新设备安装 Chub 不自动导入、不自动启用 Runtime 或微信任务编排插件。目标设备必须在 Chub 可用后，通过各自现有的受控设置入口显式导入和选择。
4. 包内不得包含来源设备的本机配置、账号、Token、Cookie、浏览器 Profile、Session、任务、运行锁、日志、缓存、构建环境或第三方运行态。目标设备必须重新创建本机配置并完成外部账号授权。
5. Chub 核心部署与 OpenClaw 安装是独立结果。部署 AI 可以在维护者选择后执行固定的 OpenClaw 安装和检查，但 OpenClaw 未安装、配置失败或通道未验收不得使 Chub 核心部署失败，也不得自动清理已成功部署的 Chub。
6. 包内 `DEPLOY_WITH_AI.md` 是目标设备 AI 的唯一部署操作入口：它必须先完成 Chub 核心安装和健康确认；仅在维护者选择后继续 Runtime/任务编排插件导入或 OpenClaw 接入。涉及凭据、账号、微信绑定或真实微信收发时停止并交给维护者。

## 发布物与构建边界

### 正式部署包

构建产物命名为 `chub-release-<版本>-<构建标识>.zip`，固定写入 `data/local/artifacts/releases/`。每个包包含：

- Chub 主程序、页面资源、固定脚本、示例配置、依赖声明和目标设备安装所需服务定义；
- 受控的项目文档及包内 `DEPLOY_WITH_AI.md`；
- 当前构建出的 Codex Runtime 正式 ZIP 与微信任务编排正式 ZIP；
- 发布清单：Chub 版本、构建标识、构建时间、每个内含扩展的版本/标识和 SHA-256，以及每个文件的受控清单与摘要。

构建不复制 `.venv`、`node_modules`、`.git`、本机 `config/*.local.yaml`、`data/local/`、日志、测试缓存、Python 缓存、临时文件或既有发布物。Chub OpenClaw 插件的仓库源码、构建说明和已验证补丁清单可随主程序交付；OpenClaw 本体、其运行目录、账号、配置和依赖不属于 Chub 发布包。插件模块开发源码是否随包由本次发布配置决定；无论是否包含源码，两个正式插件模块 ZIP 都必须随包交付。

发布包使用临时文件完成构建，所有内含扩展和发布清单校验通过后原子发布。生成按钮只创建当前构建产物并展示最终清单、大小和摘要；它不重启 Web/Worker、不修改当前 Runtime 默认实现、不导入扩展，也不影响已受理任务。

发布物只保留在固定输出目录，Chub 不自动删除、轮转或限制既有正式包；维护者按本机磁盘情况自行清理不再需要的发布物。清理发布物不影响已部署节点、已导入模块或正在运行的服务。

### 扩展产物

Codex Runtime 与微信任务编排插件继续遵循各自现有 ZIP 协议、版本标识、内容摘要、导入/覆盖和任务快照规则。部署包只负责将同次构建产生的正式 ZIP 放到固定的 `bundled-modules/` 目录；不能以此绕过插件预检、Web/Worker 双端注册、活动实现选择或插件删除保护。

构建完成后，发布清单中的摘要是目标设备导入前核对交付物一致性的依据；它不替代目标设备导入操作的最终注册确认。

## 发布配置与页面操作

“维护与版本”页新增“正式部署包”卡片，读取并保存本机发布配置。卡片首先展示当前 Chub 应用版本、当前 Runtime 正式版本/槽位和当前微信任务编排正式版本；随后提供本次构建使用的三个版本设置：

- **Chub 发布版本**：用于本次主部署包名称和发布清单。页面同时保留只读的“当前应用版本”，不把尚未构建的发布版本误报为当前运行版本。
- **AI Runtime 正式版本**：用于构建随包 Runtime ZIP。Codex 正式槽位标识由后端固定管理，Runtime 描述统一使用当前项目的主要 AI 能力说明，不在页面单独配置。
- **微信任务正式版本**：用于构建随包微信任务编排 ZIP。

版本设置读取失败时不允许构建；保存成功只表示下一次打包将使用这些值，不修改当前运行 Chub、当前默认 Runtime、已导入模块、已绑定 Session 或已受理任务。点击“生成”时必须冻结本次构建的配置；构建期间后续保存只影响下一次生成。页面不得接受任意输出路径、模块路径、命令或构建参数。

卡片提供“包含插件模块开发源码”开关，默认关闭。关闭时，主包不包含 `runtime-modules/` 与 `orchestration-modules/` 的开发源码，只提供两个正式插件 ZIP；目标设备可先部署 Chub 核心，再按需导入。开启时，主包额外包含当前受控开发源码，供维护者在目标设备使用现有开发实现和刷新流程；它不自动导入或启用正式插件 ZIP，也不复制来源设备的模块安装状态。

点击“生成正式部署包”后，Web 只登记后台固定构建脚本。脚本在受限临时目录完成主包、两个扩展包和清单校验，再原子写入 `data/local/artifacts/releases/`；页面轮询操作终态，确认成功后展示产物名称、大小和固定本地输出目录，完整文件摘要保存在包内发布清单。构建不在 HTTP 请求中同步执行，不重启 Web/Worker，也不影响已受理任务。

同一时刻只允许一个正式部署包构建操作。已有构建处于 `requested` 或 `started` 时，新的生成请求明确返回当前构建状态；它不创建第二个并行构建，也不阻止无关的只读、任务执行或第三方服务能力。构建运行依附当前 Web 实例；若服务重启或进程结束导致其无法继续，下一实例必须将该操作记录为失败并允许重新生成，不能长期显示为“构建中”。

## 目标设备部署

### Chub 核心部署

目标设备解压正式包后，按 `DEPLOY_WITH_AI.md` 执行固定流程：

1. 检查支持的平台、Python 版本和基础命令；当前支持 macOS LaunchAgent 与 Ubuntu systemd user service。
2. 创建新的 Python 环境并通过正常网络安装声明的依赖。
3. 从示例创建 `config/settings.local.yaml`，由维护者填写新设备节点、可信网络和可选服务配置。
4. 安装 Chub Web、Quick Worker 及固定服务定义，随后确认 Web 和 Worker 的健康状态。

Web 健康、Quick Worker 健康和服务安装后的可恢复状态都已确认，才表示 Chub 核心部署成功。仅解压、依赖安装完成、服务进程创建或 HTTP 200 均不单独表示部署成功。

### 可选扩展导入

核心部署成功后，维护者可从设置页选择包内的正式 Runtime ZIP 与微信任务编排 ZIP 导入，再按现有页面规则启用或选择。未导入任一扩展不影响 Chub 核心运行；导入失败只按该扩展的恢复边界收敛，不回滚 Chub 核心部署。部署包未包含开发源码时，目标设备不提供 `builtin-dev` 或微信开发实现；这不是核心部署故障，维护者可导入随包正式 ZIP 后继续使用对应能力。

### 可选 OpenClaw 接入

`DEPLOY_WITH_AI.md` 必须提供“跳过 OpenClaw”和“安装/接入 OpenClaw”两条明确路径，默认先完成 Chub 核心部署。选择 OpenClaw 后，AI 只能按仓库登记的兼容基线安装第三方依赖、构建并部署 Chub 插件、完成固定配置检查和 Gateway 健康检查；不得猜测第三方版本、安装位置、微信账号、Owner 或凭据。

OpenClaw 接入的成功条件独立于 Chub：插件加载、Gateway 就绪、已配置通道及兼容基线确认后，才可报告该子项成功。真实微信文字、语音、点击和收件仍只能由维护者本人在客户端完成。未选择、无法安装或未完成 OpenClaw 配置时，Chub 应继续显示其为未配置/不可用，而不是将整个节点判为异常。

## 页面与操作边界

“维护与版本”页面新增正式部署包生成入口时，只允许可信来源调用固定构建动作。页面显示最近一次成功构建的版本、构建标识、时间、大小、内含扩展、摘要和固定输出目录；不提供 Web 下载或文件浏览能力，也不得接受任意本机路径。

构建操作记录 `requested`、`started`、`succeeded` 或 `failed`。生成请求被受理不代表产物可用；只有 ZIP、内含扩展和发布清单均完成校验后才显示成功产物信息。构建失败保留最近一次成功包，不阻止无关的状态查看、Quick Worker、OpenClaw 或已受理任务。

## 与升级和恢复的关系

正式部署包用于新设备或全新目录的安装，不替代现有设备上的“升级与恢复”。升级与恢复仍只处理 Chub 自有 AI 运行态、Web 与 Quick Worker，且不复制、覆盖或迁移用户配置、OpenClaw、浏览器、原生 Runtime 数据或第三方账号。

目标设备从部署包首次安装后，后续维护继续使用既有 `chub` 服务管理、Web 重启、Worker 恢复、Runtime 插件维护和 OpenClaw 重启与恢复流程。不得用重新解压部署包替代已部署节点的受控升级恢复。

## 验收范围与复检

实现后至少验证：

- 构建包包含主程序、发布清单和两个可独立校验的正式插件 ZIP；
- 维护页正确展示当前版本，保存的 Chub、Runtime 和微信任务发布版本只影响下一次构建；
- 开发源码开关分别覆盖“未包含开发源码但可部署并导入正式 ZIP”和“包含开发源码且可使用现有开发流程”；
- 本机配置、凭据、运行态、日志、缓存和依赖目录不在包内；
- 在新目录完成 Chub 核心安装后，Web、Worker 和服务恢复均可确认；
- Runtime 与微信编排 ZIP 可由设置页分别导入，且未导入时不影响核心部署；
- 跳过 OpenClaw 的部署成功，及选择 OpenClaw 后其失败不影响已完成的 Chub 核心部署；
- 构建失败、摘要不一致和单个扩展构建失败均不会产生半成品成功结果或泄露路径/敏感信息。

当前已实现发布配置页面、后台单任务构建、固定本地输出目录、随包两个正式插件 ZIP 和包内 AI 部署说明；尚未完成目标设备的 macOS 或 Ubuntu 实机部署验收，也不宣称 OpenClaw 安装或真实微信链路已随此能力验收。**当前冻结该跨设备实机验收项**：正式包构建、内容和本机安装边界保持当前结论，不将新设备部署或 OpenClaw 接入扩展为当前开发范围。只有维护者重新启动新设备交付时，才恢复该验收，并完成至少一台目标 macOS 或 Ubuntu 设备上的核心部署、服务恢复和按需插件导入验证。以下变化必须重新验收：发布物包含/排除边界、版本配置语义、模块 ZIP 协议或版本绑定、目标设备服务安装、OpenClaw 兼容基线、页面构建授权、部署成功口径，或任何凭据/运行态迁移规则。
