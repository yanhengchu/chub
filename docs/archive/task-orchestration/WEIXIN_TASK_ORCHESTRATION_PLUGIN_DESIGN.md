# Chub 微信任务编排插件模块设计

状态：已归档

主要读者：AI Agent；维护者通过与 AI Agent 协作理解规则。

本文负责：记录旧微信专属润色编排能力的退役边界。

本文不负责：新的通用阶段协议、Web/微信入口适配、Worker 任务模型或未来微信润色设计。

## AI 可执行契约

1. `weixin-orchestration`、`weixin-refinement` 及其开发实现不再被发现、加载、导入、启用或执行。
2. 退役清理只执行一次并记录完成标记：只读检查旧微信编排请求、确认队列、阶段子任务和回调结构后再直接清除；不迁移、不双读、不双写、不重放。旧状态异常时只隔离该清理与微信能力，不得阻断 Web、Worker 或其他入口启动。
3. `text` / `text-check` 在新的通用阶段实现完成前明确拒绝，不能静默降级为普通任务。
4. 普通微信任务仍由入口适配器负责认证、消息去重、固定指令解析、目标 Session 选择和原路回送；手动物理任务提交统一经过通用任务编排分发器的空阶段链。
5. 后续微信润色必须按新的通用阶段协议重新设计，不得恢复本文旧模型、配置、确认队列或能力宿主。

## 当前行为与边界

当前不提供微信润色。普通微信任务使用统一分发器空阶段链并只提交一次物理主任务；自动化、周报等非交互入口可继续使用各自的直接提交路径。用户只看到原入口的提交结果和最终任务结果，不看到通用编排内部状态。

微信路由、消息去重、确认交互和回送状态属于微信入口适配器；Web 时间线属于 Web 入口适配器；这些信息不得进入通用编排请求模型或 Quick Worker 任务模型。

## 维护者操作

旧插件没有安装、启用或恢复操作。需要新增微信润色时，先按[任务编排插件模块架构设计](CHUB_TASK_ORCHESTRATION_PLUGIN_DESIGN.md)和新的入口专项设计建立测试和验收范围。

## 验收范围与复检

截至 2026 年 9 月 21 日，已验证旧状态清除、旧设置入口移除、通用分发器空阶段链和 Web 幂等测试。真实微信收发仍需由维护者本人在微信客户端验收；Ubuntu 平台和新的微信润色阶段未验证。

以下变化必须重新验收：通用分发器状态所有权、阶段链协议、微信入口认证/路由/去重、Quick Worker 终态、结果回送或未来微信润色协议。
