# Chub 可维护性整理任务

> 状态：已验收。本文记录本轮可维护性整理任务、依赖顺序和验收结果；不改变现有产品范围，也不以文件行数作为完成目标。

## 1. 总目标

在保持现有页面、接口、状态文件、插件协议、安全边界和跨平台行为不变的前提下：

- 为关键响应式页面建立可重复的真实浏览器回归；
- 让 AI 额度请求、缓存和清理只有一个明确所有者；
- 降低微信 Chub 调度服务中纯逻辑与状态协调混杂带来的修改风险；
- 逐步缩小快速交互页面单文件承担的职责；
- 保持 Quick Worker、CSS 层叠和已验收运行链路稳定。

以下结论作为本轮任务基线：

- 首页额度响应式展示已经维护者验收通过；
- Quick Worker 当前稳定，不纳入本轮结构调整；
- macOS API Key 额度采集按真实需要另行复验，不作为本轮门禁；
- 不引入前端框架、ES Modules、打包器、数据库、任务队列或新的服务进程。

M1–M2、M3–M4 和 M1–M5 是三条独立工作链，不互相制造虚假依赖。默认仍按 M1、M2、M3、M4 的顺序推进；M4 完成评估后再决定是否立即启动 M5。

每次只实施一个任务。任务完成后先记录实际验收结果，再开始下一项；不得把多个状态所有权改动合并成一次大范围重构。执行顺序可以根据真实需求调整，但不能跳过同一工作链内的技术依赖。

任务开始前记录当时的工作区状态和任务相关文件基线。验收只判断本任务新增的差异，不要求清理、覆盖或归入其他并行任务已经存在的改动。

## 3. 共同验收原则

所有任务共同满足以下要求：

- 不改变公开 API、统一响应、认证方式、状态文件格式、插件协议和消息路由。
- 不减少已有自动化用例；测试拆分前后收集到的原有用例必须一一保留。
- 不读取或写入真实 Token、本机配置、运行日志和用户业务数据。
- 页面继续使用 `textContent` 或 DOM API 渲染外部内容，不放宽 CSP。
- 首页脚本、公共样式和快速交互脚本的固定加载顺序保持可测试。
- Python 全量测试、OpenClaw 插件测试、`git diff --check` 均通过。
- 涉及页面结构或样式时完成 Standard、Cyber、桌面、平板和手机浏览器回归。
- 涉及微信指令、路由或回复格式时，由维护者本人完成真实微信验收；后台记录不能代替客户端实际收发结果。
- 无法验证的平台或真实链路必须在验收结果中明确记录，不能默认视为通过。

## 4. M1：浏览器回归基线

### 目标

把已验收的额度响应式规则固化为可重复执行的浏览器测试，为后续前端职责调整提供行为基线。

### 实施范围

- 建立隔离的本地测试服务，加载正式 Jinja 页面、正式 JavaScript 和正式 CSS；只模拟受保护 API 响应，不连接当前运行的 Chub 服务或真实上游账号。
- 测试夹具不得复制额度 DOM 结构、渲染函数、响应式选择器或换行规则，避免形成独立于生产页面的测试实现。
- 覆盖完整额度与账号简版两种数据形态。
- 固定覆盖 `390×844` 手机、`720×1024` 平板宽屏单列和 `1280×900` 电脑双列，并使用 `420×900`、`421×900` 视口验证手机规则边界。
- 覆盖 Standard 与 Cyber 两套风格。
- 同步 AI 额度设计文档中的响应式展示规则。

### 验收标准

- 完整额度在手机依次显示 `Weekly / Today / Resets` 三行，平板宽屏单列一行，电脑双列两行。
- 账号简版在手机显示 `Weekly · Today tokens / Resets` 两行，平板和电脑在空间足够时一行。
- `420×900` 仍应用手机专用 Resets 换行，`421×900` 不再应用该手机专用规则；两侧都不得因自然换行出现截断或溢出。
- 所有组合的 Weekly、Limit、Today、Token 和 Resets 文本完整，无横向溢出、遮挡和异常高度跳动。
- 测试同时验证对应数据片段位于预期行，而不只检查 CSS 或脚本中是否存在某个字符串。
- 测试通过生产页面行为判断结果，不允许以测试夹具中的重复规则直接计算预期布局。
- 浏览器测试失败时返回明确的主题、数据形态和视口信息。
- 现有全量测试保持通过，测试过程不写入真实配置、缓存或运行状态。

### 预期验收结果

形成一套可在后续前端调整中重复执行的额度布局矩阵；实际执行命令、通过数量、浏览器版本和未验证平台在完成时记录。

**实际验收结果：已完成（2026-08-15）。**

- 已建立显式启用的真实 Chrome 回归测试，临时启动隔离 Chub 应用并加载正式 Jinja、JavaScript 和 CSS；只拦截受保护 API，不访问当前运行实例或真实上游账号。
- 测试使用独立临时浏览器上下文，不写入受管 Chrome Profile 的 Cookie、Local Storage 或 Session Storage。
- Standard/Cyber、完整额度/账号简版（含本机 Token 标记）以及五个固定视口共 30 个组合全部通过；逐项验证文本、数据片段所在行、单片段完整性、额度区域和整页横向溢出。
- `420×900` 与 `421×900` 边界行为符合预期，现有页面展示和交互未调整。
- 执行命令：`CHUB_BROWSER_TESTS=1 .venv/bin/python -m pytest tests/test_web_quota_browser.py`。
- M2 完成时再次执行同一矩阵，30 个组合保持通过；最终全量数量记录在 M2 实际验收结果中。
- 实测环境：Ubuntu 24.04、Python 3.12.3、Google Chrome 150.0.7871.46（headless）。本轮未在 macOS 实机重复执行该布局矩阵；Windows 不属于 Chub 当前支持平台。

## 5. M2：AI 额度前端职责归一

### 目标

消除 Codex 卡片通过主题模块获取业务数据的反向依赖，让额度请求、共享缓存、并发刷新和退出清理由 Core 统一管理。

### 实施范围

- 建立单一的前端 AI 额度数据入口，负责请求、缓存、并发合并、强制刷新和清理。
- Codex 卡片只负责额度文本与响应式结构渲染。
- Theme 只消费额度快照并负责 Cyber 代码雨，不拥有业务请求和缓存。
- 保留现有服务端 `/api/ai/usage`、五分钟缓存、认证头和失败关闭语义。
- 保持现有非敏感浏览器缓存键兼容，避免升级后出现旧数据残留或重复请求。

### 验收标准

- 同一页面同时需要 Codex 额度和 Cyber 代码雨时，只触发一次等价额度加载，并共享同一结果。
- 手动刷新仍会强制刷新额度；并发刷新继续合并，不出现旧请求覆盖新结果。
- 未认证、退出、认证失效和缓存读取失败时，Codex 与代码雨均清除额度，不显示旧浏览器数据。
- Standard 不创建代码雨，Cyber 的 Weekly/Today 动态内容、减少动态效果和可见性恢复行为不变。
- M1 浏览器矩阵、现有 Cyber 代码雨测试、首页脚本顺序测试和全量测试通过。

### 预期验收结果

额度业务数据只有一个前端所有者；Theme 与 Codex 成为独立消费者，用户可见展示和刷新体验保持不变。

**实际验收结果：已完成（2026-08-15）。**

- 已建立跨公共页面加载的统一 AI Usage Core，独立负责浏览器端请求、五分钟缓存、并发合并、强制刷新、认证失效和退出清理；沿用原缓存键，无需迁移。
- Codex 卡片只消费共享快照并渲染文本和响应式结构；Theme 只订阅快照生成 Cyber 代码雨，不再拥有额度接口、认证头或缓存。
- 同页 Codex 与 Cyber 首次加载经真实浏览器验证只发送一个普通额度请求；多个强制刷新合并，普通请求期间触发刷新会在其结束后只补发一次强制请求，已清理的旧请求不能回写页面。
- 缓存损坏、浏览器存储不可用、认证失效和退出清理均有独立行为测试；清理会同步移除 Codex 与代码雨中的旧额度。
- 用户可见额度文案、手动刷新、Standard/Cyber 视觉及 M1 响应式分行规则保持不变。
- 验证结果：额度 Core、Cyber、Web 资源/加载顺序和服务端额度相关测试通过；M1 的 30 组合真实 Chrome 矩阵通过；Python 全量测试 `879 passed, 30 skipped`，其中跳过项即需显式启用的浏览器矩阵；OpenClaw 插件测试 `34 passed`。

## 7. M4：微信调度纯逻辑边界拆分

### 目标

让微信 Chub 模式 Manager 聚焦调度、锁、幂等、状态提交和外部协作，把可独立验证的模型、指令解析和消息格式化移出单一服务文件。

### 实施范围

- 抽离持久化模型、公开结果模型和固定状态常量，保持 JSON 字段与兼容语义不变。
- 抽离无状态的指令识别、编号解析、正文拆分和标点清理。
- 抽离无状态的 Chub 状态、Session 列表、操作结果和额度消息格式化。
- Manager 继续统一持有状态锁、Session 槽位写入、提交幂等、重启协调、通知发送和操作日志。
- 不在本任务中拆分 Quick Worker、改变插件协议或重新设计微信权限边界。

### 验收标准

- 相同输入得到与调整前一致的 disposition、HTTP 状态、业务 code、回复文本和持久化业务字段；时间戳、随机操作 ID 等非确定值只比较格式、关联关系和状态语义，不要求逐字相同。
- 重复消息、冲突消息、忙时拒绝、待续提、Session 新建/切换/归档、状态/同步、重启和通知失败语义不变。
- 状态文件能够读取调整前的数据，写回时不丢字段、不放宽大小和数量限制。
- Manager 仍是状态提交和并发协调的唯一所有者，不出现多个模块分别写同一状态文件或维护不同锁。
- M3 各业务域测试、Python 全量测试和插件测试通过。
- 维护者在真实微信完成状态查询、一个 Session 指令和一条普通任务的提交及最终结果验收。

### 预期验收结果

后续修改指令或展示文案时可以在纯逻辑模块中完成；并发、幂等、状态和通知边界仍集中在 Manager，不产生新的业务分叉。

**实际验收结果：已完成（2026-08-15）。**

- 已将持久化/公开结果模型与固定上限、指令规范化/识别/编号和正文拆分、状态/Session/额度/操作结果消息格式化分别建立为独立纯逻辑边界；独立模型模块作为模型与常量的维护入口。
- Manager 从约 4,096 行缩减至约 3,570 行，继续独占状态锁、状态文件写入、提交幂等、重启协调、通知发送和外部服务调用；新模块不读写文件、不持有锁、不启动线程或调用 OpenClaw/微信/服务管理。
- 调度改为消费结构化指令结果，现有固定指令优先级和普通任务回退保持不变；等价性复核发现并修正 `session new retrying` 近似文本可能被误识别为新建 Session 的边界，并新增回归。
- 调整前状态文件和旧状态 code 保持兼容；直接模型往返测试确认写回不丢业务字段，额外字段仍被拒绝，大小和数量上限不变。
- M3 原有 218 项核心调度测试继续全部通过；新增 19 项纯逻辑契约后，微信调度及相邻 API、通知、翻译测试共 `294 passed`；Python 全量测试 `898 passed, 30 skipped`；OpenClaw 插件测试 `34 passed`。
- 页面、插件协议、接口、权限、消息路由和用户可见文案均无计划内变化；维护者已确认真实使用验收通过，M4 正式完成。

### 继续实施评估

M4 完成后不自动进入 M5。先结合实际修改体验确认：微信指令或展示文案能否在纯逻辑边界内独立定位，Manager 的状态所有权是否更清晰，测试失败是否能直接指向业务域。只有确认收益成立且没有新增双实现、循环依赖或状态分叉，才继续快速交互页面整理；否则先修正 M4，或将 M5 记录为“本轮不实施”并说明原因后进入 M6 收口。

## 8. M5：快速交互页面职责整理

### 目标

在不改变现有页面交互的前提下，分离 Session 管理、消息时间线和页面加载协调，降低单个页面脚本的修改范围。

### 实施范围

- 保留现有共享 Quick Interaction Core 及固定脚本加载方式。
- 将 Session 切换、新建、重命名和归档整理为同一职责边界。
- 将消息时间线、通知状态、置顶和重启结果整理为同一职责边界。
- 主页面控制器是 Session、任务列表、分页、轮询、提交和滚动等可变页面状态的唯一所有者。
- Session 与时间线边界只接收只读状态快照和显式回调，不直接修改主控制器或对方的内部状态。
- 跨边界协作不依赖 DOM 内容、提示文案或跨文件可变全局变量反推和同步业务状态。
- 不引入前端框架、打包器、ES Modules 或全局事件总线。

### 验收标准

- Session 切换、新标签打开、新建、重命名、归档及失败弹窗行为不变。
- 消息顺序、增量更新、置顶、通知状态、重启结果、历史分页和“跳至最新”行为不变。
- 草稿、页面数量偏好、输入框自适应、忙碌态、轮询退避和历史返回行为不变。
- Session 与时间线逻辑可以在不创建完整页面控制器的情况下独立测试；测试通过输入快照和回调观察结果。
- 不存在两个模块分别持有或更新同一 Session、任务列表、分页或轮询状态；仅把一个大文件拆成多个共享全局状态文件不能验收通过。
- 脚本加载顺序测试、现有 Node 行为测试、Python Web 测试和真实浏览器回归通过。
- Standard/Cyber 的桌面和手机布局无重叠、溢出或焦点退化。

### 预期验收结果

快速交互的 Session、时间线和页面协调可以分别维护；用户不需要学习新的入口或交互。

**实际验收结果：已完成（2026-08-15）。**
