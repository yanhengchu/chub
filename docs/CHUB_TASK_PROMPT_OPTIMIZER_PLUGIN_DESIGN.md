# Chub 任务提示词优化插件设计

> 状态：持续维护
> 主要读者：AI Agent；维护者通过与 AI Agent 协作，理解并确认本文规则。
> 本文负责：定义一个独立任务编排插件如何接收已受理的普通用户任务，按启用后的运行模式直接返回或生成中英双语优化提示词，并把默认执行版本交回统一分发器；同时定义插件请求主项目创建、恢复和提交内部优化任务的边界。
> 本文不负责：入口认证、入口字段规范化、固定指令语法、目标 Session 选择、统一分发器通用协议、Quick Worker 执行和固定内部工作流；这些规则分别以[总体架构](CHUB_ARCHITECTURE_DESIGN.md)、[任务编排插件模块架构设计](CHUB_TASK_ORCHESTRATION_PLUGIN_DESIGN.md)、[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md)和对应入口专项设计为准。

本文是一个独立任务编排插件的专项设计。主项目已经负责把 Web 或微信普通任务转换为受控的规范化任务请求；本文只定义插件如何消费该请求、处理任务正文和返回结果，不重复描述前置规范化实现。

## 1. 插件定位

任务提示词优化插件挂载在统一任务编排分发器的阶段链中，功能上承接此前微信任务润色的“改善任务正文、使其更适合 AI 执行”的目标，但实现上是入口无关的通用任务编排插件。插件的启用状态与运行模式是两个不同概念：启用状态决定插件是否进入流程，运行模式决定进入插件后是否执行 AI 优化。

```text
Web / 微信普通任务
  -> 主项目入口校验与规范化
  -> TaskOrchestrationDispatcher
  -> （插件未启用：空阶段链，直接投递）
  -> （插件已启用：任务提示词优化插件）
       ├─ direct：原规范化正文直接返回分发器
       └─ auto：复用“任务提示词优化”内部 Session -> 串行提交当前任务的优化请求 -> 返回分发器
  -> 唯一物理主任务投递
  -> Quick Worker / Runtime
```

插件不是入口拦截器、不是第二个任务提交器，也不是旧微信润色模块的兼容层。插件不直接接收微信消息，不读取 Web 请求，不维护微信回送路由，不创建确认队列，不直接调用 Worker。

插件已接入通用模块索引、预检、开发源码自动登记、启停、装配和移除。设置侧栏“插件管理 → 任务编排插件”提供专属设置页；模式名与说明分两行显示，变更立即保存，没有保存按钮或重复的常驻成功提示。默认 `direct`；开发源码已登记且插件启用后可选 `auto`，停用时也能查看和配置。Web/微信 `direct` 与 `auto` 成功主流程均已由维护者确认验收通过；维护者反馈新增的双语结果、失败回退和微信阶段回执在 Web/微信端验收基本没有问题，目前没有明确阻塞项。提示词质量、共享 Session 历史隔离和恢复体验继续长期观察优化。`auto` 提示词优化是附加能力，优化插件内部失败时应提示并继续同一主任务，不得因此中断普通任务；针对阶段选择/初始化失败、回退标记持久化失败及提示/通知故障的定向自动化回归已补充并通过。回退标记必须先持久化：编排状态无法写入或确认时，原任务保持待编排，不投递主任务，存储恢复后通过固定 Web 重启入口重新加载同一检查点并对账；用户提示/通知投影失败不阻断已持久化回退后的主任务。上述回退行为的持久化、恢复和异常分支边界仍按本节复检规则维护。源码保存后的下一条新任务自动校验并切换到最新有效实现，不需重新扫描、导入或启用；旧请求继续使用其固定快照。开发实现移除保留源码与索引；存在未终态引用时先停用、保留实现，任务结束后重试。本插件 ZIP 路径仍未独立验收。通用发现、引用、快照与故障隔离以[任务编排插件模块架构设计](CHUB_TASK_ORCHESTRATION_PLUGIN_DESIGN.md)为准。

### 第三阶段首个独立交付项当前实现

Web 与微信普通任务共用 `auto` 优化执行路径，主流程已由维护者确认验收通过；长期使用中的输出质量、共享 Session 历史隔离和恢复表现继续观察优化。固定索引中的开发源码自动登记为稳定逻辑条目，显式启用后设置页开放 `direct` / `auto`；源码修改不要求重新导入或重新启用，两类入口一起生效，没有按入口排除逻辑。

可执行规则：

- 受理时固定插件模式、实现引用和内部执行默认值快照；唯一共享内部 Session 首次创建时采用创建请求的快照，并固定只读权限与 Chub 工作区。之后的优化任务继续复用该 Session 及其 Runtime/模型/推理配置；后续默认配置变化不重配已有 Session，插件启停只影响新任务。
- 先保留原用户任务 ID、原始正文、摘要、目标 Session 和原入口通知路由，再运行内部优化。Web 显示“正在优化提示词”；微信返回任务已受理的优化进度，不把优化当作主任务已完成。
- 宿主创建或恢复唯一的内部通用 Session，标题固定为“任务提示词优化”；所有 `auto` 请求复用该 Session。共享 Session 的优化任务串行提交，前一个子任务处于未终态或状态无法确认时，后续请求排队等待，不因 Session 正忙而失败。每个父编排请求仍使用独立阶段调用 ID 保证内部任务幂等。内部任务不带微信回送路由、不附加普通交付汇报要求、不递归进入分发器，也不产生用户通知。双语优化结果属于父任务结果：Web 原任务时间线展示两版；微信由 Quick Interaction 宿主在结果校验和检查点持久化后，使用父任务原路由发送两版，不依赖内部 Session 路由。微信结果不代表主任务已完成，发送失败不得阻断主任务。插件提供优化指令和结果解析规则，不直接持有 Session Manager 或 Worker。
- AI 一次返回 `{"optimized_prompt_zh":"完整简体中文提示词","optimized_prompt_en":"complete English prompt"}`；两字段必须同时存在、非空，各自不超过 8,000 字符并通过中文/拉丁文本最低格式检查，结构不得含额外字段；整个 JSON 结果不得超过 Quick Interaction 任务结果的 100,000 字符上限。解析器与任务结果字段共用同一上限，避免对可保存的转义 Unicode 结果提前拒绝。最低语言检查不能证明翻译质量或语义一致，仍须用中文、英文和混合语言输入做实际样例验收。空值、非法/缺失字段、超限、内部任务失败、解析失败或固定 15 分钟窗口耗尽时，优化阶段记录有限类别的失败原因并提示用户，然后将同一父任务的原始规范化正文提交给唯一主任务；不创建替代父任务。状态暂时排队或仍可等待原内部任务时继续按原检查点等待，不误判为失败。结构校验不代表语义质量已经验收；原意和安全边界需通过代表性样例复检。
- 优化窗口从受理起固定为 15 分钟，包含排队和恢复。Session 创建、内部任务关联、优化结果、主任务 Worker ID 均先保存再继续。回执丢失或重启只恢复原关联，不创建替代 Session、优化任务或主任务；Worker 接受状态未知时复用已有身份进行核验。
- 优化成功后，分发器先校验并持久化优化结果，再以原用户任务 ID 唯一提交主任务；页面仍展示原始需求，实际执行使用优化后的中文版。Web 原任务时间线与微信原消息路由都返回完整的中英文双版本，展示时只使用 `Chinese` 和 `English` 标题，不添加其他状态说明。微信消息每条不超过配置的 `max_message_chars`，最多编号分段为 80 条，全部发送成功才记录阶段通知成功；结果无法在上限内完整分段时不发送并明确记失败；开始发送后若通道中断导致部分送达，也记录失败且不自动重发，不截断后冒报成功。阶段通知状态独立持久化并记录操作终态；通知失败不得阻断主任务。无法持久化 `sending` 前置状态时不调用微信发送；若发送结果已知但终态落盘失败，不重发并继续推进终态通知。重启后仍为 `sending` 的状态按未确认失败收敛，不盲目重发。阶段通知状态收敛后，再发送主任务最终通知。
- 优化期间可停止原任务；用户停止时收敛原任务及内部任务，主任务不再投递。优化插件失败或阶段选择状态无法确认时则尽力收敛内部任务，但不因此取消或阻断同一父任务的主任务回退；**提交原文前必须先持久化脱敏失败类别与回退标记。若编排状态写入或确认失败，原任务保持待编排且不分配主 Worker、不提交原文；存储恢复后通过固定 Web 重启入口重新加载已保存检查点并对账。这属于编排状态故障，不属于优化插件自身失败。**提示状态保存或微信通知失败是尽力投影，不阻断已经持久化的回退，但可能导致用户看不到失败提示。微信失败提示固定为 `Prompt optimization failed; the original task is continuing.`；Web 显示同一原任务关联的中文提示。停用不取消已有任务。移除前先停用；仍有未终态引用或内部清理未确认时，保留制品并提示等待后重试，不能清除正在使用的实现。

开发源码在索引声明的固定目录中自动登记为一个稳定逻辑条目。每次受理新任务前，宿主重新计算源码摘要、校验并装配最新内容；保存有效代码后，下一条新任务自动使用新摘要，无需手动扫描、导入、移除旧版本、重新启用或重启 Web。启用状态与 `direct` / `auto` 模式偏好保持不变。每个已受理任务仍固定自己的实现摘要和阶段链；宿主将该版本保存在本机私有快照中，任务恢复继续使用旧快照。当前源码校验或装配失败时，插件状态提示仍在使用上次已验证版本；没有可用版本时，已受理的新 `auto` 任务按可选阶段失败规则提示并执行原始规范化正文，不因优化器缺失阻塞主任务。ZIP 制品继续遵循独立的导入与不可变版本规则。

### 插件状态与运行模式

| 插件状态 | 运行模式 | 是否进入插件 | 插件行为 |
| --- | --- | --- | --- |
| 未启用 | 无 | 否 | 分发器使用空阶段链，直接投递主任务 |
| 已启用 | `direct` | 是 | 不创建内部 Session、不调用 AI，立即返回原规范化正文 |
| 已启用 | `auto` | 是 | 复用标题为“任务提示词优化”的内部 Session，串行提交当前任务的优化请求并返回结果 |

启用状态和运行模式都在任务受理时固定到阶段链快照；后续停用插件或切换模式只影响新任务。`direct` 是插件内的直接返回模式，不等同于插件未启用，也不绕过统一分发器。

## 2. 任务来源

插件只处理已经通过主项目入口校验并由统一分发器受理的**普通用户任务**：

| 来源 | 是否支持 | 插件看到的内容 |
| --- | --- | --- |
| Web 快速交互 | 支持 | 主项目提供的规范化任务正文、固定目标 Session 和受限任务上下文 |
| 微信普通正文 | 支持 | 主项目提供的干净文字或可信语音转写，以及固定目标 Session 和受限任务上下文 |
| 微信固定指令 | 不直接支持 | 由微信入口先处理，不创建本插件阶段请求 |
| `text` / `text-check` | 不支持 | 旧能力明确拒绝，不进入本插件 |
| 周报、今日关注、部署说明等固定内部工作流 | 默认不支持 | 继续使用各自直接调用 Quick Worker 的业务流程；除非另行完成入口接入设计 |
| 插件或阶段内部任务 | 不支持 | 不得递归进入本插件或统一分发器 |

插件不根据正文自行猜测来源。入口类型、内容类型、目标 Session、请求幂等关联和 `operation_id` 已由主项目确定；插件只能读取本次阶段授权的受限投影。

## 3. 优化目标

插件在 `auto` 模式下的目标是把用户原始任务正文转换为**更明确、更完整、更适合后续 AI 执行的任务提示词**，同时保持原任务意图和执行边界不变。`direct` 模式不改变正文，只验证并返回入口已经规范化的正文。

允许的处理方向包括：

- 补充任务目标、上下文、约束和预期结果的结构化表达。
- 消除明显歧义，整理用户已经表达的要求和验收条件。
- 将口语化、简略或不完整的任务描述转换为清晰的执行说明。
- 无论当前任务输入为中文、英文还是混合语言，优化器均生成语义一致的一份简体中文提示词和一份英文提示词。Web 和微信原提交入口都返回/展示两版；中文版本用于主任务，英文版本不提交给主任务；不得让入口语言、模型或维护者的临时选择改变默认提交版本。
- 主任务面向用户的执行回复和完成说明使用简体中文；若用户明确要求最终交付物使用其他语言，仍按该语言制作交付物。两种优化提示词都必须保留此区分，不能把“中文回复”扩张为“所有产物都必须中文”。
- 保留专有名词、路径、标识、代码、链接和必须原样使用的文本及明确格式要求。
- 每次优化请求的提交正文只由本次父任务携带的当前输入构造；不能把此前任务正文或优化结果拼入本次输入。提示词要求模型忽略共享 Session 的历史对话，但 Codex 恢复同一原生 Session 时，历史轮次仍可能处于模型上下文中；提示词要求不是技术隔离保证。必须用相互无关且要求冲突的连续任务验证结果没有串扰，发现串扰时不得关闭 `auto` 验收。

禁止的处理方向包括：

- 改变用户目标、扩大权限、增加未授权的操作范围或虚构事实。
- 自行选择 Runtime、Session、模型、文件、命令、URL、收件人或外部账号。
- 执行任务、修改文件、调用外部服务或替用户确认高风险动作。
- 把插件结果当作任务完成，或绕过分发器直接提交 Worker。
- 自动恢复旧微信确认队列、旧微信专属设置或旧润色状态。

插件输出的是“下一步要执行的任务提示词”，不是最终业务结果，也不是面向用户的独立回复。

## 4. 插件输入

插件输入由统一分发器根据受理时快照提供。本文只约束插件可消费的字段，不重新定义主项目的入口规范化过程。

| 输入 | 说明 | 插件边界 |
| --- | --- | --- |
| `entry` | `web` 或 `weixin` | 只用于受控匹配和处理策略，不得据此读取入口私有状态 |
| `task_type` | 当前为 `ordinary_user_task` | 不接受插件或用户改写 |
| `content_type` | 普通文字或可信语音转写等受控类型 | 只能使用主项目已经确认的类型 |
| `content` | 已规范化的任务正文 | 只读；不得修改原始受理快照 |
| `session_id` | 固定目标 Session 的受限引用 | 不得重新选择、切换或创建 Session |
| `markers` | 主项目根据可信入口事实提供的受控标记 | 不得伪造入口来源或新增未登记标记 |
| `mode` | `direct` / `auto` | 由插件启用配置在受理时快照；插件不能由正文或模型自行切换 |
| `operation_id` | 当前编排操作的关联 ID | 用于关联阶段记录；不得创建替代主任务 |
| 阶段检查点 | 当前插件阶段的持久化输入和恢复信息 | 只能按插件协议读取和返回 |

插件不得接收或保存微信账号、收件人、Context Token、客户端凭据、任意路径、命令、原始 HTTP 请求或未授权的 Runtime 私有配置。

## 5. 运行模式与提示词输出

### `direct` 模式

插件接收分发器提供的规范化正文后，完成最小输入校验并立即返回原正文：

```text
input.content -> output.optimized_prompt
```

`direct` 的单一正文沿用分发器既有字段；双语结果契约只适用于 `auto`。

`direct` 模式不创建内部 Session、不调用 AI、不产生插件子任务、不创建确认项。返回结果交回分发器，由分发器继续唯一物理主任务投递。

### `auto` 模式

插件通过 Chub 宿主授予的受控 AI 能力执行提示词优化。插件不得直接调用模型供应商、OpenClaw、`openclaw agent`、Quick Worker 或 Runtime 私有对象。插件只能向主项目公开能力提出创建/恢复内部 Session、提交内部任务和读取任务结果的请求；Session、任务和底层执行均由主项目对应的公开用例负责。宿主能力调用的授权、结果枚举和最终状态以总体架构与任务编排架构为准。

进入 `auto` 模式后，插件请求主项目创建或恢复唯一的 `internal` 提示词优化 Session，固定标题为“任务提示词优化”。它不是用户目标 Session，不执行最终任务；列表展示由 Chub 内部 Session 可见性开关控制，以[Chub Session 状态模型设计](AI_SESSION_STATE_DESIGN.md)为准。主项目负责创建、恢复、关联和终态；插件不持有 Session 状态或直接调用 Session Manager。Session 使用稳定的宿主幂等键跨父任务复用；每个父 `operation_id` 和阶段调用 ID 仍唯一关联自己的优化任务。所有优化任务在这个共享 Session 上串行运行；前一个子任务未到终态或状态无法确认时，后续 `auto` 请求保持排队，不另建 Session，也不并发写同一 Session。

共享 Session 在首次创建时使用该任务受理时快照中的主项目默认 Runtime、模型、只读权限和 Chub 工作区，之后始终沿用此配置；后续默认配置变化不改写已创建 Session。内部优化任务使用普通任务提交协议和 `standard` 任务类型，不使用已退役的 `translation` 类型、旧翻译队列或微信通知任务类型。提示词优化用途、父编排请求和阶段调用关系由主项目编排状态记录，不通过新增 Worker 任务类型表达。内部任务不绑定 Web 请求或微信通知路由，结果只返回给插件和分发器，不产生独立用户通知。

主项目必须提供受控的内部任务能力，用于按本次阶段请求创建或恢复普通 Session、提交 `standard` 任务和读取该任务结果。该能力由主项目的公开用例负责状态写入、Worker 协调和最终状态确认；插件只能提交受限参数和读取结果，不能把内部任务伪装成 Web/微信用户任务，也不能直接调用 Session Manager、Quick Worker 或 Runtime。

主项目创建/恢复共享内部 Session 时使用稳定的宿主幂等键；每次内部任务提交仍必须以父 `operation_id` 和阶段调用 ID 幂等关联。插件或分发器重启后，先按共享 Session 键和阶段调用 ID 查询已有 Session、任务及结果；只有确认本次任务尚未提交时才能继续请求，不能用新的 Session 或新的任务替代原请求。共享 Session 的所有写入必须串行；状态未知时暂不启动下一条优化任务，恢复对账确认终态后再继续。

一次 `auto` 阶段回合最多发起一次受控 AI 处理。插件向 AI 能力提供：

- 已规范化的任务正文。
- 本插件固定的处理目标和输出格式约束。
- 本次任务允许使用的非敏感上下文。
- 明确的禁止事项：不得虚构事实、扩大权限或执行任务。

成功时必须只返回以下结构化结果，不能把解释性文字直接当作任务正文：

```json
{
  "optimized_prompt_zh": "完整简体中文优化提示词",
  "optimized_prompt_en": "Complete English optimized prompt"
}
```

两字段必须同时存在、非空，分别不超过 8,000 字符；整个 JSON 结果不得超过 100,000 字符（与 Quick Interaction 结果存储上限一致）。拒绝多余字段、非法 JSON、超限正文或未通过最低语言文本检查的版本。两个值只包含各自语言的完整可执行任务正文，不带包装文字、翻译说明或摘要。最低语言文本检查仅验证存在对应书写文本，不能证明简体中文纯度、英文自然度或语义一致；这些质量由代表性样例验收。可恢复检查点由宿主管理，不作为模型输出字段。

分发器重新校验并将两版一起写入父请求检查点，再由 Quick Interaction 宿主保存到原 Web 任务供时间线读取；只有 `optimized_prompt_zh` 被作为下一阶段任务提示词提交给唯一物理主任务。Web 时间线和微信阶段结果都只用 `Chinese`、`English` 标题区分两个版本，不展示提交状态说明；执行时仍只有中文版进入主任务。微信阶段结果只沿父任务原路由发送，不由内部优化任务或插件发送；每条不超过配置的 `max_message_chars`，最多编号分段为 80 条；超限时不发送不完整结果且不得记录为成功，部分发送失败时不自动重发。主任务终态通知不包含优化提示词正文，运行日志也不得包含两版正文。部署前已受理且只有单一优化正文的旧检查点继续按原快照恢复，不重新调用优化器，也不补造英文版；双语契约仅对新建请求强制生效。主任务到达终态后，编排检查点立即清除两版优化正文，仅保留所需状态与关联信息；原 Web 任务的双语展示记录仍按任务历史保留。

插件不返回 Worker 任务 ID，不返回微信通知路由，不直接发送用户通知，也不宣称主任务成功。

## 6. 状态、幂等与恢复

插件阶段状态归统一分发器所有，至少包括：

| 状态 | 含义 |
| --- | --- |
| `accepted` | 编排请求已受理，尚未开始插件回合 |
| `running` | 插件回合或其受控 AI 能力正在处理；`direct` 模式可快速经过此状态 |
| `waiting_capability` | 已保存等待关联，等待可信能力结果或恢复事件 |
| `resuming` | 已找回阶段检查点，准备继续同一请求 |
| `completed` | 插件阶段已返回合法处理结果；不代表物理主任务完成 |
| `failed` | 当前阶段处理失败；对提示词优化 `auto`，分发器可按专项规则记录失败并继续父任务，因此阶段失败不必然代表父任务失败 |

插件阶段必须绑定父编排请求、模式快照和不可变实现引用。`direct` 模式的阶段结果是原规范化正文；`auto` 模式的阶段结果还必须绑定共享内部 Session 和该父任务的内部任务检查点。阶段检查点至少保存父 `operation_id`、阶段调用 ID、模式、实现引用、输入指纹、内部配置快照、内部 Session 关联、内部任务关联、阶段状态和最终结果引用。内部配置快照按请求留存；共享 Session 首次创建时固定采用创建该 Session 的请求快照，后续请求不得据各自快照重配或替换 Session。创建或提交内部任务前必须先保存检查点；重复回调只能读取已保存的检查点，不能重复调用 AI 能力；Web 或 Worker 重启后只能恢复原阶段、原模式、原实现和既有 Session/任务关联，不能切换当前活动实现，也不能重新创建替代任务。

`auto` 模式的检查点还必须保存一个受控子阶段：共享 Session `session_create_pending` / `session_ready`，以及每个父任务的 `task_submit_pending`、`task_accepted`、`result_pending` 或 `result_ready`。共享 Session 的创建/恢复使用稳定的宿主 Session 幂等键；每次任务提交和结果查询使用父 `operation_id`、阶段调用 ID 与动作名称组成的幂等关联。每次调用前先写入对应 pending 子阶段，回执丢失时先按同一关联查询，不得用新 Session 或新任务替代原请求。

恢复规则：

1. AI 调用回执丢失时，按父 `operation_id` 和阶段调用关联对账；共享 Session 按稳定宿主键恢复。
2. 能确认结果且结果校验通过时，回写原阶段检查点并继续分发。
3. 结果未完成时只在固定的阶段对账窗口内等待原关联，不创建第二次调用。
4. 结果未知且继续调用可能产生重复副作用时，不创建替代的优化调用；若当前优化阶段已失败或无法在固定窗口内确认，则按下述可选阶段回退规则处理。
5. AI 优化失败、输出为空、输出超限、结果无法校验、优化实现不可用或固定窗口耗尽时，先持久化脱敏失败类别与回退标记，再继续提交同一父任务的原始规范化正文；绝不创建第二条父任务。若失败类别或回退标记无法持久化，保持父任务待编排且不分配主 Worker 身份、不投递原文；将该情况视为编排状态存储故障，恢复后从已保存检查点重新对账，不创建新父任务或替代任务。用户提示与微信通知是尽力投影，持久化、排队或发送失败不阻断已持久化回退后的主任务。主任务提交回执状态未知时仅按原 Worker 身份对账，不得触发原文回退或重复提交。

`waiting_capability` 只表示仍在等待原内部任务的可信终态，不表示等待用户确认。等待使用受理时固定的阶段超时或对账窗口；窗口结束仍无法确认时，提示词优化阶段记录脱敏失败原因并回退到原始规范化正文；不无限等待、不自动重投优化请求。该回退只适用于本插件 `auto` 提示词优化阶段，不覆盖主任务提交状态未知，也不构成其他阶段的通用规则。

`direct` 模式没有 AI 调用和内部 Session；它只需要持久化阶段完成结果，然后回到分发器，不进入等待或确认流程。

插件停用、实现替换、运行模式切换或模块故障只影响尚未受理的新请求；已受理请求继续使用受理时固定的启用状态、运行模式、实现和阶段快照。若 `auto` 优化内部阶段不能继续，按本节回退规则以原始规范化正文推进原父任务；主任务提交仍按 Worker 自身的状态对账规则处理。该例外不自动适用于其他插件阶段。

## 7. 用户可见结果

插件处理过程不是独立的用户任务，不单独产生一条 Web 或微信任务，也不单独发送完成通知。

- 插件成功：用户最终看到的是后续物理主任务的正常执行结果。
- 插件等待：入口根据已有请求状态展示处理中或等待状态，不创建新请求。
- 优化插件失败：Web 原任务时间线显示“提示词优化未完成，主任务将按原始输入继续执行。”；微信原路由发送简短固定失败提示。分发器继续原父任务，使用受理时保存的原始规范化正文提交唯一主任务；插件阶段失败不作为父任务最终失败。主任务最终结果仍按原入口返回。该行为不适用于用户主动停止，也不改变主任务提交结果未知时的对账规则。
- 微信回送：仍由微信入口保存的原路由负责，插件不能直接发送消息。`auto` 成功后宿主先发送完整的中英文阶段结果，消息只使用 `Chinese`、`English` 标题；结果按固定上限编号分段，超限或部分发送失败均不能冒报完整成功，且通知失败不阻断主任务。原路由随后承载主任务终态通知。通知状态未知时不自动重发，避免重复消息。
- Web 展示：仍由 Web 页面原请求关联负责，插件不能替换浏览器请求 ID。

若未来具体场景需要用户确认处理后的正文，必须新增编排检查点和入口交互设计；确认只能恢复原编排请求，不能恢复旧确认队列，也不能创建第二条物理任务。

## 8. 插件实现与生命周期

插件应作为独立任务编排模块登记，至少定义：

- 稳定 `module_id`、版本和 `scope`。
- 插件协议版本、能力协议版本和 Chub 兼容版本。
- 阶段入口、输入/输出模型和固定处理目标。
- 允许匹配的 `task_type`、`content_type`、入口范围和标记。
- 所需 Chub 能力投影及其失败边界。
- 开发实现或 ZIP 实现的不可变引用和内容摘要。

插件通过 Chub 通用模块机制完成发现、启用、禁用和加载。仓库开发源码按固定索引自动登记为稳定条目，不要求开发期间手动扫描或导入；首次启用仍由维护者明确操作。正式 ZIP 仍须显式导入，且导入不自动启用。启用操作先校验并装配入口，成功后立即影响下一次受理的新任务；禁用立即让后续新任务跳过插件，均不要求重启 Web。已受理任务继续使用创建时固定的阶段链和模式快照。插件在插件管理列表中展示通用生命周期操作；设置页通过“设置 → 插件管理”侧栏的“任务编排插件”分组独立进入。专属设置页面只负责维护 `direct` / `auto` 模式等插件配置，不重复提供导入、启用、禁用或移除等生命周期操作。模式选项以名称和说明分两行展示，不以中点连接；控件变更后立即持久化，保存成功后只影响后续受理的任务，不能改写已受理任务；读取或保存失败必须显示真实错误，保存失败恢复此前确认的选项，不展示未确认成功状态。

插件包、开发实现、状态隔离、操作日志、替换和移除规则统一遵循[任务编排插件模块架构设计](CHUB_TASK_ORCHESTRATION_PLUGIN_DESIGN.md)和[总体架构设计](CHUB_ARCHITECTURE_DESIGN.md)的宿主边界。

## 9. 验收标准

首个实现至少验证：

1. Web 和微信普通任务均能从统一分发器进入插件，固定指令和内部工作流不会误匹配。
2. 插件只消费主项目已规范化的任务正文，不读取入口私有路由或敏感凭据。
3. 插件未启用时不进入插件；主任务直接投递。
4. 插件已启用且为 `direct` 时不创建内部 Session、不调用 AI，原正文只返回一次并继续投递一个物理主任务。
5. 插件已启用且为 `auto` 时，插件只请求主项目创建或恢复标题为“任务提示词优化”的唯一共享内部 Session，并以 `standard` 任务类型串行提交当前任务的优化请求；中文、英文或混合输入都必须得到完整的中英文双版本，结构、非空、各自 8,000 字符上限及最低语言格式检查均通过后才算优化成功。两版进入同一检查点，Web 原任务时间线和微信原提交路由都返回/展示两版，展示时只使用 `Chinese`、`English` 标题，不添加提交状态说明；分发器只把中文版提交给唯一物理主任务。面向用户的执行回复使用中文，明确指定语言的交付物仍使用该语言。
6. AI 回执丢失、Web/Worker 重启、插件回合中断后，按原 `operation_id`、模式和检查点恢复，不重复创建 Session、调用 AI 或投递任务。
7. 优化内部任务仍在排队或运行时按固定检查点等待；优化调用明确失败、结果为空/非法、实现不可用或 15 分钟窗口耗尽时，Web 显示失败提示、微信按原路由发送失败提示，并由同一父任务使用原始规范化正文继续。确认提示词优化失败后只创建一个主 Worker 任务；主 Worker 提交结果未知时必须沿原 Worker ID 对账，不能回退重提。还需注入回退标记落盘故障，确认主 Worker 未分配、原文未提交且父任务保持待编排；提示状态持久化与通知失败则不得阻断已持久化回退。恢复状态存储并通过固定 Web 重启入口重新加载后，须能从同一检查点完成对账。
8. 重复 Web 请求或重复微信消息只关联首次编排请求，不创建第二个插件回合或 Worker 任务。
9. 插件停用、运行模式切换、版本替换或实现不可用不会改变已受理任务，也不会阻断不匹配的普通任务和无关 Chub 能力。
10. 首次创建共享优化 Session 的任务快照固定该 Session 的 Runtime、模型、只读权限和工作区；后续默认配置变化不重配共享 Session，也不改变任何已受理任务。
11. 当前不实现自动优化后的人工确认；插件成功后直接回到分发器。
12. 微信 `auto` 优化结果通过校验并持久化后，宿主沿父任务原路由发送中英文两版阶段结果，消息只使用 `Chinese`、`English` 标题，不添加状态说明。每条不超过配置的 `max_message_chars`，最多编号分段为 80 条；任何一段发送失败或超出分段上限都不得记作完整成功，已部分送达时不自动重发，失败不阻断主任务。发送前状态无法持久化时不得调用微信；发送后状态落盘失败不得盲目重发，必须释放终态通知的推进路径；重启后遗留的 `sending` 按未确认失败记录。阶段结果通知状态收敛后才发送主任务终态通知；Web 在原任务时间线展示两版，内部优化任务不直接发送通知。
13. 真实微信发送、回送和用户可见结果由维护者在微信客户端完成验收。
14. 仓库开发源码由固定索引自动发现并登记为单一稳定条目；摘要变更不产生重复条目，不需要手动移除、扫描/导入或重新启用。自动登记不自动启用，维护者首次显式启用后，源码保存后的下一条新任务自动使用最新有效版本。ZIP 继续显式导入且导入不自动启用；插件不可用时不影响不匹配的普通任务和无关 Chub 能力。
15. 已导入插件的设置入口出现在“设置 → 插件管理”侧栏的“任务编排插件”分组；插件扫描列表不显示设置按钮，只承担通用生命周期操作。停用插件仍可从侧栏进入设置，移除后侧栏入口消失。
16. 插件专属设置页能读取模式；模式选项名称与说明分两行显示、不用中点连接；模式控件变更后立即保存，不提供单独保存按钮。保存成功后不显示重复的常驻成功提示；保存失败恢复原值并展示错误。模式变更只影响后续受理的新任务。
17. 已受理任务继续使用受理时固定的模式、实现和阶段链，设置变更、停用或替换不能改写这些任务。
18. `auto` 优化阶段预检、提示词构造、内部 Session/任务执行、双语结果解析或结果保存失败时，原父任务继续执行原始规范化正文；Web/微信显示或发送失败提示。执行配置快照读取或校验异常使用独立类别 `execution_snapshot_failed`，提示词指令构造异常或无效指令使用 `instruction_generation_failed`，不得混为同一诊断类别。自动化需覆盖阶段选择/配置快照异常、提示词构造异常、无效输出、内部任务失败、超时、回退标记落盘失败、提示状态保存失败和通知失败。回退标记落盘失败时确认父任务保持待编排且不提交主 Worker；提示或通知投影失败不得阻断已持久化回退。模拟内部任务提交后回执丢失、失败输出和超时恢复，确认最多一条父任务和一个物理主 Worker。若主 Worker 的提交回执或终态未知，确认系统按原 Worker ID 对账，不被优化回退逻辑重复提交。插件错误日志只记录请求 ID 与固定失败类别，不记录任务正文、模型输出或原始异常。
19. 长期质量观察：连续提交内容无关且要求冲突的 `auto` 任务，持续确认共享 Session 的历史没有造成任务串扰；保持拒绝完全不含汉字的优化结果，并根据实际使用反馈逐步优化简体中文质量。该观察不阻塞已确认的当前主流程验收；如发现串扰、非预期跨任务影响或违反安全边界，应重新打开验收并处理。
