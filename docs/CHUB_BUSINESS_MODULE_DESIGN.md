# Chub 工作台业务模块设计

> 状态：调研中
>
> 主要读者：AI Agent；维护者通过与 AI Agent 协作，理解并确认本文规则。
>
> 本文负责：定义 Chub 工作台业务模块的最小宿主边界、首个 Deliveryline 固定开发模块的接入方向、状态归属和第一阶段验收。
>
> 本文不负责：Deliveryline 的需求交付规则、任何业务模块的页面细节和数据模型、Runtime/任务编排插件协议，或 ZIP 导入与通用第三方插件市场；这些内容在有真实需求后分别定义。

## AI 可执行契约

1. 工作台业务模块是在 Chub 工作台中提供独立业务页面、业务数据和流程的模块；它不是 AI Runtime，也不是一次任务提交前的任务编排阶段。
2. Chub 核心拥有工作台壳、可信访问、固定导航注册、模块可用状态、受控 Chub 用例、通知和最终运行状态；业务模块拥有自己的领域记录、阶段规则、页面交互和业务结论。双方不得直接改写对方私有状态。
3. 首个模块是 Deliveryline。实现开始时，其固定开发源码位于 `business-modules/deliveryline/`；当前尚未创建该目录、模块宿主、页面入口或数据模型，不能宣称模块已安装或可用。
4. 第一阶段只支持仓库内固定开发模块和固定工作台分区。页面、外部入口、配置或模块自身均不能传入任意代码路径、命令、路由、数据目录、Runtime、Worker、原生 Session、收件人或凭据。
5. 业务模块需要 AI 执行时，维护者必须在业务页面明确触发；模块只能通过 Chub 提供的受控 Session/任务用例提交，并保存业务记录与受限 Chub 标识的关联。任务受理、HTTP 成功或 Agent 回复不等于业务阶段完成；模块只依据 Chub 确认的最终状态收敛自身结论。
6. 模块故障、停用或未实现只能影响该模块及之后的新业务请求，不阻塞 Chub 核心、Runtime、Quick Worker、微信或其他独立服务。已受理业务记录按其创建时快照和具体业务恢复规则完成或明确失败。
7. ZIP 导入、动态发现、任意第三方业务模块、动态页面注入和跨模块流程编排不属于第一阶段。出现第二个真实业务模块后，才根据共同需求定义最小安装、升级、移除和恢复协议。

## 当前定位

Chub 已实现 Runtime 插件模块与微信任务编排插件模块；工作台业务模块是第三类模块方向。它的目的是让独立业务在同一工作台中复用 Chub 的可信入口、页面壳和受控执行能力，而不把业务流程写入核心层。

```text
Chub 工作台
  ├─ 核心：可信入口、导航、模块状态、通知、Session、Worker
  ├─ Runtime 模块：本机 AI 执行能力
  ├─ 任务编排模块：一次任务的受控逻辑阶段
  └─ 业务模块：独立业务流程与交互
       └─ Deliveryline：需求交付管理
```

业务模块不是新的第四业务层：它依赖 Chub 核心公开用例，不能反向成为核心、Runtime 或第三方服务的依赖。Chub 也不因业务模块存在而拥有其领域规则、业务数据或验收结论。

## 首个 Deliveryline 接入边界

Deliveryline 在工作台内管理需求从提出到验收合格的流程、资料、决策、自动化测试结果和验收结论。它与 Chub 的分工固定为：

| 范围 | 权威所有者 |
| --- | --- |
| 需求、阶段门槛、退回、资料、测试证据与验收结论 | Deliveryline 业务模块 |
| 可信访问、工作台壳、模块可用状态、通知基础设施 | Chub 核心 |
| AI Session、任务、租约、Runner、Worker 与执行终态 | Chub AI Runtime |

“开发实现”阶段只有在维护者明确操作后，才创建关联的 Chub Session 或任务。Deliveryline 保存受限关联标识和 Chub 的最终结果摘要作为证据；它不读取或控制原生 Session、Worker、Runner 或 Runtime 私有配置。业务阶段是否通过仍由 Deliveryline 的阶段规则和维护者验收决定，不能把 Chub 任务成功直接等同为需求合格。

模块专属数据位置、是否可同步以及资料的保留/清理边界，必须随 Deliveryline MVP 数据模型一并定义。不得复用或直接编辑 Chub 需求储备、Session、任务、通知、配置或其他模块的数据文件。

## 第一阶段范围与验收

第一阶段只交付 Deliveryline 需要的最小闭环：固定工作台入口、需求记录、阶段状态与门槛、阶段资料/决策、测试结果、验收结论，以及一次维护者显式触发的 Chub 执行关联。开始实现前，必须先补充 Deliveryline 的具体页面、数据模型、状态流转、失败/恢复与验收规则。

首轮验收至少确认：

- Chub 在没有 Deliveryline 时继续正常提供核心能力；
- Deliveryline 未实现、不可用或故障不会影响 Runtime、Worker、微信和其他工作台分区；
- 模块只能在固定工作台入口和可信网络内访问，不能扩大外部入口权限；
- 业务记录与 Chub Session/任务使用受限标识关联，任务终态可追溯但不自动替代业务验收；
- 页面、数据、通知和失败提示只反映可确认的业务或执行终态。

实现工作台业务模块宿主、Deliveryline 数据所有权、Chub 用例授权、任何模块安装/移除规则，或用户可见业务阶段/验收契约变化时，必须重新评审本文并执行相关自动化与产品回归。
