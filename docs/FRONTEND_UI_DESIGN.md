# Chub 前端 UI 模块化设计

> 状态：已验收
> 主要读者：AI Agent、实现和排障 Agent；维护人员用于确认页面分层、交互边界和验收范围。
> 本文负责：Chub Web 前端分层、页面状态归属、公共交互、固定资源加载顺序，以及主题、文字大小注册、完整 Token 包和语义 Token 契约，遵循[Chub 总体架构](CHUB_ARCHITECTURE_DESIGN.md)。
> 本文不负责：后端 API、认证与安全契约、Quick Worker/OpenClaw 的业务状态、服务恢复流程和历史前端拆分过程；这些内容分别以总体架构、专项设计和能力清单为准。

## 1. AI Agent 执行摘要

Chub Web 使用 FastAPI、Jinja2、原生 JavaScript 和 CSS，同源部署且不引入前端构建链、全局状态库或前端框架。根路径 `/` 是正式工作台；`/workspace` 只负责跳转到根路径对应分区，不是独立页面。

实现或排障前按以下规则判断：

1. 前端只投影后端快照，不根据按钮、缓存、文案或旧 DOM 推断业务终态。
2. 每个动态卡片或分区独立拥有请求、缓存、刷新、轮询、渲染和失败反馈；共享资源只由页面协调层定向协调。
3. 页面切换或 DOM 替换必须释放被替换 Feature 的请求、计时器、事件订阅和临时资源；不存在目标 DOM 时不得初始化该 Feature。
4. 公共组件只解决稳定的 DOM 与无障碍行为，不吸收业务请求、业务状态或服务维护决策。
5. 主题和文字大小只改变公共页面的视觉 Token 与排版比例，不改变模板语义、数据、路由、权限、状态机、键盘操作或响应式信息结构；终端保持独立显示。
6. 设置页展示配置、安装和版本元数据；Gateway 等实时运行状态及其操作只属于首页工作站。具体 OpenClaw 边界以 [OpenClaw 定制设计](OPENCLAW_CUSTOMIZATION_DESIGN.md) 和[能力清单](CHUB_INTEGRATION_CAPABILITIES.md)为准。

本文记录当前可维护结构和后续主题收敛方向，不以页面的临时文案、某次故障诊断或历史实现过程作为产品契约。

## 2. 状态与页面边界

| 范围 | 前端所有者 | 前端职责 | 权威规则 |
| --- | --- | --- | --- |
| AI Session | Session Feature 或快速交互 Page Controller | 请求统一快照、展示状态、提交当前入口允许的操作 | [AI Session 状态模型](AI_SESSION_STATE_DESIGN.md) |
| 工作站、自动化、项目资料 | 各自 Feature | 独立读取、会话级成功缓存、局部刷新和局部失败反馈 | 本文第 3 节 |
| 页面级切换与共享资源 | `workspace.js` / 页面 Controller | 组装页面、切换分区、触发受影响 Feature 刷新、释放已替换 Feature | 本文第 3 节 |
| 外观偏好 | `theme.js` | 保存、恢复和应用有效主题与文字大小；为首屏同步非敏感 Cookie | 本文第 6 节 |
| 设置 OpenClaw 信息 | 设置页 Feature | 读取本机配置、安装元数据和补丁清单；不读取 Gateway 运行状态 | OpenClaw 定制设计 |

前端不得另行定义 Session owner、phase、入口权限或维护操作成功条件。Session 快照中的 `usage`、`status` 和 `activity` 含义以状态模型为准；HTTP 成功、任务受理或子进程创建都不能渲染为业务成功。

首页工作站、AI Session、自动化和项目资料是同级分区。设置按维护对象分为通用设置、AI Runtime、第三方服务和维护；AI Runtime 分组在侧栏中包含“通用配置”及每个已接入 Runtime 的独立入口。跨 Runtime 的用量时区在通用配置维护，Runtime 专属配置不混入通用页。Runtime 详情页只展示健康状态、任务接入策略和适合日常维护的专属配置；工作目录、运行目录和其他部署字段保留在 `settings.local.yaml` 的 `ai_runtime.<runtime_id>`，不得伪装成设置页可编辑项。设置入口是独立 URL，侧栏切换替换当前历史条目，浏览器返回应离开设置回到进入前的应用页。次级详情页沿用当前标签和浏览器返回，不额外创建专用返回栏。

设置 OpenClaw 页面只呈现微信 ClawBot 适配器、Chub 插件的本机配置/安装元数据匹配，以及已验收补丁基线的清单登记。该读取应直接读取固定配置或清单，不因页面性能引入长时命令探测或 Gateway 检查；读取失败只表示元数据无法确认，不得推断 Gateway、插件加载或补丁运行结果。

## 3. 模块、加载与生命周期

当前前端使用全局函数和固定 `defer` 顺序，不是 ES Modules。首页相关目录如下：

```text
app/web/
  templates/
    workspace_preview.html
    partials/app_styles.html
  static/
    theme.js
    quick_interactions_core.js
    quick_interaction_session.js
    quick_interaction_timeline.js
    quick_interaction_conversation.js
    js/
      components/
      features/workspace-sessions.js
      features/workspace-workstation.js
    css/
      tokens.css
      base.css
      components.css
      responsive.css
```

首页加载顺序是兼容契约：

```text
Workspace Bootstrap -> Theme -> Components -> Workspace Coordinator -> Workspace Features
```

快速交互页的顺序是：

```text
Quick Interaction Core -> Session View -> Timeline View -> Page Controller
```

- Components 只处理可复用 DOM 行为、焦点和 ARIA 状态，不发起业务请求。
- Feature 拥有本分区请求、快照、缓存、轮询、DOM 渲染和错误展示，不能读取其他 Feature 的内部状态。
- `workspace.js` 只负责侧栏、分区替换、页面级协调和必要的清理，不回收业务实现为单体脚本。
- 快速交互中，Core 管理请求和无状态规则，View 只消费快照并通过回调上报动作，Page Controller 是 Session、任务列表、分页、轮询、提交和草稿状态的唯一所有者。
- `theme.js` 只管理主题、文字大小、首屏色彩方案和无敏感 Cookie，不拥有业务缓存或服务状态。
- 其他次级页面可保留独立脚本；只有存在稳定、多处复用的边界时才提取公共能力。

动态区域遵循以下生命周期：

1. 首次进入可渲染安全的会话级成功缓存，再后台读取最新快照。
2. 刷新期间保留最近一次成功内容；失败保留旧内容并只在所属区域反馈。
3. 卡内操作只刷新实际受影响区域；共享操作由页面协调层显式定向刷新，不能全页盲目重载。
4. 分区替换、快速会话关闭或目标 DOM 消失时，Feature 必须取消未完成请求、清除计时器/轮询、移除监听器并释放临时对象 URL 等资源。
5. 已销毁或不在页面中的 Feature 不得写入 DOM、更新缓存或重新启动轮询。

调整脚本文件、模板引用或顺序时，必须同步顺序测试并完成受影响页面的真实浏览器回归。

## 4. 公共交互契约

- 外部内容、日志和 API 文本一律经 DOM API 与 `textContent` 渲染，不使用 `innerHTML`。
- 业务确认、选择和编辑使用 `showModal()` 的原生 `dialog`；不得以浏览器 `confirm()` 或 `alert()` 承载业务流程。
- 确认弹窗必须说明对象、直接影响、取消路径和恢复边界。危险操作使用危险按钮；提交中禁用关闭与重复提交。
- 已被后端受理的普通异步操作可以关闭弹窗，进度和最终结果回到所属卡片或页面；直接阻断控制面的维护操作按专项设计在弹窗内等待可确认终态或失败。
- 即时反馈仅承载当前页面可立即判断、用户可立即重试或确认的非阻塞异常和警告。首页在顶部工具栏中间展示；非首页使用可关闭、自动消失的顶部 Toast；首页内嵌的快速交互必须回传给首页工具栏，不能在 iframe 内重复展示。工具栏中的持续错误是底层状态：后续持续错误必须取消旧的短时清理，短时反馈消失后必须恢复先前仍有效的持续错误，不能被过期定时器提前清空或永久覆盖。表单字段校验和弹窗提交失败保留在弹窗内；控件不可用原因由控件自身说明；任务、通知、Session 或服务的持续状态和最终失败必须留在其所属时间线、卡片或状态区，不能只依赖短时提示。
- 折叠卡片只保留标题层和内容层两个直接子容器。标题负责折叠，内容内按钮、链接和表单控件不得触发折叠；必须支持键盘、`aria-expanded`、减少动态效果和本地偏好恢复。
- 原生表单控件优先保留原生弹层。只有有限选项需要展示复杂选中态、说明或禁用项时，才使用现有自定义选择浮层，并保持 `listbox`/`option`、焦点、Escape 和点击外部关闭语义。
- 模型、推理等级和权限的选择器在所有入口统一复用快速交互的双行下拉选项样式：选项第一行展示名称，第二行展示当前默认、能力说明或不可用原因；触发器可按页面采用通用带边框或紧凑样式，但不得为同一类选择器另行省略说明或引入不同的选中态。
- 即时生效控件由控件自身表达当前状态。除失败或会影响判断的重要信息外，不展示常驻“已保存”反馈。
- 桌面双列和手机单列均使用卡片自然高度；文本、按钮和状态不得遮挡或挤出容器。

当前正式首页以左侧导航和右侧主工作区组织；设置页与首页共享侧栏宽度偏好。桌面侧栏折叠时，固定操作图标仍留在主区工具栏；存在用户快速会话时，紧随图标导航横向展示可滚动的紧凑会话按钮，只投影同一份 Session 快照并仅提供切换，不放入新建、重命名、停止、归档或删除操作。窄屏改为单列和图标导航，不显示该按钮组，不能以隐藏业务内容替代响应式布局。

## 5. CSS 层次

公共页面样式只能通过 `templates/partials/app_styles.html` 引用，加载顺序固定为：

```text
tokens.css -> base.css -> components.css -> responsive.css
```

- `tokens.css` 是每个完整主题包、文字大小比例、语义 Token 和设置页预览映射的唯一入口。公共 CSS 只消费语义 Token；主题专属颜色不得回写到组件规则。
- `base.css` 负责基础排版、原生控件、全局可访问性和页面默认行为。
- `components.css` 负责公共组件，以及尚未出现合理归属时的页面规则。
- `responsive.css` 只负责跨断点布局和尺寸调整。

已删除的 `static/app.css` 不得恢复。不要为了目录整齐进行批量搬迁；每次迁移必须保持层叠结果、页面行为和当前主题视觉一致。

## 6. 主题、文字大小与语义 Token 方案

### 6.1 当前状态与目标

当前有效主题为 `standard`、`code-dark` 和 `studio-cyan`。`Standard` 是默认的简约工具型界面，主要文字使用深橄榄绿；`Code Dark` 是共用信息结构和组件语义的深色开发工作台，文字保持中性浅灰；`Studio Cyan` 以深海蓝文字、青蓝强调色和冷静浅色表面组织工作台。主题选择保存在当前浏览器，并同步非敏感 Cookie 供服务端首屏设置 `color-scheme`；无效、过期或不可读取的值必须回退 `standard`，不得为此放宽 CSP。浏览器拒绝写入偏好时，主题仍只在当前页面立即生效，页面必须明确提示其不会持久化。

`app/web/themes.py` 是主题元数据的唯一注册表，定义稳定 `id`、显示名称、说明和 `color-scheme`。服务端首屏、浏览器端有效值校验和设置页选项均从该注册表派生；页面模板只输出注册表提供的数据，不再硬编码主题名称或颜色方案。`tokens.css` 为每个注册主题提供完整包、根语义映射和设置页预览映射。`base.css`、`components.css` 与 `responsive.css` 不保存主题色值；它们只消费第 6.2 节定义的语义 Token。

文字大小同样由注册表维护，当前仅有 `small`（90%）、`default`（100%）和 `large`（110%），无效值回退 `default`。`theme.js` 分别保存主题与文字大小，并同步非敏感 Cookie 供服务端首屏应用；浏览器无法写入时只在当前页生效并提示。文字大小以公共根字号驱动，影响公共页面的 `rem` 排版，终端 PTY 与固定像素触控目标不参与。

### 6.2 主题包定义

一个主题是完整、可注册的 Token 包，而不是对少数强调色的覆盖。每个主题包至少包含：

| 类别 | 必需语义 |
| --- | --- |
| 元数据 | 稳定 `id`、显示名称、`color-scheme`、简短说明 |
| 页面与表面 | 页面背景、内容表面、抬升表面/弹窗、输入表面、代码表面 |
| 文字 | 主要阅读文字、次要说明、禁用文字、反色文字 |
| 线条 | 弱边框、强边框、分隔线、焦点环 |
| 强调 | 主强调、悬停、选中、强调文字对比色 |
| 状态 | 成功、警告、错误、信息的文字、背景和边框 |
| 视觉层级 | 阴影、遮罩、选中与禁用的透明度/对比关系 |

语义名称必须一对一表达用途，具体 CSS 自定义属性名可以随现有命名演进，但不能为同一用途保留互相冲突的主题别名。组件样式应只消费语义 Token；新增以 `.code-dark ...` 等页面或组件选择器直接覆盖颜色的做法默认不允许。确需过渡时，必须在同次改动中说明原因、迁移目标和删除条件。

主题必须同时具备辨识度和可读性：主题身份至少由主要文字、次要文字和主强调色共同形成，不能只改变页面背景；正常阅读状态的主要文字、次要文字、强调文字在内容表面上的对比度，主要文字在代码表面上的对比度，以及反色文字在主强调背景上的对比度，均不得低于 `4.5:1`。禁用状态不承载唯一业务信息，可按控件禁用语义降低对比度；状态信息仍须保留文字、图标或结构提示。

布局 Token 不属于单个主题包。间距、内容宽度、圆角、控件尺寸、断点、动效时长和折叠规则默认跨主题一致；未来若要引入结构化风格，必须单独设计并重新验收，不能借“新增颜色主题”改变信息密度或交互。

主题包不得包含业务文案、路由、API 地址、权限判断、状态机或针对单一业务 Feature 的逻辑。终端 PTY 保持独立的原生终端样式，不参与公共页面主题切换。

### 6.3 主题选择与预览

主题页以单选网格切换主题，无需网络请求。折叠状态的每个主题项展示标题、描述和三枚代表色：

1. 主要阅读文字；
2. 次要说明文字；
3. 主强调色。

代表色的作用是让维护者快速比较文字层级和交互重点，不代替完整 Token。第二枚代表色和预览中的描述必须直接使用该主题的次要文字 Token，正文直接使用主要阅读文字 Token。展开“文字层级示例”后，每个主题使用该主题的内容表面预览卡展示标题、描述、正文、当前选择、成功/处理中/需处理状态、输入表面和主次操作。预览必须从该主题包的同一组 Token 生成，不能使用当前已应用主题覆盖未选中主题的预览。展开偏好保存在当前浏览器。

状态不能只依赖颜色表达；主题预览和真实页面都必须保留文字、图标或结构性状态提示。Code Dark 不使用代码雨、动态背景或主题专属调节项；减少动态效果仍是跨主题无障碍规则。

### 6.4 新增与迁移规则

新增主题或调整既有主题时按以下顺序执行：

1. 清点直接颜色值和主题专属覆盖，区分共享组件、页面局部规则和终端样式。
2. 在 `app/web/themes.py` 登记稳定 `id`、显示名称、简短说明和 `color-scheme`；不得在页面模板、`theme.js` 或组件 CSS 另行维护有效主题列表。
3. 在 `tokens.css` 补齐完整主题包、根语义映射和设置页预览映射，并确认所有既有主题的同一语义仍完整、可读。
4. 新增组件只消费语义 Token；修改旧组件时同步删除出现的主题专属颜色覆盖。
5. 仅在所有已注册主题完整通过同一组件和预览矩阵后，才增加或调整主题。
6. 不引入“旧颜色 + 新 Token”双轨路径；例外必须限于终端等明确排除的独立样式，并写明边界。

注册新主题必须同时提供完整 Token 包、主题元数据、根语义映射、折叠代表色、展开预览、桌面和手机回归结果。注册表会提供有效值校验和首屏应用；新增主题不得为了这些步骤修改公共页面模板或 `theme.js`。切换主题不得重置当前分区、会话、表单草稿、折叠偏好或页面数据。

### 6.5 文字大小验收规则

文字大小是跨主题的独立外观偏好，不属于任何一个主题包。选择上述固定档位不得发起网络请求、重置主题、刷新页面或改变数据。公共文字层级必须使用 `rem`，不得通过 `vw`、`clamp()` 或负字距绕过该比例；布局可继续单独使用视口相关尺寸。

实现或排障时按以下分类检查，不以单个字号值替代整体可读性判断：

| 类别 | 包含内容 | 验收重点 |
| --- | --- | --- |
| 层级标题 | 页面标题、区块标题、卡片标题 | 层级保持清晰，不截断或覆盖相邻内容 |
| 阅读文字 | 正文、说明、表格与详情 | 小档仍可阅读，大档不产生横向溢出 |
| 操作文字 | 普通按钮、导航、选择项、表单控件 | 文本在固定控件内完整可见，触控目标不缩小 |
| 辅助信息 | 描述、状态、时间、标识和禁用提示 | 不成为唯一状态表达，仍保留原有对比和结构提示 |

新增文字等级时必须先在注册表登记稳定 ID、名称、说明和正比例值，再补齐 `tokens.css` 根比例映射、服务端首屏属性、浏览器有效值校验和设置页选项。若新增等级会改变断点、控件最低尺寸、信息密度或终端显示，属于独立设计，不能作为普通文字大小扩展直接加入。

## 7. 维护与验收

新增或调整前端功能时：请求、状态、缓存和渲染优先留在所属 Feature；共享请求和页面生命周期由协调层承担；只有多个真实功能稳定复用时才增加 Component。不得借目录拆分引入空泛抽象、事件总线或状态管理框架。

涉及主题、公共组件、加载顺序或响应式布局时，至少确认：

- 所有已注册主题和文字大小均保持可读的文字层级、状态区分、焦点可见性和无横向溢出；
- 主题折叠项与展开预览和实际组件使用一致 Token，且切换无需网络请求、不丢失页面状态；
- 项目资料和周报的行内代码、命令块使用代码表面、主要文字和边框 Token；长行仅在代码块内横向滚动；
- 快速交互在桌面和 `360x800`、`412x915` Android Chrome 视口可用，软键盘下输入区不被遮挡；设置页主题、文字大小选择与预览在桌面及同一手机视口无横向溢出；工作台至少在桌面与 `390x844` 窄屏验证；
- 调整即时反馈时，验证独立页 Toast 的展示、关闭和自动消失，以及首页工具栏反馈的警告色、短时清理与后续常驻错误接管；
- 键盘操作、原生 dialog、折叠语义和“减少动态效果”仍有效；
- 变更脚本/样式加载边界时，顺序测试和受影响页面的真实浏览器回归通过。
