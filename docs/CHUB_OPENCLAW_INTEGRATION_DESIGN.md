# Chub–OpenClaw 接入设计

> 状态：持续维护。本文描述微信 ClawBot 单入口调度、微信专用任务、完成通知和安全边界，并记录已确认的近期架构调整；具体能力状态与插件部署状态分别以能力清单和插件说明为准。当前 Session 命名、指令路由、独立 Worker 与跨 Web 重启恢复已在 macOS、Ubuntu 完成验收。

当前可用插件、插件能力、固定 API 和消息路由统一登记在[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md)；本文只解释其架构与行为边界。

## 1. 当前架构

Chub 与 OpenClaw 当前提供四类能力：

1. Chub 管理本机 OpenClaw Gateway；首页展示 Gateway、消息通道和访问入口，Owner 检查结果合并到通道与总体状态中。
2. OpenClaw Agent 通过受限 Tool 查询 Chub 状态或发送飞书通知。
3. 微信 Chub 模式在模型调度前拦截符合条件的私聊，只调用 Chub 单一调度入口；固定后端路由执行只读查询、白名单维护操作或受控任务续提，其他非空业务正文按普通任务处理。
4. 微信 Chub 任务结束后通过任务保存的 ClawBot 路由发送最终结果；页面快速交互只有在完成通知和全局收件人均已配置时才发送微信结果。任务摘要只是提交状态和最终消息中的关联信息。

```text
OpenClaw Agent 能力（TUI 或未进入微信 Chub 模式的消息）
  OpenClaw Agent -> chub_get_status | chub_send_notification -> Chub

微信 Chub 模式（当前实现）
  微信私聊 -> before_dispatch -> Chub 统一消息调度接口
           -> 模式检查 / 固定后端路由 / 普通任务提交
           -> 普通任务进入 Chub 快速交互 -> Quick Worker -> Codex CLI
           -> Hook 同步原路交付 Chub 回执
           -> 任务结束后由 Chub 使用 openclaw message send 发送最终通知

页面快速交互通知
  Chub 快速交互 -> openclaw message send -> 全局固定微信收件人
```

微信 Chub 模式的同步调度回执由 Hook 原路返回；异步最终结果、微信任务重启结果、微信固定重启指令结果和页面完成通知使用 `openclaw message send` 投递。两条路径都不调用 `openclaw agent`，也不得借此触发新的设备操作。Chub 直接发送飞书则调用自身 Notification Service，不经过 OpenClaw。

以下状态必须独立判断：

| 状态 | 含义 |
| --- | --- |
| Gateway 正常 | 后台服务、进程、端口和 RPC 正常 |
| Channel 正常 | 微信插件和本地通道进程正常 |
| ClawBot 已绑定 | 微信服务端当前仍绑定这台 Gateway |
| Owner 已配置 | 指定微信身份具有 Owner 权限 |
| Chub 模式就绪 | 固定配置、工作区、Codex、模型和完成通知开关满足启动条件；实际 ClawBot 路由在任务提交时校验 |
| 任务或 Tool 成功 | 已取得目标能力的最终结果 |

同一个 ClawBot 同时只能绑定一台 Gateway。在另一台设备重新扫码后，旧设备可能仍保留本地 Channel 和 Owner 信息，最终状态以真实微信收发为准。

## 2. 安装与状态

macOS 使用 launchd，Ubuntu 使用 systemd user service。OpenClaw 可通过官方安装脚本或已有 Node.js 环境安装；初始化后由 OpenClaw 自身管理 Gateway 服务：

```bash
openclaw --version
openclaw doctor
openclaw onboard --install-daemon
openclaw gateway status --json
openclaw gateway probe
```

安装并启用微信插件：

```bash
openclaw plugins install "@tencent-weixin/openclaw-weixin"
openclaw config set plugins.entries.openclaw-weixin.enabled true
openclaw gateway restart
openclaw channels login --channel openclaw-weixin
```

最后一条命令生成绑定二维码；Chub 首页“OpenClaw 环境”卡片也使用同一固定命令提供二维码和验证码流程。绑定只建立消息通道，不自动完成发送者配对或 Owner 授权。

常用只读检查：

```bash
openclaw gateway status --json
openclaw gateway probe
openclaw channels status --probe --json
openclaw config get commands.ownerAllowFrom
openclaw exec-policy show
openclaw config validate
```

Chub 首页卡片只提供 Gateway、消息通道、Tailscale 访问入口、固定启停、重启和微信绑定，不单独展示 Owner 身份或数量，也不提供安装、升级、任意命令、配置正文或原始日志。Owner 未配置或检查失败会进入通道提示和总体“功能受限”状态。卡片刷新失败时保留最近成功内容；卡内操作以最终状态结束，不把子进程创建视为成功。

## 3. 身份与权限

当前采用可信单用户策略：一个健康 ClawBot 和一个获准的微信 Owner 发送者。扫码、发送者配对与 Owner 权限是三个独立步骤，不得批准未知请求。

普通 OpenClaw Agent 路径使用 Gateway 的 Shell 审批和文件边界：

- 当前电脑使用 `host=gateway`；只有明确指定已配对 Node 时才使用 Node。
- Shell 默认按白名单执行，未命中时审批，审批不可用或超时则拒绝。
- 不将 `bash`、`sh`、`zsh`、`python`、`node`、`osascript` 等通用解释器整体加入持久白名单。
- 无关任务不得读取凭证、密钥、密码库、系统钥匙串、浏览器登录数据或其他敏感路径。
- 对敏感数据的修改、移动、删除、轮换或外发必须先说明准确目标并取得明确确认。

这些是模型和应用约束，不是操作系统级隔离。如果允许其他微信身份或不可信输入访问，必须重新评估 Sandbox、独立 Agent 和文件工具权限。

微信 Chub 模式是单独批准的例外：固定 Tailnet 内的单一 Owner 可以通过微信通道当前绑定 Session 使用 `Full access`，不逐条审批。该权限随受控绑定关系生效，不属于 Session 的永久属性，也不扩展到其他账号或入口；关闭微信 Chub 模式即可撤销入口。

## 4. Chub OpenClaw 插件

插件源码位于 `integrations/openclaw/chub/`，负责 OpenClaw Agent 的受限 Chub Tool、微信私聊转发和飞书通知原文保护。
当前能力名称和状态只在[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md)中统一登记；插件协议、构建、部署、最小验收和协议升级同步清单以[Chub OpenClaw 插件说明](../integrations/openclaw/chub/README.md)为准。

插件只使用固定 Tailnet `baseUrl`、固定 API 路径、严格 Schema、受控超时和有界响应，不配置 Hub Token，也不接受任意 URL、文件路径或命令。飞书原文保护的会话访问必须显式开启，只用于按当前 `runId` 取得用户明确提供的通知原文，不改变微信 Chub 消息调度权限。

仓库内 `integrations/openclaw/chub/` 是插件的唯一源码和发布来源。OpenClaw 运行经过构建验证后安装到用户扩展目录的部署副本，不得直接修改运行副本形成仓库外实现。协议不兼容变更时，插件与 Chub 必须配套切换；版本不一致时失败关闭，不回退 Agent。

微信链路只调用一个固定接口：

```text
POST /api/openclaw/wechat-chub-mode/dispatch
```

请求固定携带协议版本 `3`，用 `content` 携带干净正文、用 `message_type` 区分可信的 `text` / `voice` 来源；响应只使用同版本的 `pass` / `reply` / `handled` 交付决定和 Chub 生成的有界 `message`，不暴露业务状态码。`handled` 仅表示 Chub 已完成本次同步路由、插件无需额外回复，不代表后台通知已经送达。版本不匹配时失败关闭，插件只执行交付决定；Chub 独立负责业务判断、同步文案以及异步任务结果和重启结果，双方不得重复发送同一阶段消息。

插件只负责部署开关、微信私聊范围、可信账号与发送者、原始正文、语音来源归一化、幂等标识、固定 Tailnet 地址、超时和有界响应。它不识别业务指令，不检查 Codex 或 Session 状态，不生成或修改任务摘要、提交状态和业务失败文案，也不让正文指定动作、接口、任务编号、Session、权限、模型、路径或命令。正文为空且没有可信语音转写时，插件在调用 Chub 前返回固定的内容识别失败提示；Chub 不可达、协议不匹配或响应无效时仍只返回统一通道失败，不解释具体业务原因。

Chub 统一调度接口处理模式关闭时放行、固定后端路由和普通快速交互提交；固定后端路由包括只读查询、白名单维护操作和受控任务续提，当前能力和指令名称登记在[Chub 集成能力清单](CHUB_INTEGRATION_CAPABILITIES.md)，匹配与执行规则由本文维护。

插件使用 `weixinChubMode` 部署开关。Chub 与插件使用同一版本化调度协议；版本不匹配时明确失败，不回退 Agent。

## 5. ClawBot 统一调度与绑定任务

### 5.1 模式与路由

Chub 配置 `openclaw.weixin_chub_mode` 决定业务状态和当前绑定 Session 的匹配条件：

```yaml
openclaw:
  weixin_chub_mode:
    enabled: false
    workspace_id: "chub"
    permission_mode: "full-access"
    model: null
    reasoning_effort: null
```

插件配置 `weixinChubMode` 只控制 OpenClaw 是否启用统一转发，Chub 配置控制业务模式。当前行为为：

| 插件路由 | Chub 模式 | 微信私聊行为 |
| --- | --- | --- |
| 关闭 | 任意 | 保持原 OpenClaw Agent / LLM 流程 |
| 开启 | 关闭 | 调用统一接口，由 Chub 返回放行 |
| 开启 | 已启用 | Chub 执行已登记的固定路由，其他非空正文提交普通任务 |
| 开启 | Chub 不可达或响应异常 | 返回受控失败，不回退 Agent / LLM |

Chub 先匹配能力清单登记的固定路由，命中后由固定后端能力处理；未命中的非空正文才提交普通任务。具体指令和中文别名登记在[能力清单](CHUB_INTEGRATION_CAPABILITIES.md)，匹配规则和用户可见结果由本文维护。插件不识别业务指令，消息正文也不能指定内部 Session ID、任务编号、接口、路径、权限、模型或任意系统命令。

固定指令默认要求整条消息匹配，英文指令不区分大小写。`restart` 与 `重启` 只接受完整指令，不接受附带正文；微信正文中的旧 `chub restart` 不再属于固定路由。`session new`、`新建会话`以及指定槽位的 `session switch N`、`切换N`、`切换会话N`、`会话N` 可以在指令后附带非空任务正文，例如“切换 2，检查日志”或“会话 2 检查日志”；边界接受空格或常见中英文标点，只移除一层分隔符并保留正文自身的路径、隐藏文件、Markdown 前缀和末尾标点。`N` 只接受 Chub 分配的 `1`–`9` 槽位，中文切换和归档同时支持一至九。无编号的 `session switch`、旧 `codex ...` 指令和其他未匹配正文按普通任务处理。

Session 使用 1–9 持久化槽位向微信用户提供稳定的受控目标。`Available` 可立即接收任务，`Busy` 可切换但不能接收新任务，`Unavailable` 保留已占编号但禁止切换。创建、切换、归档、补位和释放必须复检实时状态并原子更新；失败或结果不确定时不得提前改变槽位或绑定。单个 Session 始终只有一个 writer，不因多个 Session 可并行而放宽单 Session 写入互斥。

### 5.2 状态快照与维护操作

> 本节记录 Chub 状态总览和维护操作的现行可靠性边界；当前可用指令以[能力清单](CHUB_INTEGRATION_CAPABILITIES.md)为准。

ClawBot 中的 `chub` 是 Chub 全局状态入口，不经过 Agent 或 LLM。每次查询现场采集系统和当前已分配 Session，读取本地任务状态，并通过统一 AI 用量服务读取至多缓存 5 分钟的额度快照；它不附带指令列表，不扫描或调整槽位，也不触发失败通知补发。`chub refresh`、`chub -f` 和 `刷新状态` 不再属于固定路由。裸 `codex` 不属于固定路由，按普通任务处理；Codex Session 的明确操作指令继续使用固定白名单路由。

状态快照按系统、微信任务、Session 和 AI 用量分区维护。各分区独立记录最近成功值和采集时间；某一分区失败不能清空或阻塞其他分区。Chub 启动后异步初始化系统和 Session 等本地分区，不预取 AI 用量；AI 用量按需读取共享缓存。

任务计数在查询时读取已与 Worker 对账的本地任务投影，Session 快照由本地 Session 操作更新，并在展示时用当前快速交互运行态覆盖 `Busy`。每次 `chub` 查询并行采集系统状态、当前已分配 Session，并读取统一 AI 用量服务；系统和 Session 的并发查询共享正在执行的同一次采集，AI 用量独立遵循 5 分钟缓存、8 秒总预算和同次刷新合并规则。启动初始化缓存只用于服务刚启动和采集失败时兜底，不在用户总览中暴露缓存年龄或刷新机制。内存或磁盘达到 85% 时进入总览告警；不使用 CPU 瞬时值触发首版告警。后续调整这些规则时必须同步本文和相关测试，不能允许消息正文覆盖。

Web 投影必须直接反映能够确定的变化：每次查询从已恢复的快速交互状态汇总任务与通知计数；任务执行终态和 Session 租约以 Worker 为准，Session 创建、切换、归档和槽位同步更新 Web 快照，查询时再覆盖正在运行的 Session。系统状态和 Codex 用量等依赖外部采集的数据可以在内部标记失效；默认查询仍返回最后成功值，不因失效隐式刷新，也不把缓存状态作为用户异常。

状态刷新在统一调度全局锁外采集数据，并遵循以下约束：

- 同一时刻只执行一次刷新，并发请求共享该次结果；该次结束后的下一条查询重新采集。
- 刷新受微信同步请求总预算限制；超时返回已有快照，不把刷新异常或单个数据源失败扩大为整条请求失败。
- 刷新完成后只合并本次取得的分区，不使用采集前的完整状态覆盖期间发生的任务、绑定或槽位变化。
- 状态查询的调度锁只用于路由、统一幂等检查和短时状态提交；实时采集中的慢速账户读取、Session 扫描和总览格式化不得长期持有该锁。
- 状态刷新只读取系统、任务、当前已分配 Session 和 Codex 用量；它不扫描或分配等待候选，候选扫描只属于槽位同步。

槽位同步只由英文指令 `sync` 或中文别名 `同步状态`、`状态同步` 显式触发，是独立写操作，同一时刻只执行一次。已移除的 `chub sync`、`chub -s`、`补充槽位` 不再属于固定路由，按其他未匹配正文进入普通 Codex 任务。同步先执行两次完整扫描确认候选稳定，再在提交锁内复检固定配置、原槽位和当前绑定均未变化；任一依据变化或写入无法完整确认时放弃本次写入，不提交部分变更。有效映射保持原编号，空槽按数字从小到大补充；候选依次使用当前有效绑定、已有微信任务历史和内部 Session ID 稳定排序。同步不创建、归档或切换 Session；当前绑定失效时只清除绑定。普通状态查询不能隐式改变槽位。槽位候选选择与用户可见列表排序相互独立，后者统一按创建时间倒序展示。

`restart` 与 `重启` 是微信 Owner 的显式高权限 Web 重启入口。Chub 在登记前校验本次 Hook 保存的真实 ClawBot 账号和发送者路由，持久化入口消息、操作 ID、协调器操作和通知状态，然后同步回复“重启已登记”；未能确认原路回送或持久化时不宣称受理。固定指令复用现有串行重启协调器，不调用 Agent、不创建 Codex 任务，也不直接从请求线程操作服务管理器。旧实例为同步回执保留短暂发送窗口，新实例在实例 ID 变化且本机健康检查通过后，使用该操作保存的账号和发送者发送独立最终结果。重复消息复用首次回执，同一路由已有重启时不重复登记；与任务级重启合并时保留该任务原有完成与通知屏障。最终结果发送采用至多一次状态，发送中再次中断时标记失败且不自动重试；失败记录进入该微信路由的 `chub` 异常摘要，不回退全局收件人。

槽位同步的业务终态只由槽位写入结果决定。回复应保存清理、补充和最终槽位数量及操作后的列表；没有变化时明确回复“槽位无需调整”。扫描或写入无法完整确认时不提交部分结果，也不附带可能失真的列表；重复消息重放首次结果。同步已完成但附带状态生成失败时必须报告部分成功并提示重新发送 `chub` 查看总览，不得把已确认的写操作伪装成失败或再次执行。

高频只读查询仍需按微信消息标识返回稳定结果，但其短期去重记录不能挤占普通任务和维护操作的长期幂等容量。涉及副作用的维护操作继续执行 `requested`、`started`、`succeeded` 或 `failed` 操作日志；缓存读取本身不得伪装成数据源已刷新成功。

状态总览只返回当前受控身份可见的非敏感摘要，不暴露主机名、Session ID、路径、权限、模型、路由或错误原文。首行使用 `Chub · <耗时>` 展示本次现场状态采集耗时：小于 1 秒显示整数 `ms`，达到 1 秒后显示一位小数的 `s` 并去掉多余 `.0`，例如 `10ms`、`1.3s`、`10s`；不再展示 `Active/Limited`。功能受限仍由异常区给出明确原因。正常状态除此之外只展示 Session 列表和 Codex 用量；系统资源、零任务计数、正常更新时间和就绪说明隐藏。异常按序号集中展示，只包括功能受限、资源告警和通知失败。Session 状态由 Sessions 列表表达，Codex 可用性由 Codex 主体表达；没有可用内容时显示“暂不可用”，缓存不可用、过期、刷新失败或超时等内部数据状态不进入异常区。所有 Session 列表按创建时间倒序展示，内部 Session ID 仅作为同一创建时间的稳定兜底；微信列表仍只包含已分配槽位且不改变槽位编号，固定使用 `S<槽位> · 标题` 和独立状态行，当前槽位在状态后追加 `Current`。Busy Session 仅在能从当前可信微信路由确认运行中的快速交互任务时，以 `T<槽位> · 摘要` 显示有界脱敏摘要；终端或其他入口造成的 Busy 不猜测任务内容。`S`、`T` 前缀不使用点号，避免微信把多行状态重新解释为有序列表。当前单 Owner 场景可汇总其关联的全部 Session；未来支持多个 Owner 时，任务和 Session 快照必须按可信身份边界隔离，不能直接暴露节点全局详情。

任务完成通知和任务级重启结果继续使用独立的精简 Codex 状态快照，不调用或嵌入完整 `chub` 总览，避免把任务通知状态递归带入通知正文。该内部快照只展示关联 Session 所需的用量与槽位状态，也不得隐式补位或触发通知补发。状态总览、Session 维护回执和该精简快照共用统一 AI 用量服务生成的 `Weekly 78% · Today 100M` 短格式；今日 Token 不可用时只显示 `Weekly 78%`，不展示不可用占位。Session 维护回执和重启快照先展示 `Sessions`，AI 用量固定放在最后。

当前正常总览示例：

```text
Chub · 10ms

Sessions

S1 · 项目维护

T1 · 检查设备状态

Busy · Current

S2 · 日志检查

Available

Codex

Weekly 35% · Today 81.8M
```

出现资源或通知异常时，在主信息前增加编号异常区，仍保留可用主体：

```text
Chub · 10ms

异常
1. 内存使用率较高：87%
2. 1 个任务结果通知失败

Sessions

S1 · 项目维护

Available · Current

S2 · 日志检查

Unavailable

Codex

Weekly 35% · Today 81.8M
```

本节的关键验收条件为：

- 连续发送 `chub` 时每次重新采集现场状态，但不改变槽位或通知状态。
- 并发状态查询共享同一次采集，采集结束后的下一条查询重新刷新；慢数据源和单分区失败保留其他可用快照。
- 状态采集不长期占用调度锁，不阻塞普通任务和固定维护操作。
- `sync`、`同步状态` 与 `状态同步` 使用稳定顺序原子更新槽位，失败不提交部分结果，重复消息不再次执行；`chub sync`、`chub -s`、`补充槽位` 进入普通任务。
- 固定指令按本节规则匹配，裸 `codex` 和其他未匹配正文进入普通任务。
- 状态查询不重新登记失败通知；完成通知和任务级重启通知使用独立精简状态，不受总览失败影响。

### 5.3 提交状态与任务摘要

普通文字和可信语音任务受理后均静默处理，不发送“任务已提交”或语音识别内容回执，完成后再原路发送最终结果。提交失败仍立即返回明确失败原因。静默只表示 Chub 已完成安全校验、幂等预留和后台任务建立，不代表任务成功；最终状态以快速交互结果为准。

任务摘要由 Chub 从首个有效句子确定性提取，统一为单行并限制在 20 个 Unicode 字符；超出时保留前 19 个字符并追加省略号，不调用 Agent 或 LLM。摘要过滤内部语音标记、控制字符并遮蔽明显的 Bearer、Token、Authorization、Cookie、Secret、Password 和 Webhook 值；生成后随任务持久化，页面、提交状态、最终结果、分段结果和重启结果复用同一份摘要。

微信任务提交时同时保存 Session 槽位、内部 Session 关联和有界脱敏标题快照。完成回送使用 `Session：3 · 服务检查` 标明上下文；若发送时槽位已释放或复用，则追加“已不可切换”。数字槽位只在 Session 未归档期间稳定，历史消息中的已复用编号不承诺继续指向原上下文；切换本身不提交任务，并返回使用 `S<槽位> · 标题`、独立状态行及 `Current` 状态后缀的完整列表供确认。

可信微信语音转写进入任务正文时保持干净，不把内部来源标记交给 Codex。文字和语音任务成功提交及已成功任务的重复消息均静默处理；插件仍传递可信类型并执行 Chub 的交付决定，不自行生成提交回执。

### 5.4 语音转写可信来源

腾讯微信插件可能把带转写的语音消息转换为普通正文，导致 Chub 插件无法仅凭正文区分语音转写和用户键入文字。微信通道适配必须保留可信来源，并满足：

1. 只有上游消息项类型确认为语音且包含非空转写时才设置内部来源标记。
2. 进入任务和原 OpenClaw Agent 流程的正文始终是干净转写；内部标记只用于 Hook 识别，不进入任务正文、摘要、日志或对外接口。
3. Chub 插件只有同时取得可信标记和不同的干净正文时才向 Chub 发送 `message_type: voice`；用户键入相同标记仍按 `text` 处理。
4. 普通文字和可信语音任务成功提交后均静默处理；提交失败仍由 Chub 返回明确失败原因，插件不参与判断或拼接。
5. 入站事件没有可处理文字且未取得可信语音转写时，插件不得提交空正文，固定提示重新发送文字或稍后重试语音；不得把该情况描述为 Chub 消息通道不可用。
6. 插件继续验证 Chub 响应边界并按 `pass` / `reply` / `handled` 决定原样交付。

微信插件升级、重装或实际加载目录变化后，先用 `openclaw plugins inspect openclaw-weixin --json` 确认运行来源。若上游已提供可信语音来源和干净转写，应直接适配上游字段；否则按 `integrations/openclaw/patches/weixin-clawbot-voice-transcript-origin.patch` 恢复等价能力。应用前必须 dry-run，同时维护仓库参考补丁和实际构建产物，不得只修改运行目录。完成后重载 Gateway，并分别验证普通文字、真实短语音、普通文字伪造标记、重复语音和模式关闭场景。

### 5.5 信任与权限

当前部署固定为同节点 Chub 与 OpenClaw、单一微信 Owner、单一健康 ClawBot：

- 统一调度接口只接受来自 Chub 当前节点真实 Tailnet socket 的请求，不接受 Hub Token 或转发 Header 替代。
- 微信消息只能提供正文，不能指定 Session、工作区、权限、模型、推理等级、文件路径、命令、接口或回送目标。
- 回送账号和发送者只能来自 `before_dispatch` 的可信通道上下文，并在普通任务提交前确认对应账号是唯一健康 ClawBot。
- 群聊、缺少稳定消息标识、缺少回送路由或路由不可信时不进入 Chub 任务。
- `Full access` 例外只适用于固定 Tailnet、当前单 Owner 和微信通道当时的绑定关系；Session 本身仍是普通 Chub Session，解除绑定后不保留微信入口授权。

当前不支持第二个 Owner、多个并行 ClawBot 或跨节点提交，也不能通过放宽现有配置绕过身份认证、Session 隔离和调用方边界。

### 5.6 Session 复用与写入互斥

普通微信任务默认复用 Chub 保存的当前绑定 Session，以保留 Codex 上下文。Session ID 只保存在 Chub 私有状态中，不向 OpenClaw 或微信消息暴露；用户只能通过固定编号路由在实时可绑定列表中切换。

文本优化与翻译镜像默认关闭，本机配置决定首次默认值；之后可在 Chub 设置页通过受保护接口即时启停，选择写入 Chub 私有状态，不改写本机 YAML。启用后，普通业务任务会镜像到一个由内部角色标识关联的固定翻译 Session。该 Session 使用独立运行目录和 `read-only` 权限；当前浏览器偏好统一决定内部翻译 Session 是否在首页、快速交互导航及其他 Session 可见列表中展示，列表接口默认隐藏并只在偏好开启时显式包含。翻译 Session 固定使用快速交互入口并禁止实时终端，不进入 1–9 槽位或成为当前绑定。关闭只阻止新翻译，已排队或执行中的翻译继续完成；再次开启时使用新的翻译 Session。旧 Session 在所属任务及通知完成后尽力归档；失败时保留清理记录，并在后续启动或翻译状态变化时重试。执行新翻译时只复用仍存在且未归档的原生 Session；绑定缺失、已归档或不可确认时创建新 Session，不自动恢复已归档 Session。Chub 将 JSON 编码后的原文作为不可信数据交给 Codex，只接受严格的非空“润色”和“English”两段输出，最终由 Chub 组合原文、润色和英文并原路回送。翻译任务使用有界持久化顺序队列，是不影响业务任务的尽力而为辅助能力；只有成功结果需要回送，登记、执行、取消和通知失败均静默记录。`read-only` 只禁止模型修改文件，不能把提示词视为对本机可读内容的强隔离；维护者应在接受该模型信任边界后再启用。

设置页读取或保存结果不确定时以服务端回读状态为准；私有状态文件损坏、不可读或权限保护失败时，状态接口和新翻译均失败关闭，页面保持开关禁用。只有存在排队或执行中的翻译时才短暂轮询任务状态，归零后停止并清除提示。

- 绑定不存在或配置不匹配时，在下一次普通任务提交时按固定配置创建并绑定；暂时忙碌或不可提交不触发新建。
- 切换只影响后续任务；原 Session 上的任务继续执行并使用任务保存的微信路由回送，因此不同 Session 可以并行执行微信任务。
- 同一原生 Codex Session 同时只允许一个 writer，不维护额外消息队列。
- 已有快速交互、明确执行中或 writer 仍被占用时拒绝新的普通任务，不中断现有任务。
- 因当前绑定 Session 忙而拒绝时，只在私有状态中保留最近一条任务正文 10 分钟；用户可使用 `session retry` 在当前 Session 续提，或使用 `session new retry`、`新建会话执行`新建并续提。
- `session new`、`新建会话`以及指定槽位的中英文切换指令可附带本条任务正文，把现有 Session 操作与任务提交合并为一次显式操作。指令和正文之间接受空格或常见中英文标点，只消费边界的一层分隔符并保留正文自身的路径、隐藏文件和 Markdown 前缀；新建或切换失败时不提交，切换并执行只接受 `Available` 目标。归档及待续提指令不接受附带正文；待续提指令误带正文时固定拒绝且不改变原待续任务。
- `session switch N` 只认 `S1`–`S9` 持久槽位，不把展示位置重新解释为槽位编号；无参数形式不再提供循环切换。
- Session 创建路径不再写入“微信 Chub”或其他预设标题；空标题在首页、终端页和微信状态中统一显示“未命名 Session”。首次实际任务提交后仍由快速交互使用首条任务命名，后续任务不再改名。
- 待续提任务使用可信微信路由摘要隔离，新的忙碌拒绝覆盖旧项；领取、提交和清除受持久化状态及消息幂等约束，结果不确定时不自动重放。
- 当前绑定 Session 状态为 `unknown` 时，Chub 可以撤销页面票据、停止残留终端，并在确认 writer 释放后提交；失败时保持关闭，不并行 `resume`。
- 任务级协调重启不等待翻译队列、执行或通知，Web 实际停止前仍可接收新翻译。已经由 Quick Worker 接受的排队
  或执行中翻译不会因 Web 重启取消或重放，新 Web 恢复同一任务引用、队列投影和通知观察；Worker 身份或
  任务关联无法确认时保持失败关闭，不猜测成功或创建替代任务。
- Writer 探测依赖 `CODEX_HOME/thread-writer-locks/` 的只读兼容边界，Codex CLI 升级后必须回归。

状态总览按微信任务保存的原路账号和发送者汇总执行与通知状态，不承担补发副作用；失败通知保留独立失败终态，当前不提供微信补发指令或后台自动重试。未来若恢复补发能力，必须使用原任务保存的可信路由，并作为独立显式操作重新设计。

### 5.7 幂等与状态

OpenClaw Hook 当前不提供微信平台原始消息 ID。插件使用固定通道上下文、账号、会话、发送者、时间戳和原始正文生成 SHA-256 消息标识；缺少稳定时间戳时失败关闭。

Chub 在产生副作用前持久化统一调度预留：

- 相同消息标识和相同路由复用首次处理决定；已成功提交任务的重复投递静默处理，不重放首次回执，也不重复执行 Codex 任务。
- 相同消息标识携带不同路由时返回冲突。
- 首次失败会被记录，重复消息不自动重试。
- 服务重启时未完成的副作用预留转为固定失败，避免不确定状态下重复执行。

幂等历史最多保留 5000 条且不超过 8 MiB，只保存回送路由摘要，不保存任务正文或原始账号。完整任务和任务级路由保存在权限为 `600` 的快速交互私有状态中；接口、页面和操作日志不返回原始路由。

统一调度、任务提交、Session 回收、Codex 终态和微信通知分别记录自己的状态。消息被拦截、HTTP 返回成功或后台任务建立都不能代替任务和通知的最终结果。

## 6. 微信完成通知

任务成功、失败或超时后进入完成通知流程。微信 Chub 任务使用任务保存的原路路由；页面快速交互只有在完成通知和全局收件人均已配置时发送，否则记录为跳过。普通结果在单条上限内完整发送，不附加页面跳转提示；超过 `max_message_chars` 时优先按段落编号分段，最多 5 条，超过总量才截断并提示到快速交互页面查看。整批通知共用一个超时，全部送达才记录为已发送；中途失败记录已送达数量并停止，不自动重试。状态查询不重新登记失败通知，当前不提供替代补发入口。通知状态独立记录为发送中、已发送、失败或跳过，通知故障不改变任务最终状态。

快速交互触发任务级 Web 重启时，只等待请求任务自身的完成结果和通知终态，不等待其他 Session、快速任务或翻译。新实例通过本机健康接口确认实例 ID 已变化后，只有微信 Chub 来源任务会按任务保存的账号和发送者再发送一条重启结果；成功文案、关联 Session、关联任务摘要、Codex 用量和 `Sessions` 各区块之间保留空行，`Sessions` 标题与列表连续展示。状态区块使用独立的精简 Codex 状态快照，包含状态行中的 `Current` 后缀和已分配 Session 状态，不依赖任何用户状态指令，也不补入等待候选。页面来源只更新快速交互时间线。重启结果通知使用独立的至多一次状态，发送中再次中断时不自动重试，失败不改变任务或重启结果，也不切换到全局目标；启动或健康确认失败时保存并展示具体原因。

两类路由严格隔离：

- 页面来源使用 `openclaw.quick_interaction_completion.weixin_recipient`；账号默认选择唯一健康 ClawBot，`weixin_account_id` 只作为兼容性覆盖。
- 微信 Chub 任务保存本次 Hook 提供的账号和发送者，完成时只按该路由回送。

微信任务的路由缺失、账号停止或投递失败时不切换到全局目标。收件人需要先主动向对应 ClawBot 发送消息，使微信插件获得该账号与收件人的 Context Token。当前按约 10 分钟有效的实测口径维护；超过该时间没有新的微信入站消息时，主动通知可能失败，出站消息不会续期，用户再次向同一 ClawBot 发送消息后才会刷新。该时间不是上游公开承诺的精确 TTL。

当前微信插件需要持久化 Context Token，并在通道启动实例与出站模块实例隔离时支持磁盘惰性恢复；还必须保留本文件定义的语音转写可信来源。日常 Gateway 重启和 ClawBot 重新绑定不要求重复打补丁；微信插件升级、重装、安装目录重建或兼容性检查失败时，应重新识别上游能力并只恢复缺失部分。Context Token 规则见[微信 ClawBot Context Token 持久化 AI 补丁规范](WEIXIN_CLAWBOT_CONTEXT_TOKEN_AI_PATCH.md)。Chub 首页不得自动修改第三方插件、重启 Gateway 或发送探测消息。

## 7. 飞书通知

通知目标注册表和 Secret 保存在本机用户配置目录，权限分别为 `700` 和 `600`，不得提交到 Git。Chub 提供固定 CLI 和受保护 API：

```bash
chub notification validate
chub notification list
chub notification test --target <target>
chub notification send --target <target> --message <text>
```

- Codex PTY 和 Chub 快速交互直接使用 Chub CLI 或通知 API。
- OpenClaw TUI 及未进入微信 Chub 模式的 Agent 使用 `chub_send_notification`。
- 默认不提醒任何人；指定人员只能使用目标预配置的别名，`@所有人` 必须由用户明确要求且目标允许。
- 用户明确提供“消息内容”时使用 `verbatim`，插件按当前 `runId` 关联进入模型前的原文；无法取得可信原文时拒绝发送。
- 只有用户要求 AI 撰写、总结或改写时才使用 `generated`。
- 飞书返回接受只表示 Webhook 已接受请求，不表示群成员已读。
- 日志不记录正文、Webhook、Token、Authorization 或完整 Open ID。

## 8. 运维与故障判断

HTTP 200、进程创建、Tool Call 发起、微信进度提示或本地 Channel 正常都不能单独证明操作成功。Gateway 操作检查最终实例和健康状态；微信绑定检查真实收发；Chub 任务、通知和飞书发送分别使用各自最终状态。

`openclaw channels status --probe --json` 的 `lastOutboundAt` 当前可能在消息实际发送成功后仍为空，因此只能辅助判断通道配置和运行状态，不能作为送达凭据。Hook 同步回执优先查看微信通道的 `text sent OK`，异步最终结果查看 Chub 快速交互和微信通知终态；最后仍以用户实际收到消息为准。

当前链路使用 Chub 私有状态把非敏感消息标识、OpenClaw 会话关联、Chub 操作 ID、快速交互任务和通知终态串联起来；OpenClaw 与 Chub 的独立运行日志主要依赖时间窗口交叉定位，能够支持当前单 Session 场景排障。日志不记录正文、完整账号、完整收件人、Session Key 或 Context Token。

| 现象 | 优先检查 |
| --- | --- |
| Gateway 正常但微信无回复 | `channels status --probe` 检查运行状态，再看通道发送日志并做真实微信收发；不要只看 `lastOutboundAt` |
| 微信只收到统一通道失败 | 检查 Chub 可达性、插件与 Chub 协议版本、插件运行时来源和 Hook |
| 旧设备仍显示微信信息 | ClawBot 是否已在另一台设备重新绑定 |
| 微信 Chub 消息进入 Agent | 插件路由开关、Chub 模式状态和运行时 Hook |
| 微信 Chub 任务被拒绝 | 当前绑定 Session 是否执行中、writer 是否占用、路由账号是否唯一健康 |
| 完成通知失败 | 任务保存的账号与发送者、Context Token 和当前通道状态 |
| 飞书正文被改写 | `content_mode`、原文 Hook 和当前 `runId` 关联 |

涉及插件、微信通道、权限或通知行为的变更，至少执行相应静态测试和配置校验，并在受影响平台做一次真实最终结果检查。Gateway、微信绑定、Owner、状态 Tool、飞书通知和微信 Chub 单入口均已纳入验收基线；具体路由状态见[能力清单](CHUB_INTEGRATION_CAPABILITIES.md)，插件的平台部署状态见[插件说明](../integrations/openclaw/chub/README.md)。
