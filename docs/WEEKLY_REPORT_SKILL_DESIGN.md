# 工作周报生成技能设计方案

> 状态：已实现并验收。技能位于 `.agents/skills/generate-weekly-report/`，当前保持人工触发和重点确认门禁。

## 1. 当前定位

`generate-weekly-report` 消费 Chub 自动化已经发布到本地的 Markdown 材料，生成可追溯的本期重点清单、正式业务周报和核对记录。它不负责打开飞书、下载文档、恢复截图内容或修改自动化任务状态。

当前能力覆盖：

- 将自动化输入适配为明确角色和使用范围的 Manifest；
- 校验周期、必需来源、内容状态、路径、标题范围和文件哈希；
- 先生成重点清单并等待维护者明确确认；
- 确认后生成正式周报并执行确定性校验和人工事实 Review；
- 保存输入口径、冲突、缺失项、确认和 Review 结果。

自动化下载和周报生成保持两个可独立验收的环节。当前不提供定时生成或无确认的一键串联。

## 2. 当前流程

```text
自动化发布完整输入集
  -> 适配并校验 mapping / manifest
  -> 阶段 A：生成本期重点确认清单
  -> 维护者确认或调整
  -> 阶段 B：生成正式周报
  -> 格式校验 + 完整性/准确性/文案 Review
  -> 生成核对记录
```

阶段 A 读取主文档的重点关注内容并与各端事实交叉核对，记录纳入、合并、降级、排除或待确认。输入缺失、内容仍在编辑或范围不明确时默认停止；只有维护者明确批准带缺口继续，才能进入阶段 B，并记录批准范围与影响。

阶段 B 以已确认重点为主线，但仍回到原始材料核对数字、日期、版本、状态和责任边界。正式稿通过校验和三类 Review 后才可标记完成。

## 3. 周期与工作目录

正式周报周期固定为周一至周日。每周三开始新周期的处理窗口，周三至下周二的下载和汇总归属同一周期，下周二为报送日。

```text
data/artifacts/weekly-reports/<周期>/
  inputs/
    <主周报>.md
    linked/
      <关联文档>.md
      .sources.json
  mapping.json
  manifest.json
  output/
    本期工作重点确认清单-<周期>.md
    weekly-report-confirmation.json
    本期业务周报-<周期>.md
    周报生成核对记录-<周期>.md
```

自动化先在暂存区校验主文档、当前必需来源和上周参考，全部通过后才原子发布唯一有效的 `inputs/`。技能只读该目录，不修改源文件。输入变化会使已有 Manifest、确认和正式稿失效，必须重新校验。

## 4. 输入契约

`mapping.json` 声明业务线的来源角色、范围和报告校验规则；适配器据此生成 `manifest.json`。技能不能依赖关联文件顺序或自然语言文件名猜测角色。

当前 V 业务配置要求：

- 上周周报 `previous-report`，仅用于结构、背景和延续事项参考；
- 产品商业化、产品/OS、运营、客户端、服务端五类本期事实来源；
- 可选的周会记录、人工确认和补充材料。

这些角色属于 V 业务 profile，不是通用技能的永久硬编码。来源变化时更新 mapping 和 `references/v-report-profile.md`，不改写通用流程。

每份 Manifest 材料至少明确：

- 受控相对路径、业务角色、来源标题和可追溯链接；
- 下载状态与内容状态；下载成功不能替代内容已就绪；
- 来源统计周期和本次实际使用周期；
- `reference-only`、`whole-document` 或 `heading-range` 使用模式；
- 文件 SHA-256、运行标识和下载时间等新鲜度信息。

本期事实来源的使用范围结束日期必须落在正式周期内，开始日期可以早于周一。生成时保留来源真实统计周期，不把跨周期数据改写为完整周报周期，也不直接比较不同统计窗口的数据。

输入路径必须解析在当前周期受控根目录内，只接受 Markdown 文件；绝对路径、目录穿越和远程 URL 不能作为本地输入。Manifest 不保存 Cookie、Token、账号或浏览器状态。

## 5. 内容状态与范围

只有内容状态为 `ready` 或经维护者明确记录的 `manually-approved` 才能进入正式汇总。需要复核、不完整、仍在编辑或过期的材料默认阻塞。

`heading-range` 在匹配前只对标题做受控标准化，包括 Markdown 标记、常见转义、空格和可识别日期格式。开始或结束边界缺失、不唯一或顺序错误时停止，不自行选择；显式配置时可以读取到文档末尾。标准化仅用于定位，不修改原始文件。

客户端和服务端等包含多业务组的材料，必须按 V profile 的明确章节范围读取；图片或 Canvas 中无法可靠读取的数据不能作为确定事实。

## 6. 重点确认门禁

重点确认清单至少记录：

- 主文档每项 OKR 的原始标题、目标及本期事项去向；
- 不属于 OKR 的其他重点工作；
- 建议合并、弱化或不纳入的历史和重复事项；
- 多来源冲突、缺失信息及需要维护者确认的问题；
- 重点关注内容对照和按来源统计的覆盖情况。

维护者确认必须同时写入重点清单和 `weekly-report-confirmation.json`，保存确认时间、最终取舍、带缺口批准范围、Manifest fingerprint、重点清单相对路径及其 SHA-256。

正式生成前再次校验 Manifest fingerprint、重点清单哈希和所有输入文件哈希。任何输入、范围或清单变化都会使旧确认失效，防止将历史确认套用到新材料。

## 7. 正式周报规则

正式稿默认直接进入业务关键指标或第一项 OKR，不放置输入资料清单、编制说明和内部缺失说明。当前 V profile 的主体结构包括业务关键指标、四项 OKR 和各端周报；其他重点工作、需关注与决策事项按本期事实决定是否出现。

- 每项 OKR 保留原始标题和目标文案；指标型 OKR 保留可比周期的当前进展。
- 同一事项按现状或数据、当前结论、验证动作和下一步组织，区分事实、初步判断与计划。
- 已上线使用完成时态，计划上线使用计划时态；相对日期尽量换算为具体日期。
- 指标、金额、版本、人名、日期、状态和专业字段必须可回溯到来源。
- 上周事项必须明确为继续、更新、关闭或不纳入，不能直接作为本周事实沿用。
- 多来源冲突按维护者最新确认、本周会议结论、本周各端周报、上周周报的顺序处理；仍无法确定则保留待确认。
- 各端来源链接统一放在文末，不在顶部或各章节重复罗列。
- 默认不生成业务摘要；维护者明确要求时才生成 4 至 6 条不重复正文的管理结论。

业务结构和细化规则分别维护在 `references/report-structure.md`、`references/review-rules.md` 和 `references/v-report-profile.md`，本文不重复完整业务模板。

## 8. 校验与 Review

`scripts/validate_weekly_report.py` 负责确定性检查，包括 Manifest、周期、角色、路径、使用范围、内容状态、哈希绑定、业务线必需章节和标签、Markdown 表格、来源链接及未处理占位标记。脚本不判断业务重要性，也不能替代人工事实核对。

正式稿必须完成：

1. 完整性 Review：每份来源重点都有纳入、合并、不纳入或待确认结论。
2. 准确性 Review：数字、日期、版本、链接、状态、责任边界和计算方向与来源一致。
3. 文案 Review：标题层级、术语、单位、时态和表达一致，且不因压缩丢失必要背景或下一步。

维护者每次修正后需要全文检查相关关键词和旧口径，覆盖摘要（如有）、OKR、其他重点、决策事项及来源。核对记录保存来源覆盖、实际范围、人工放行、冲突处理、校验结果、修正点和残留检查结果。

## 9. 技能结构与维护边界

```text
.agents/skills/generate-weekly-report/
  SKILL.md
  agents/openai.yaml
  references/
    manifest-contract.md
    report-structure.md
    review-rules.md
    v-report-profile.md
  scripts/
    adapt_downloads.py
    validate_weekly_report.py
```

- `SKILL.md` 保留执行顺序和阶段门禁。
- `manifest-contract.md` 定义输入、范围、状态和确认绑定。
- `report-structure.md` 定义正式稿结构和业务线声明方式。
- `review-rules.md` 定义通用事实与文案复核规则。
- `v-report-profile.md` 定义当前 V 业务来源和提取边界。
- 两个脚本负责只读适配和确定性校验，不承担业务判断。

来源角色、业务分类、报告结构或稳定口径变化时，应同步更新相应 reference、样例和测试。仅本周事实变化时不修改技能规则。

## 10. 安全与当前结论

- 原始材料只读，所有生成内容写入当前周期独立输出目录。
- 设计、Manifest、日志和输出不得包含 Token、Cookie、账号或终端票据。
- 项目资料页可展示适合可信网络只读访问的生成文档；不适合直接访问的敏感业务内容不得纳入展示。
- 日志只记录受控任务、角色、相对路径、状态和错误摘要，不记录文档全文。
- 正式稿校验失败时可以保留草稿，但不能标记完成。

当前链路已经覆盖输入适配、人工重点确认、正式生成和可追溯复核。继续保留人工触发与确认门禁是现行产品边界，不属于待完成的开发阶段。
