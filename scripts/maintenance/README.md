# Maintenance Scripts

These are canonical fixed scripts for independent service actions and the system-upgrade oneshot. They retain only Chub-specific sequencing, deferred-restart handling, state cleanup, and final health checks; every fixed `launchctl` or `systemctl` operation is delegated to `scripts/platform/service-management.sh`. The upgrade-start action refreshes and reloads an inactive oneshot definition before triggering it, so a removed legacy path cannot remain cached in an installed service. Recovery first detects an active executor and leaves it untouched; it only reloads and starts an inactive executor. `chub-system-recovery-reset` is the local-terminal escape path for a stuck upgrade: it stops the upgrade executor, Web, Quick Worker and the Debug Chrome Supervisor; discards Chub-owned rebuildable runtime, task, automation, module-lifecycle and deployment-package state; rebuilds those service definitions; and confirms Web, Worker and Supervisor health. It does not inspect the previous upgrade state or modify configuration files. It uses the normal configuration loader: a missing or invalid `settings.local.yaml` is ignored with a redacted error log and the tracked `settings.yaml` baseline remains active. The reset does not affect OpenClaw Gateway state, OpenClaw plugins or patches, Native Sessions, browser Profiles, logs, documents, shared business data or user configuration. Invoke it through `chub` or its fixed Chub caller. Root-level legacy maintenance paths are not provided.
